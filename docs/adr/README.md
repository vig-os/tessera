Each ADR records one load-bearing decision: context, the decision, why, and consequences. They
correspond to the open-decision register in `tessera/docs/ROADMAP.md` (D1–D7). Status: Proposed /
Accepted / Superseded.

| [0064](0064-logical-tables-over-numbered-leaves.md) | **Logical tables over numbered leaves** (#677, from the #681 note, option P-logical): a table above `BLOCK_ROWS` is written as the leaves `<table>/0000`, `<table>/0001`, … (index padded to at least four digits, never per count: no ceiling, deterministic), each carrying a sealed `TableSpec.partition {index, last}` marker; a node is one logical table only if its leaves are canonical, contiguous from 0 with exactly one terminal, and it holds nothing but them and their `.cidx` sidecars, else a typed `Error::LogicalTable` from every reader and a refusal at seal; one resolver (`Reader::table_group`) behind `LogicalTableView`, CLI `ls`/`tree`/`read`/`sql` and the Python reads; legacy `_NNNN` products read unchanged for format v0, never written again, and a mixed product is `Ambiguous`; every multi-block writer switches in one PR (new `content_hash`es above `BLOCK_ROWS`, no corpus golden moves, no `TESSERA_VERSION` bump); `StreamWriter::push_table` stages each block's input on disk with the bound `min(W, n) · p_block + s` and a ksb RSS proof; P, R and F rejected. Amends SPEC §5b, ADR-0026, ADR-0062 (`RowAlignment`) and ADR-0063; implementation #709–#717 | **Proposed** |
| [0063](0063-block-name-grammar.md) | **Block-name grammar** (#685): a block name is one or more `/`-separated segments of `[A-Za-z0-9._-]+` (not `.`/`..`), at most 255 bytes; **leaf rule** — no name in one product is a parent prefix of another, so zip members, exploded directories and S3 prefixes mirror names one-to-one; `tessera pyramid` names level 0 `<block>/0`. One validated type (`tessera_core::block::BlockName`) for `BlockRef`/`BlockPayload`/`pack_streaming`, and every filesystem join through `BlockName::path_under` (plain components only) — closes the write-session, `recover`, `unpack`, `pack_dir` and `aux/` path traversal. Single-segment grammar and a flat on-disk encoding rejected; Windows device names and case folding deferred to #690. **Amended by #686:** `recover` quarantines a journal tail it can't replay (`quarantine/<id>/`, names stay taken, `QuarantinedBlockName`) instead of leaving its fragments in `blocks/`, refuses an invalid complete journal line (`CorruptJournal`; only an unterminated last line is torn), and rewrites the journal durably. **Amended by ADR-0064 (2026-10-30):** a node of numbered, marked table leaves is one logical table | **Accepted** |
| [0062](0062-streaming-table-provider.md) | **Streaming table provider** (#654 epic): bounded-memory queries over sealed table blocks, replacing `tessera sql`'s whole-table `MemTable`. **Home:** an engine-neutral, synchronous `tessera_io::scan` (Vortex → Arrow batches, pruning, integrity, zip, multi-product) plus a new **`tessera-query`** crate holding *only* the DataFusion adapter, so `tessera-core`/`tessera-wasm` and the abi3 wheel stay DataFusion-free; `vortex-datafusion` 0.75 rejected (unpatched umbrella crate, multi-thread tokio, no seal/`.cidx`/zip). **DataFusion policy:** exposed and re-exported only from `tessera-query`, one major at a time, its arrow major must equal Vortex's, a DataFusion major is a breaking `tessera-query` release. **Memory is bounded in rows in flight**, not bytes: probed, Vortex's default split is ~1 MiB of uncompressed column (524 288 rows for an `i16`), and Vortex multiplies its scan concurrency by the host's core count, so each partition drives explicit 65 536-row window scans (probed: one split per window, ~0.1 ms set-up each) with the layout-reader cache and a fresh Moka segment cache per opened block (segment ids are file-local), at most two blocks open per partition (probed: without it windows re-read 2.6–8× the bytes, with it exactly a single scan's) under a `ScanBudget` + bounded channel; the bound is **per query** (at most `max_partitions`, default 8, scan partitions, not DataFusion's core-count default; operators above the scan stay bounded only by DataFusion's pool), proven by a CI high-water test and a ksb run that measures **anonymous** memory (swap off, `--exclusive-cpus` dedicated cores and pinned partitions, scale-invariant peak, plus a negative control that must exceed the bound). **Pruning in two tiers:** `.cidx` row-group pruning before any block byte is fetched (exact NULL rules from `nulls = rows − count`), then Vortex zone maps every 8192 rows (probed: 328 KB instead of 1.31 MB); a closed filter class (integer/bool/utf8, no floats — zone pruning's NaN/±0.0 handling unaudited, and a wrongly dropped row can't be recovered — no casts, literals narrowed to the column type), always **`Inexact`**, gated by a pushdown-on/off differential test. **Positional zip** only with an alignment proof — a sealed, corpus-neutral `TableSpec.aligned_to` (a writer's claim, written only by the `derive_aligned` path and recording the source blocks' digest; whether it must also be signed is an owner question) or a **strictly increasing** key checked while streaming, including across partition-unit boundaries (each unit's predecessor row is always read and verified, even from a pruned block, and counted) — refused before the first row on any count/partition/source mismatch, no hash-join fallback. **Multi-product:** (product, block, row-group run) units, members pinned by `manifest_hash`, identical schemas or an explicit common-column projection (no NULL-fill union, no widening), object store via our own `VortexReadAt` behind a tessera-owned `RangeSource` seam so a consumer's DataFusion `ObjectStoreRegistry` (object_store 0.13, beside our 0.14) can feed it. **Integrity default `VerifyBlocks`** (hash before any row of a block is emitted; pruned blocks never fetched except key-mode predecessor reads; the `.cidx` verified in every mode, and pruning switched off for a block whose sidecar has no digest; locally the rows are read in a second pass, so the guarantee covers corruption at rest, not a concurrent writer); `SealOnly` is a labelled opt-out. Three PRs: #666 single product → #667 zip → #668 multi-product/object store; deferrals #669–#671, owner questions #672–#675 | **Proposed** |

| [0059](0059-chunk-index-statistics-schema.md) | The **chunk-index statistics schema** — the single format event for `ChunkStats` (#522 spike, gating #347 P1). Attaching a `.cidx` adds a block digest and `content_hash = merkle_root(&digests)` over *every* block ref, so default-on **and** any field change each move `content_hash`/`manifest_hash` — today both are free (**no corpus product carries a `.cidx`**), after the first default-on seal each is another regeneration, so everything that wants to be in `ChunkStats` lands together. **Determinism decides the design**: `f64` addition is order-independent only *by convention* and #472 already found a cross-arch seal divergence from a persisted float NaN — so **the `.cidx` stores integers only** (order-independent *by algebra*: counts merge commutatively under any worker count) and every real-valued statistic is derived at read time. That rejects **t-digest** (order-dependent merge) and **KLL** (randomised) outright, and kills `sum³`/`sum⁴`: `int32` kurtosis overflows `i128` at the **8th sample** and `int64` still overflows at n=7 *in i256* — no accumulator width fixes it. Recommends instead **one block-level histogram** (per-chunk measured 4.6–14.5× the sidecar for no consumer; block-level 4096 bins = **1.13×**, 0.061 % of a 151 MiB file) from which quantiles, skew, kurtosis, Tukey/k·σ fences and mode all derive decode-free — and for ≤16-bit integers with one bin per value those quantiles are **exact**, not estimated (measured CT recon: span 4096, 4096 distinct values). Bin edges fixed at write time from the observed range, recorded in the spec as `kind`/`lo`/`hi`/`bins`/`exact`; two-pass, and the second pass is measured at **+20 % on the index build** (the surprise: the existing stats fold already costs **5.2× the encode**). **Mandatory M1** — bind the index to its block's `indexed_digest`: the `.cidx` records only a NAME today, so `commit --remove-block volume --add-block other:volume` served the OLD volume's stats as `exact: true` (#524 guarded the path; this closes the class). **Mandatory M2** — fail closed on overflow, never wrap (#523). **Separable candidate C1** (#526): blake3 stays the default identity hash, optional top-level sha256 fixity from the same single seal pass — measured blake3 2930 MB/s vs sha256 1305 MB/s (dual = 3.2× serial, 2.25× threaded, ~120 ms on a 151 MiB product), `sha2` already in the graph, **additive only** (folding it into `content_hash` would move every existing identity) | **Proposed** |
