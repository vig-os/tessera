# [Issue 787]: [ci(macos-build): curl | sh without pipefail masks a failed cargo-dist download as 'dist: command not found'](https://github.com/vig-os/tessera/issues/787)

## Defect
`.github/workflows/macos-build.yml` installs cargo-dist with `curl … | sh` under the default `run:` shell, which is `bash -e {0}`. That shell has **no `pipefail`**. When the download fails, the step still passes, and the failure shows up one step later as an opaque `dist: command not found` (exit 127).

`release.yml` (generated by cargo-dist) guards against exactly this: `shell: bash` gives `bash --noprofile --norc -eo pipefail`, with the comment "we specify bash to get pipefail".

## Evidence
PR #786, run 42569492387, job 129003331571:
- `Install dist` step: `curl: (22) The requested URL returned error: 504`, step **passed**.
- `dist plan`: `dist: command not found`, exit 127.
- Rerunning the failed jobs is the remedy for the 504 itself. The defect is that the cause is masked.

## Fix (root cause, not a retry)
- Add `shell: bash` to the `Install dist (the version pinned in dist-workspace.toml)` step (macos-build.yml:80), so a failed curl fails the step that caused it.
- Do the same for `run: sh -c "$INSTALL_DIST"` (:128), because `sh -c` drops pipefail for release.yml's piped install command. Use `bash -o pipefail -c`, or `shell: bash` plus `bash -eo pipefail -c "$INSTALL_DIST"`.
- Test: a workflow-lint or actionlint-style check that every `run:` containing `| sh`/`| bash` sets `shell: bash`. If none exists, show the fixed step failing once against a bogus version URL.
