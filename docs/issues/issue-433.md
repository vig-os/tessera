# [Issue 433]: [ci(release): generated release.yml violates the SHA-pin policy (checkout@v7.0.1, upload-artifact@v7, download-artifact@v8) — pin via [dist.github-action-commits]](https://github.com/vig-os/tessera/issues/433)

## Diagnosis

`.github/workflows/release.yml` is GENERATED by cargo-dist (pinned `0.32.0` in `dist-workspace.toml`; the Release workflow's `plan` job regenerates it and fails if the checked-in copy differs — so it must never be hand-edited in a way `dist` wouldn't emit).

The repo's guardrail `scripts/check-action-pins.sh` (prek hook `check-action-pins`, scans all workflows) requires every `uses:` to be a full 40-char commit SHA. `release.yml` currently violates it in **16 places**:

- `actions/checkout@v7.0.1` (5×) — from PR #429's `[dist.github-action-commits] "actions/checkout" = "v7.0.1"`, a TAG where the setting takes a SHA.
- `actions/upload-artifact@v7` (6×) — cargo-dist's own default.
- `actions/download-artifact@v8` (5×) — cargo-dist's own default.

Reproduce (from the nix devShell):

```bash
prek run check-action-pins
```

## Fix

Set `[dist.github-action-commits]` in `dist-workspace.toml` to full 40-char SHAs for all three actions, then **regenerate** `release.yml` with the pinned `cargo-dist` (`dist generate --ci github` in the nix devShell) so the checked-in file is byte-exact with what the `plan` job emits. Never hand-edit `release.yml`.

## SHAs to use (resolved from the tag refs, all `type: commit`)

- `actions/checkout` v7.0.1 → `3d3c42e5aac5ba805825da76410c181273ba90b1`
- `actions/upload-artifact` v7.0.1 → `043fb46d1a93c77aae656e7c1c64a875d1fc6a0a`
- `actions/download-artifact` v8.0.1 → `3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c`

## Verification gate

- `prek run check-action-pins` → Passed
- Release workflow's `plan` job on the PR → green (proof the regen is byte-exact)

Priority: block before any release is cut.
