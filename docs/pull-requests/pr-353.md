# [PR 353](https://github.com/vig-os/tessera/pull/353) feat(referencing): first-class Interp + IcdfSampler evaluator descriptors

Stacked on #350 (`feat/349-log-axis-transform`) — review that first.

`Transform::Log` (#350) makes an array's **axis law** first-class: a reader can
recover *where* a sample sits without out-of-band knowledge. But the *evaluator* —
how you interpolate between the samples, and how you invert a 2-D table to sample
from it — still has to ride in sealed `extra` as an application convention. Two
products with identical axes and identical data can then disagree on what a lookup
returns, and nothing in the format catches it.

This adds the missing half:

- `referencing::Interp { Nearest, Linear, Log }` — `reconstruct(a, b, t)` gives the
  value between two samples. `Log` is the log-log interpolation that attenuation and
  cross-section tables actually use; reading such a table with `Linear` is a silent
  physics error, which is precisely why it belongs in the file.
- `referencing::IcdfSampler { row, col }` — the bilinear evaluator for an inverse-CDF
  table, i.e. "given a row coordinate and a uniform deviate, return the sample."
  This is the shape every Monte-Carlo angular/energy sampler wants.

Both are plain serde types alongside the existing `Transform`s, so they are
self-describing in the manifest and cost nothing to a product that does not use them.
Generic format only — no domain specifics.

19 referencing tests green.

**Follow-up, deliberately not in this PR:** an `interp: Option<Interp>` field on
`ArraySpec`, so the evaluator rides next to `axis_referencing` rather than in `extra`.
That touches the array spec's serialized shape and deserves its own review.
