## Changes

- `tessera/docs/FEATURE-MATRIX.md`: the row is ✓. Its gate column now opens with the pass condition, as the matrix's ✓ rows do: each plan PR's acceptance test, plus the §8.1 criteria on ksb. The row's "Open: consumer notice (#716)" is replaced by the list of finished work: each issue with its merged PR, the release and the migration note. The evidence column gains `block::partition::tests`, `logical_tables.trycmd`, `tessera-py/tests/logical_tables.py`, the two `push_table` stream tests and the migration note.
- **Review nit from #842 (docs only).** The `push_table` rustdoc (`tessera-io/src/stream.rs:902`) still gave the figures from before #770: a 3,180 B entry, 8,408 B per leaf, 4.8 MB at 573 leaves. It now gives ADR-0064's canonical figures: 2,966 B, so 7,980 B per leaf, 4.6 MB at 573 leaves. It also said "the term holds once #759 lands", and now says "since #759 (PR #765)". This is a rustdoc comment edit with no code change. The doctest and CI cover it.
- **Stale test comment.** The doc comment on the CLI fixture (`tessera-cli/tests/cli.rs:24`) still said that no writer produces partitioned tables yet (#712). It now says the writers partition a table only above `BLOCK_ROWS` rows, which is too large for a committed fixture. This is a comment edit with no code change.
- ADR-0064, ADR-0026, the README and the ROADMAP have no "pending #716" or "#677 open" wording, so they are unchanged. No ADR status changes.
