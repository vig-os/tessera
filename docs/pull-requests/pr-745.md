# [PR 745](https://github.com/vig-os/tessera/pull/745) feat(io)!: write multi-block tables as marked <table>/NNNN leaves

ADR-0064 PR D: multi-block writers emit the marked leaves `<table>/NNNN`.

## What changed

- `table::block_name` names block `idx` of `total` `<prefix>/{idx:04}` through `leaf_name`, so `events/10000` follows
  `events/9999`, and it now returns `Result<String>`. The new `table::block_partition` gives the marker
  `{index, last}`, or `None` for a single block.
- Both multi-block writers name and mark through these two functions: GE whole-file ingest
  (`to_listmode_product_partitioned`) and `TableMultiBlockSink` (GE streaming ingest and `bench --input`).
- A table of at most `BLOCK_ROWS` rows is unchanged: one bare-named block, no marker.
- Out of scope:
  - Generic `ingest table` still seals one block, because Refs #538 has not landed.
  - Blob ingest's `file_NNNN` names a series of blob files, not a partitioned table, so it stays.
- Docs: rustdoc on `block_name`, `block_partition` and both writers, the SPEC §5b note, the FEATURE-MATRIX row and
  the CHANGELOG. The ADR has no per-PR status column, so it is unchanged.

## Proof

- **Pre-change failure.** Run against the unswitched writers at `11280ba`,
  `ge_hdf5::whole_file_and_streamed_multi_block_match_at_n_blocks` fails: `left: [("events_0000", None), …]` against
  the expected `[("events/0000", Some(Partition { index: 0, last: false })), …]`.
- **GE streamed vs whole-file.** The two paths seal equal block projections (per block: name, kind, digest,
  `spec.rows`, `spec.row_index`, `spec.partition`) and the same `content_hash`. That hash equals the pinned
  pre-switch value `blake3:1d54…5123`, captured from the same test at `11280ba`. Both outputs pass
  `check_partitions`, and `table_group("events")` resolves them as `Partitioned`.
- **`TableMultiBlockSink` against the committed legacy fixture.** The sink seals the legacy fixture's block digests
  and `content_hash` under `events/0000…0002`, with markers and a different `manifest_hash`, so only
  `manifest_hash` moves. The legacy fixture still reads as `LegacyFlat`.
- **Mutation runs** (manual and not committed; each one was a temporary edit, restored before committing):
  - The sink names its leaves under the wrong node (`eventsx/NNNN`). The projection assert fails on the name.
  - The GE whole-file writer drops the marker (`partition: None`). The projection assert fails with `None` against
    `Some(Partition …)`.
  - The sink misnames one leaf as `events/1`. The seal itself refuses this with `NonCanonicalLeaf`.
- **Goldens.** No corpus golden moves. No dependency was added, so the Gate B feature snapshots are untouched.
- **Commands.** Local runs: `cargo test -p tessera-io -p tessera-ingest` exit 0, clippy `-D warnings` exit 0,
  `nix build -L .#checks.x86_64-linux.workspace-test` exit 0 and `.#checks.x86_64-linux.ingest-gate-a` exit 0.

**Breaking:** products above `BLOCK_ROWS` rows get new block names and markers, and so a new `manifest_hash`.
Their `content_hash` is unchanged.

Closes #712
