# [PR 983](https://github.com/vig-os/tessera/pull/983) docs(changelog): one section per release

## What

The root `CHANGELOG.md` had only `## Unreleased` at every tag from `v0.1.0-alpha.1` to `v0.1.0-alpha.6`. cargo-dist
builds the GitHub Release body from it and, for a prerelease with no section titled with its exact version, falls
back to `Unreleased`. So every release's notes listed all history to date (alpha.6's included alpha.5's #709).

## Changes

1. **One section per past release.** `scripts/changelog.py split CHANGELOG.md v0.1.0-alpha.1 … v0.1.0-alpha.6`
   rebuilt `## [0.1.0-alpha.N] - <tag date>` (date: `git log -1 --format=%cs <tag>`). A release's entries are the
   bullets at its tag that are absent at the previous tag, compared as whole bullets. Result: alpha.1-4 recorded no
   entries in this file (each section says so and points to the crate changelogs; alpha.2 also notes its failed
   macOS cut, #647), alpha.5 has 15, alpha.6 has 19, and `Unreleased` keeps the 17 that are new since alpha.6. All 51
   entries are kept.
   - **Rewording: none.** Every bullet at alpha.5 and alpha.6 is on dev verbatim, under the same subhead, so every
     section uses the text as it was at its tag. `split` refuses, rather than guesses, if that ever fails to hold.
   - Cross-checked independently with the real `parse-changelog` 0.6.16 (the version cargo-dist 0.32.0 locks):
     per section, the extracted bullets equal the tag diff, in order.
2. **`Format break` leads `Unreleased`** (#917): ADR-0066 A′ (seal over the stored JCS bytes, `manifest.seal` as
   entry 2); alpha-layout products refused with no migration verb (rule 10); which hashes moved and why (#720/PR
   #942, #895/PR #934, PR #972, traced in `docs/spikes/916-format-break-crosscheck.md`); signatures made before the
   break (they stop verifying where a seal moved; ADR-0066 rule 8 keeps the rest); #828 (`tessera-table-v2`) not in
   this release.
3. **The next release takes exactly its own section.**
   - Lookup, from the source of cargo-dist 0.32.0 (`axoproject/src/changelog.rs`): the exact version, then the
     version without its prerelease suffix, then `Unreleased` for a prerelease. `## [0.1.0-alpha.7] - <date>`
     matches case 1. The release title becomes `0.1.0-alpha.7 - <date>` (was `Version 0.1.0-alpha.6`).
   - The release-time step is `scripts/changelog.py release CHANGELOG.md <version> <date>` on the release PR. It
     renames `Unreleased`, opens a fresh one and adds the compare link. It is documented in `docs/RELEASING.md`
     (step 1, plus a "Release notes" section) and `CONTRIBUTING.md`. `release.yml` is untouched.
   - New flake check **`changelog-sections`**: runs `--self-test` and `check`. `check` requires a section for the
     workspace version in `tessera/Cargo.toml`. release-plz bumps that version on the release PR, so the PR stays
     red until the step has run.
   - A caveat, documented: when `dev` moves, release-plz closes a release PR that carries a non-bot commit and
     opens a new one, so the rename is the last thing before merging.
4. **Compare links** at the bottom (the oldest links to its tag).
5. Comments corrected in `release-plz.toml`, `dist-workspace.toml` and `release-plz.yml`: release-plz writes only the crate
   changelogs, never the root file. The release commits #694 and #858 touch only `tessera/crates/*/CHANGELOG.md`.

## Tests

- `python3 -I scripts/changelog.py --self-test`: 30/30, exit 0.
- **Before the change:** `nix build .#checks.x86_64-linux.changelog-sections` with dev's `CHANGELOG.md` exits 1
  (`no ## [0.1.0-alpha.6] - <date> section for the workspace version`). **After:** exit 0. `guardrails-gates`
  exits 0.
- The bumped-version case: with `tessera/Cargo.toml` at `0.1.0-alpha.7`, `check` exits 1, and after `release …
  0.1.0-alpha.7` it exits 0. `parse-changelog` finds `[0.1.0-alpha.7]` and accepts the fresh, empty `Unreleased`.
- `pymarkdown -c .pymarkdown scan CHANGELOG.md` exits 1 with the same 8 findings as dev's `CHANGELOG.md` (6 MD013,
  2 MD018), all inside entries kept verbatim. `docs/RELEASING.md` exits 1 only on line 144, which was already on
  dev. `typos` over the changed files exits 0.

Heads-up: the open release PR #932 (alpha.7) fails `changelog-sections` once this merges, until step 1 runs on it.
That is the intended gate.

Known and harmless: `parse-changelog` counts the compare-link block in the oldest section (alpha.1). Link
definitions do not render, and that section is never announced again.
