# [PR 876](https://github.com/vig-os/tessera/pull/876) feat(io): sequenced table input on StreamWriter, seq-ordered from any thread

Closes #812

A thread-safe, seq-ordered table input on `StreamWriter`, one per lane (ADR-0065 §7.2–§7.3). It adds `StreamWriter::open_sequenced_table_on(lane, name, spec, SequencedOptions) -> SequencedTable` with `push(&self, writer, seq, batch)`, `mark_done`, `abort(reason)`, `stats()` and `close(expected_count)`.

## Design
- **No second scheduler.** The ordering gate is a second `CreditWindow` on the writer (`order`). Each lane has its own `next`, window, reserved set and stall clock. The due `seq` is never held. Any other push blocks while `seq >= next + window` or while the shared byte credit is held. With `refuse_instead_of_block`, that same condition is refused at once and is terminal.
- **Release** follows the committer's ordered pattern. The push that completes a contiguous run drains it, under one lock per lane, into #806's `OpenTable`. Full leaves become ordinary staged jobs on the lane. `StreamWriter::submit` is now `&self` (lanes behind a `Mutex`), so releases on several lanes can hand leaves over concurrently. The public `OpenTable::push`/`close` signatures are unchanged.
- **Refusals** poison the writer's sequenced inputs and wake every blocked push (`notify_all`, as `CreditWindow::close`). They are:
  - a duplicate, either `seq < next` or a `seq` already entered (reserved under the gate lock on entry);
  - `seq >= next + max_ahead`;
  - a gap or an `expected_count` mismatch at `close`;
  - `abort`;
  - the stall deadline;
  - pipeline death, which the encode window cascades into the order gate.
- **Stall deadline:** always finite, default 10 min, capped at `MAX_STALL_TIMEOUT` = 24 h. A zero or longer value is refused at open, and there is no way to disable it. It raises `StreamedTableError::Stalled { next }`.
- **New `StreamedTableError` variants** in `tessera-core`: `Duplicate`, `TooFarAhead`, `WouldBlock`, `Missing`, `CountMismatch`, `Aborted`, `Stalled`, `Failed`.

### Decision for review: byte credit = the writer's `max_in_flight_bytes`
The shared byte credit, which bounds the batches waiting ahead of `next` across the writer's lanes, is set equal to the writer's encode-window byte limit (`StreamWindow::max_in_flight_bytes`). It is not a new option.

Rationale: ADR-0065 §7.2, "The window" (`docs/adr/0065-c-abi-bridge.md:609`), reads: "at most the shared byte credit (half of `ram_budget_bytes`; the other half is the `StreamWriter`'s encode window)". The two halves are equal. The bridge's `ram_budget_bytes` sizes the `StreamWriter`'s encode window, so making the credit equal to that window reproduces the 50/50 split, with no second setting that could drift from it.

Alternative, if the reviewer prefers it: a separate `SequencedOptions::byte_credit` field.

## Evidence
- **Before the change:** with only the tests applied, `cargo nextest run -p tessera-io sequenced` exits **101**, with 64 compile errors from the missing `SequencedOptions`, `SequencedTable`, `SequencedStats` and `StreamedTableError` variants.
- **Mutant:** I changed the code to release each batch on arrival (`pop_first`) instead of releasing the contiguous due run. The smoke test then fails (nextest exit **100**). The code is restored.
- **After the change:** `cargo nextest run -p tessera-io` passes 281/281 (exit 0). `cargo clippy -p tessera-io -p tessera-core -- -D warnings` is clean, and the new items have no rustdoc warnings.

## Scope
- The sequence-key checks (#833) and the determinism suite (#834) are not in this PR.
- #868 is not folded in. A second sequenced input on one lane is refused at open. Mixing other jobs onto that lane is documented as a producer rule; that is #868 item 1's territory.


## Fix round 1 (13df09c)
- **A refusal poisons the writer, not only the gate.** The gate's poison now reaches the encode window too (a `Weak` upstream, since the window owns the gate) and closes the pipeline. Every later push on any lane returns the refusal, and `finish`/`finish_with_stats` return it first and seal nothing. A sequenced table that is still open at `finish` fails it with `StreamedTableError::NotClosed`, and dropping one unclosed poisons the writer with that error. The doc caveat is gone.
- **Seq arithmetic.** A `seq` below `first_seq` gets its own refusal, `BeforeFirst`. `next` is an `Option<u64>` sequence number (`None` once `u64::MAX` has been released), so nothing overflows and nothing truncates on 32-bit targets.
- **Byte credit vs ADR §7.2 "half of `ram_budget_bytes`".** The credit is the writer's `max_in_flight_bytes`, the same value as the encode window's budget, so one value bounds two pools of equal size. The bridge sets `max_in_flight_bytes = ram_budget_bytes / 2` and gets the ADR's split. Only an *unequal* split can't be expressed, and the ADR doesn't ask for one. Both pools are soft bounds: each can overshoot by the last item it admitted and by the item it never holds back. This is documented on `SequencedTable`.
- **Recovery** is unchanged. The poison lives in the writer, not on disk, so `WriteSession::recover` on the stage dir replays the leaves committed before the refusal, as it does for any interrupted run. That is ADR-0065 §5's "recovery isn't exposed", and it is documented.
- **New tests:** `a_refusal_poisons_the_writer_so_finish_seals_nothing`, `a_sequenced_table_not_closed_at_finish_fails_it` (dropped and still open), `a_seq_below_first_seq_is_refused_as_before_first`, `the_last_sequence_numbers_release_without_overflow`, `every_advance_of_next_restarts_the_stall_deadline`, `a_failed_release_poisons_the_writer_as_failed`.
- **Before the fix,** the same scenarios fail on 5d51ee2 (nextest exit **100**, 4/4 FAIL): abort→finish and drop→finish both return `Ok` with 0 blocks; `first_seq = u64::MAX` panics with "attempt to add with overflow" (stream.rs:671); seq 9 below `first_seq` 10 reports "already pushed". **Mutant:** with the deadline counted from the push's entry instead of the last advance, the stall-restart test fails.
- **After the fix,** `cargo nextest run -p tessera-io -p tessera-core` passes 471/471 (exit 0), doctests pass (exit 0), and clippy `-D warnings` is clean. A fresh reviewer approved with nits, and the nits are folded in.
