# [PR 1022](https://github.com/vig-os/tessera/pull/1022) feat(io): collections in the repository; gc marks through members (ADR-0067 step 4)

Store sealed collections by manifest hash in the repository, accept typed collection ref records, and verify ref/object kinds. Existing lineages retain their recorded kind: product commits and low-level ref writes reject changes with `LineageKindMismatch` under the writer lock before storing objects or publishing refs. Typed object accessors report `ObjectKindMismatch`; ref-record disagreements report `RefKindMismatch`.

GC dispatches by object kind, marks nested collection members and follows stored version edges. Missing, torn, unreadable or wrong-kind members abort before any sweep and name the full path from the root ref. Shared objects are read once while every incoming kind claim is checked. Parent-indexed traversal provenance avoids copying path prefixes; paths are rendered only on error, preserving every member step and summarizing consecutive source edges by their version/object count.

Update ADR-0036, align ADR-0067's test names, and document the API, failure modes and cost in the repository chapter and Unreleased changelog. Atomic collection commit, history and pin-management verbs remain in their planned ADR-0067 steps.
