# [PR 696](https://github.com/vig-os/tessera/pull/696) fix(io): make WriteSession::recover crash-safe and idempotent

Closes #686

`WriteSession::recover` (`tessera-io/src/write.rs`) now rewrites the journal through the durable write path, so a crash during recovery can't lose it. Recovering twice changes nothing. This PR also fixes both PR #691 review findings folded into #686.

## What changed
- **Durable rewrite.** `recover` rewrites the journal with `write_durable` (temp file, fsync, atomic rename, directory fsync) instead of `fs::write`, which truncated and then wrote. The replayed lines are kept byte for byte; before, they were re-serialized.
- **Finding 1: quarantine.** If complete lines follow the first line whose fragment is missing, that line and every line after it move verbatim to `quarantine/<blake3 hex of the lines>/journal.jsonl`, and the fragments they name move to `quarantine/<id>/blocks/`.
  - The quarantine is never sealed.
  - A second `recover` leaves it as it is.
  - An append whose name is a quarantined name, or its parent or child, gets the new `Error::QuarantinedBlockName`. Before, it got EISDIR.
  - `create` on the same directory keeps the quarantine.
  - The id comes from the content, so a crash part-way through is finished by the next `recover` into the same directory.
  - A lone last line with no fragment is still dropped. This is the poisoned-fsync flow, so retrying that block still works.
- **Finding 2: a complete line is a commit.** A complete line that is not UTF-8, not JSON, not a `BlockRef`, or commits the same block twice gets the new `Error::CorruptJournal { path, line, detail }`, and nothing on disk changes. Only an unterminated last line is torn, whatever its bytes: a cut-off prefix, a whole object missing its newline, or a split UTF-8 character. Before, a split UTF-8 character failed with an I/O error from `read_to_string`, and a whole object with no newline was replayed as a commit. The duplicate and leaf-rule checks now run in O(n log n).
- **Docs.** The `recover` and `create` rustdoc, a new amendment to ADR-0063 (its "fragment is kept" and torn-tail sentences point to it), the ADR index row, and the FEATURE-MATRIX crash-recovery row.
- No sealed bytes, `content_hash` values or corpus goldens move. This only changes the internal staging directory.

## `write_durable` callers, and how they changed
`write_durable` itself now:
- names its temp file `<file name>.tmp` (it used `with_extension("json.tmp")`, which gave `journal.json.tmp` for the journal);
- removes the temp file again when it fails;
- fsyncs `.` when a bare relative path has an empty parent;
- has a `#[cfg(test)]` thread-local seam, `FAIL_NTH_DURABLE_RENAME`, that fails before the rename.

It already renamed atomically and fsynced the directory.

| Caller | Change |
|---|---|
| `WriteSession::create` (header) | Unchanged call; it gets the cleanup and the temp-name fix. |
| `WriteSession::persist_header` (header, on every `with_*`/`add_source`) | Same as `create`. |
| `WriteSession::recover` (journal) | **New.** Replaces the non-atomic `fs::write`. |
| `quarantine` (quarantine journal) | **New.** |

The audit also found two directory-entry durability gaps that `write_durable` doesn't cover, because they create files in place: `append_block` never fsyncs the fragment's parent directory, and `create` doesn't fsync the journal or `blocks/` entries. They are filed as #695 with a fix sketch. The directory-creation code is now one helper, `create_dirs_durable`, which `fragment_guard` and the quarantine both use.

## Tests (`write::tests`)
- `a_crash_while_recover_rewrites_the_journal_keeps_the_original`: the seam fails the rewrite before its rename. The original journal is byte-identical, a stale `.tmp` is replaced, and a second `recover` gives the same blocks and root. On the old code, with the seam placed between its truncate and its write, it fails with `left: []`: the journal was lost.
- `recover_quarantines_an_unreplayable_tail_and_a_second_recover_changes_nothing`: checks the quarantine contents, that a second `recover` leaves the whole tree identical, typed errors for `c`, `c/0`, `c/0/x` and `b/0`, the seal leaving out the quarantine, and that `create` keeps the names taken. On the old code it fails because there is no quarantine and the fragment stays in `blocks/`.
- `a_crash_while_recover_quarantines_is_completed_by_the_next_recover`: a crash at the quarantine journal write or at the session journal write ends in a tree identical to an uninterrupted recovery.
- `recover_refuses_a_complete_line_that_is_not_a_valid_commit`: covers five shapes; each gets `CorruptJournal` at line 2 with the tree unchanged. On the old code it fails because the line was dropped as torn.
- `recover_drops_the_unterminated_last_line_whatever_its_bytes`: covers a prefix, a whole object and split UTF-8. On the old code the whole-object case fails because the line was replayed (watermark 3).
- `parse_journal_applies_the_leaf_rule_both_ways_and_only_across_a_slash`.
- `recovery_drops_a_torn_journal_tail` is kept. `recover_cut_short_keeps_the_fragments_of_later_lines` is replaced by the quarantine test.

`cargo test -p tessera-io` (228 tests) and `cargo test -p tessera-core` pass, and `cargo clippy -p tessera-io -p tessera-core --all-targets -D warnings` is clean.
