# [PR 875](https://github.com/vig-os/tessera/pull/875) fix(core): verify a manifest's seal over the object it parsed

Closes #573

## What

`Manifest::from_json_verified` now checks `manifest_hash` over the manifest JSON **object as parsed**, with only
`manifest_hash` removed (SPEC §4), not over a re-serialisation of the typed struct. This is ADR-0060 §2.2 / §11 P0a.

| case (each of the 8 corpus manifests where marked) | dev `02b8741` | this PR | reference reader |
|---|---|---|---|
| B: newer key (`actors`) added, resealed (8/8) | Integrity | **ok**, `newer_fields() == ["actors"]` | ok |
| C: key spliced in under the old seal (8/8) | **ok** | Integrity | tampered |
| `"study": null` / no `sources` key, resealed | Integrity | ok | ok |
| nested newer key (`producer.agents`, `blocks[0].stats`), resealed | Integrity | ok, named | ok |
| key spliced in and seal deleted or `null` | ok | Integrity | tampered |
| duplicate key (top level, nested, `"name"`), NaN, `1e400`, lone surrogate, major version 1 | mixed | refused | refused |

- **One seal function.** `canonical::hash_without`/`bytes_without` back `manifest::seal_of` (reader, over the parsed
  object) and `Manifest::compute_manifest_hash` (writer, over `to_value(self)`). Number handling is unchanged: no
  `arbitrary_precision`, the strict parser builds numbers exactly as `serde_json::Value` does, so #587 is neither
  fixed nor made worse.
- **Strict parse.** `canonical::parse_strict` refuses a repeated key in any object, compared after unescaping
  (RFC 8785 §3.1 needs I-JSON, RFC 7493 §2.3). serde_json and Python's `json` keep the last value and other parsers
  keep the first, so the same bytes would read differently under one seal.
- **Missing seal = integrity failure.** `from_json_verified` requires `content_hash` and `manifest_hash`. Before,
  a deleted seal skipped the check (found in review).
- **Newer fields.** `Manifest::newer_fields()` is a declared-field walk (`FIELDS` consts on `Manifest`, `Producer`,
  `Generation`, `BlockRef`, `Source` and `IngestTransform`, kept honest by a fully-populated-instance test; opaque
  maps are not walked). A re-seal of such a view is refused with the new `Error::NewerFormatFields`.
  `ProductBuilder::from_manifest` (**breaking:** now `-> Result`), `compute_manifest_hash` and `canonical_bytes`
  all refuse it.
- **No writer emits a manifest whose seal doesn't hold.** `pack`, `pack_streaming*` and
  `Repository::put_manifest` write `Manifest::to_sealed_json()`. `Reader::manifest_json()` gives the stored bytes,
  and `unpack`, `pack_dir` and the Python `Reader.verify` use them, so a newer or `null`-bearing product
  round-trips unchanged. The aux rewrite already copied the bytes. The wasm `verify_manifest`/`verify_signature`
  now verify the seal over the given JSON; `verify_signature` didn't verify the seal at all before.
- `tessera verify` warns `fields from a newer format revision are not interpreted: …`.

## Conformance between the two readers

`tessera/corpus/seal-cases.json` holds 40 manifest-only cases with a `verdict` each. They were built from
`corpus/files` and resealed with the reference reader's own `manifest_seal`. `tessera-core/tests/seal_cases.rs` and
`corpus/reference_reader/run.py` must each reach every verdict, so the two readers agree by construction. The
`reference-reader` flake check guards the case count: its output is piped, which masks the exit code, so the check
greps the pass line.

## Proof

- Pre-fix: the verdict-only version of the seal-cases test, run against an `origin/dev` worktree, fails with
  **23 disagreements** (all 8 B cases read as tampering, all 8 C cases pass, the `null`/omitted/nested cases fail,
  and the nested duplicate key is taken last-wins).
- `cargo nextest run -p tessera-core -p tessera-io -p tessera-ingest -p tessera-cli -p tessera-wasm`:
  811/811 passed, exit 0 (and core+io 467/467 after the round-2 nits). `cargo clippy … --all-targets -D warnings`: exit 0.
- `python run.py`: `8/8 fixtures passed`, `40/40 seal cases agreed`, exit 0.
- **Corpus unchanged:** `corpus_hashes_match_goldens` and `committed_corpus_files_are_byte_identical_to_a_fresh_pack`
  pass. Every `as-sealed` case is the stored `manifest.json` byte for byte, and the writer's seal over it equals the
  golden (`writer_seal_is_the_reader_seal_over_the_written_json`).

## Not in this PR

- `Collection` and embedded `ProductSchema` forward compat, the SPEC §5 rows and the `inspect --help` text are the
  ADR's P0b, now #873.
- The `inspect` warning and `inspect --json` printing the stored object are the split the ADR allows, now #874.
- #587 (integers above 2^53) is unchanged.
