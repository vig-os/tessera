# [PR 630](https://github.com/vig-os/tessera/pull/630) ci(release): exempt bot-authored release PRs from the branch-name gate

## Summary

release-plz's release PR (#626) failed the Commit Messages job because its branch, `release-plz-<RFC 3339 timestamp>`, fits no branch shape. release-plz has no setting for the timestamp, and its uppercase `T`/`Z` fail every slug, `chore/` prefix or not (release-plz 0.3.169–0.3.172, `crates/release_plz_core/src/pr.rs` `release_branch`).

- **ci.yml, Validate branch name:** PRs whose author is a bot account (`pull_request.user.type == 'Bot'`, via env) skip the branch check, matching the `[bot]` commit-author exemption `validate-commit-range` already applies. It keys on the author, never on the branch name. ci.yml is devkit-managed, so the block is a LOCAL PATCH linked to upstream vig-os/devkit#1902.
- **docs/COMMIT_MESSAGE_STANDARD.md:** documents the exemption next to the commit-author one.
- **release-plz.toml:** `pr_branch_prefix = "chore/release-plz-"`. The headers of it and release-plz.yml record the branch and commit conventions, why the `Refs:`-less `chore: release v<version>` commit passes (chore is Refs-optional, bot author exempt; release-plz has no commit-message setting, the commit message is the PR title), and that release-plz finds its open PR by prefix.
