# [PR 682](https://github.com/vig-os/tessera/pull/682) fix(io)!: stream one canonical table block to a staged file and commit it by a verified rename

Part of #677. **PR 2 of 3**: gap 1, the file-backed single-table sink. #677 stays open after this PR; PR 3 (the Vortex writer bound, #681) finishes it.

**Residual (#681, PR 3 of 3):** the pinned Vortex 0.75 writer still holds about 0.4× the encoded size in
flight during the encode, because of an unbounded per-chunk fan-out with a cross-column write order.

## Root cause

`table::encode_streaming` collected the whole encoded table in a `ByteBufferMut` and returned
`freeze().to_vec()`, so the encoded output grew with the table. `TableStreamWriter::finish` and
`table_job_from_fragments` reached that path.

## Change

1. **File-backed encode.** `table::encode_streaming_to(spec, groups, sink: impl std::io::Write) -> u64`,
   which is `VortexWriteOptions::blocking(&rt).write` at the pinned Vortex (`gerchowl/vortex@608d8a1`).
   `encode_streaming` keeps its signature as `encode_streaming_to` into a `Vec`.
2. **Staged blocks, digest born with the bytes.**
   - `WriteSession::staging() -> BlockStaging` and `BlockStaging::create() -> StagedBlock`.
   - `StagedBlock` is a file in the session's `staging/`. It hashes every byte in its `Write` impl
     (ADR-0002 first-moment integrity).
   - A staged file is deleted on a failed commit and on drop. `create` and `recover` clear `staging/`.
3. **Commit by verified rename.**
   - `WriteSession::append_staged` takes the born digest: a set `block_ref.digest` must match it, and a
     `None` digest is filled in.
   - It fsyncs the file and **renames** it into `blocks/`, with no copy. If `staging/` is on another
     filesystem, the rename fails with `CrossesDevices` and the file is copied instead.
   - It then re-reads the fragment against the born digest, so scratch corruption is refused.
   - Then the journal line and Merkle leaf, as `append_block`.
   - `append_block_from(block_ref, reader)` copies a reader into a `StagedBlock` and commits it the same
     way.
4. **A failed journal write poisons the session.**
   - All three appends share one commit. If it fails once the journal write has begun (the write or its
     fsync), the failed block's fragment is deleted.
   - From then on, every append and the seal are refused with an error that says to `recover`. `recover`
     keeps exactly the blocks committed before the failure.
   - Truncating the journal back was rejected: it would rest on the fsync that just failed.
   - A committed block name is refused, so a failed append can't delete a committed fragment.
5. **Staged jobs.**
   - `StagedEncodeJob` / `StagedEncodedBlock` and `StreamWriter::push_staged`.
   - Staged bytes are reported as `StreamStats::{peak_staged_bytes, max_staged_job_bytes}`. They don't
     count against the RAM window.
   - **The rule is that table streaming jobs are always staged**: `table_job_streaming`,
     `table_job_from_fragments` (used by `TableMultiBlockSink`) and `TableStreamWriter::into_job`.
6. **Fragment compaction.** `TableStreamWriter::finish_to(sink)` and `table_job_from_fragments` share
   `compact_fragments_to`. It reports a fragment read error ahead of the encode error that the read
   error caused.
7. **#680 item 3 folded in.** `finish_with_stats` joins every thread before it reports the first error.

ADR-0026 gets the "single-table output sink" amendment: the contract, the rule, the RAM bound (`< B`
for staged table jobs), poisoning and the disk need. Disk is about `2 × T + J × S` and only `T + J × S`
until the seal; the rename removes the extra `S` a copy needed during a commit. FEATURE-MATRIX is updated.

### Final public API

- `table::encode_streaming_to`
- `stream::{table_job_streaming, StagedEncodeJob, StagedEncodedBlock}`
- `StreamWriter::push_staged`
- `StreamStats::{peak_staged_bytes, max_staged_job_bytes}`
- `WriteSession::{append_block_from, append_staged, staging}`
- `BlockStaging::{dir, create}`
- `StagedBlock::{len, is_empty, path}` plus `impl Write`
- `TableStreamWriter::{finish_to, into_job}`

**Breaking:** `table_job_from_fragments` returns a `StagedEncodeJob`, pushed with `push_staged`. It has
no callers outside `tessera-io`. `WriteSession` also refuses a block name that is already committed, and
refuses to go on after a failed journal write.

## Determinism

Bytes, block digests and `content_hash` are unchanged. A staged block is byte-identical to the in-memory
encode for every worker count and window tested. No corpus golden moved.
