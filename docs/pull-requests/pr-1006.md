# [PR 1006](https://github.com/vig-os/tessera/pull/1006) fix(io): collection member file names are injective

Collection members such as `a:b` and `a_b` previously overwrote the same file. Members now share the injective percent encoder used by lineage refs: `a%3ab` and `a_b`; uppercase bytes are escaped too, preserving distinct names on case-insensitive filesystems.

The single encoder lives in `tessera-core::names::file_name` and is exposed as `tessera_io::names::file_name`, avoiding a dependency cycle. Existing member helpers and both ref namespaces delegate to it. Ref basenames and validation limits remain unchanged. Local writers/readers, ingest staging, S3 prefix exports, nested descriptors and seals use the encoded layout. OCI layers remain digest-addressed.

`collection ls` lists every member, marking absent products and subcollections while continuing to present entries. `collection verify` still refuses missing members. A missing encoded member reports `member file not found: <encoded name>`; legacy-layout advice appears only when an old underscore or raw-id path actually exists. Legacy names are probed only for diagnostics and are never read as member content or returned as resolution fallbacks. Older layouts must be recreated from source products.

CHANGELOG Unreleased, ADR-0049, ADR-0054, the migration guide, executable CLI walkthroughs and seal-path fixtures use the encoded spelling and document the shared encoder.

This unblocks ADR-0067 step 4 (collection refs and GC through members).
