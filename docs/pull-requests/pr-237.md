# [PR 237](https://github.com/vig-os/tessera/pull/237) refactor(io): parallel blob hash via blake3 update_mmap_rayon (one native call)

Follow-up refinement of the opt-in parallel blob hash (PR #234, item C). Replaces the manual 16 MiB read→`update_rayon` loop with blake3's **native `Hasher::update_mmap_rayon`**:

- **one call**: mmaps the whole file and fans the full Merkle tree across **all** cores at once — no per-chunk serialization, no read/hash alternation, no manual buffer.
- **demand-paged** → peak RSS stays bounded (we never `malloc` the file; the OS pages it in).
- **digest byte-identical** to single-thread (determinism test + empty/sub-chunk edge tests green).
- adds blake3 `mmap` feature (with `rayon`) on `tessera-io` only; `tessera-core` (wasm) stays free of both. Drops the `PARALLEL_HASH_CHUNK` constant + the loop.

Green `nix flake check`.
