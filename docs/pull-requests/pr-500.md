# [PR 500](https://github.com/vig-os/tessera/pull/500) ci: make the local branch-name gate mirror CI instead of being laxer

Closes #499.

## Problem

The local gate accepted branch names CI rejects, so a branch could pass **every** pre-commit hook and
fail only after a ~45-minute CI leg. That is how it was found — `ci/nix-check-timeout-headroom` passed
locally, then:

```
##[error]Branch name 'ci/nix-check-timeout-headroom' does not follow the convention
<type>/<issue>-<summary> (types: chore,feat,feature,fix,…)
```

Cost: one CI cycle plus a closed PR (#496 → #498), because renaming a branch **closes** its open PR
rather than following it.

The old hook was `no-commit-to-branch --pattern` allowing `<type>/<slug>` with no issue number. Its
reasoning was sound in isolation — `.gitmessage` already forces `Refs: #<issue>`, so requiring the number
twice looks redundant. But CI requires it for every type except `chore`, and between a local gate and the
gate that actually blocks merges, the local one does not get to be more permissive. All it can do is
defer the failure to the expensive place.

## Change

`scripts/check-branch-name.sh` mirrors CI's `ALLOWED` clause for clause — including `renovate/**` and
`dependabot/**`, so a bot branch checked out locally behaves the same.

**The type list is not duplicated.** It is read from `.vig-os`'s `DEVKIT_BRANCH_TYPES`, the same key CI's
resolve-toolchain action reads, so the two gates cannot drift on *which types exist*. Only the shape rule
is written twice; the script says so at the top and names CI as the source of truth, because `ci.yml` is
devkit-managed and a local-only relaxation would be reverted by the next scaffold upgrade while CI kept
rejecting.

Two details worth noting:
- the hook runs **first**, so it fails before anything slower;
- it exits 0 on a **detached HEAD or mid-rebase**, where there is no branch name to judge and failing
  would block legitimate commits.

## Verification

Both directions, not just the happy path:

| branch | result |
|---|---|
| `ci/499-branch-gate-parity`, `fix/356-encode-trace-race` | passes |
| `chore/devkit-1-17-0`, `release/0.1.0`, `worktree/12`, `main`, `dev` | passes |
| `dependabot/github_actions/dev/x`, `renovate/foo` | passes |
| `ci/deliberately-no-number` | **rejected** |
| `feat/nonumber`, `badname` | **rejected** |

Exercised through `prek` end to end, not just as a regex: the hook reports `Passed` on a valid branch and
`Failed` with an actionable message on an invalid one — including the warning that renaming a pushed
branch closes its PR, which is the part that actually cost something here.

`shellcheck` clean.

## The remaining duplication is upstream's

devkit exposes this rule **only inline in `ci.yml`** — no hook, no script, no `vig-utils` entry point
(`grep -rl` across `assets/` and `packages/` finds it nowhere else). So every consumer wanting
commit-time enforcement must restate it, and the copies drift. Filed as **vig-os/devkit#1760**, noting
that the commit-*message* rule is already single-sourced through `vig-utils` — which is precisely why
that one has not drifted, and what the branch-name rule should copy.

Refs #499, #496, #498
