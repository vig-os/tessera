# [PR 929](https://github.com/vig-os/tessera/pull/929) feat(io): writers emit the JCS form of every sealed JSON document

Every door that writes a sealed `manifest.json` or `collection.json` now writes exactly `JCS(object)`
(RFC 8785: one line, sorted keys, JCS number and string forms), still with the in-band `manifest_hash`.
This is ADR-0066 decision rule 1 and implementation plan step 2. Readers are unchanged and **no seal moves**.

## Design

- One new module, `tessera_io::stored`: `manifest(&Manifest)`, `collection(&Collection)`, `canonical_form(&str)`.
  Each one re-encodes a parsed `Value` with `tessera_core::canonical::to_bytes`, the single JCS producer.
  `tessera-core` is not touched (#913 owns `canonical`).
- **Why the seal can't move:** the seal is `digest(JCS(object − manifest_hash))` over the object a reader parses
  (SPEC §4). Parsing JCS output gives back the same object, because a JCS number is the shortest round-trip
  form of its double and keys and strings unescape to the same text. So the parsed object, and with it the seal,
  is the one parsed from the old pretty bytes. Unknown newer-format keys and an explicit `null` survive, since
  the re-encode works on `Value`, not on the typed view.
- **I-JSON at every door:** `parse_strict` refuses duplicate keys, lone surrogates and integers beyond
  ±(2^53−1), and `to_bytes` checks the integers again.

**Intentionally unchanged:** appending `aux/` members (`add_aux_members`, used by `sign` and ingest provenance)
copies `manifest.json` byte for byte. Aux members are outside the seal and that path already enforces
byte identity. This is documented in `stored.rs`. The display outputs (`inspect --json`, `info`, `tree`) stay
pretty; they are not sealed documents.

## Proof

- **Before the change:** the six `tessera-io` door tests failed 6/6, with
  `pack recon_int16: the written document is not its own JCS form (first difference at byte Some(1))`.
- **Mutation check:** with only the `unpack` hunk reverted, `unpack_writes_the_jcs_form_of_a_pretty_stored_manifest`
  fails and the other nine pass.
- **The 13 tracked `.tsra` (12 distinct manifests) are re-packed:**
  - The 8 corpus files through `gen_corpus_files`, `scan.tsra` through `TRYCMD=overwrite`, and
    `partitioned_pairs.tsra` through `TESSERA_PY_FIXTURE_REGEN=1`.
  - The frozen `versioning.in`/`persona_signing.in` `study.tsra` and `legacy_flat_events.tsra` through
    `tessera unpack` + `tessera pack`: id, content_hash and manifest_hash, the member list and order, and
    `verify` are all unchanged.
  - **`corpus.json` is unchanged**, the conformance goldens pass, and `every_tracked_tsra_stores_the_jcs_form`
    holds all 13 to the form.
- **File-level change:** only the `manifest.json` entry bytes move, so each file shrinks (for example
  `recon_int16` 6785 → 5221 B, `multiblock_study` 13316 → 11563 B). Block entries are byte-identical. Nothing
  in the repo pins a file digest or size. The one snapshot that prints a size, `bench_compare.trycmd`
  (`volume size`), moves from `10.[..]`/`9.[..]` KiB to `8.[..]` KiB.
- **Integral floats now store as integers:** three fixtures had `rescale_slope: 1.0` and
  `rescale_intercept: -1024.0`; they now store `1` and `-1024`. The seal is the same because JCS already
  hashed them that way. A Python caller reading the manifest dict now gets an `int` for those values.
- **Reference reader `run.py`**, unchanged (`uv run --no-project --with-requirements requirements.txt`):
  8/8 fixtures, 76/76 seal cases, 7/7 refusals, exit 0.
- **`smoke.py` JCS check:** the check environment has no Python JCS library, so `smoke.py` carries a
  stdlib-only JCS oracle. It refuses any number it can't render exactly. On all 8 corpus manifests it was
  checked equal to `jcs==0.2.1` and to the stored bytes.

## Docs

- SPEC §2 notes that tessera's writers store the JCS form, with `jq .` for a readable view.
- The book's `format-anatomy.md` gains "The stored `manifest.json`" (`unzip -p … | jq .`).
- FEATURE-MATRIX: the ADR-0066 row goes from ○ to ◑, with step 2 built.

Out of scope, per ADR-0066: `manifest.seal`, reader-side canonical checks, the stored-bytes API (#913), and
the cutover (#914).
