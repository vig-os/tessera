### Decision

- **Where it lives:** a new sealed, ordered `Manifest.actors` (`software_agent` / `person` / `organization`, with an open `role` token). `producer` stays scalar.
- **Identity:** in `manifest_hash` (the version), never in `id` or `content_hash`; `actors` is forbidden in `id_inputs`. Wall-clock, URLs, tokens and cost go in `aux/actors.json`. Host, login and IP aren't recorded, because `aux/` ships unencrypted.
- **Trust:** the signature binds actors through `manifest_hash`. A person or organisation actor is *attested* only when a trusted key whose **pinned** identity matches signed the version; otherwise `inspect` shows it as unattested (#590 covers the existing `--require-signer` flaw).
- **Change vs product:** whoever approves a code change signs a change record; host-signed products bind to it through the sealed `producer.git_commit` (P3c). Derived products carry no approver.
- **Privacy:** ORCID/ROR only with consent to permanent attribution; random `urn:tessera:actor:` pseudonyms otherwise. Pseudonyms only, with no names, in de-identified products. Email-shaped strings are refused in every actor string. Per-version erasure needs a redacting commit (#591).
- **Schemas:** `required_actor_roles` is a claim check and ships in one PR with the signer binding.
- **Exports:** RO-Crate `CreateAction` + PROV-O, with collision-proof `@id`s; DataCite contributors + `TechnicalInfo`. Invalid or newer input is refused. The RO-Crate part (P2a) waits for #541.
- **Compatibility (probed):** corpus-neutral, no `TESSERA_VERSION` bump. The plan depends on #587 (integers above 2^53), then #573 (newer fields read as tampering), then #574.

### Decisions (owner, 2026-10-18)

The owner accepted all nine recommendations, as recorded in the ADR's *Decisions* section: P0 ships one release before P1; the P0 forward-compat rule (`from_manifest` becomes fallible); the §7 personal-data rules; pseudonym-first guidance, with #591 scheduled separately; the §6.5 change record + P3c (the operator is an organisation, with a host key pinned per host); strict P3b plus the #590 fix in P3; no native PROV exporter; the §10.1 carry rule; `commit` carries `generation` unless it's replaced (#574).

§11 is the implementation plan as ready-to-file sub-issues. FEATURE-MATRIX gains a todo row citing ADR-0060 (required by the adr-matrix gate for an Accepted ADR).
