# [PR 764](https://github.com/vig-os/tessera/pull/764) docs(adr): amend ADR-0064 §8/§8.1 with c_leaf · n and a tmpfs parallelism run

Amends Accepted ADR-0064 §8 and §8.1 per the owner rulings on #715 (comment of 2026-11-04) and the diagnosis `docs/spikes/715-rss-proof-diagnosis.md` (`252af87`). It is a dated amendment, `## Amendment (#760, 2026-11-04)`, with inline `*(Amended by #760, below)*` markers on the text it supersedes, following the ADR-0063/ADR-0026 convention.

- **A.1 — §8 bound:** `min(W, n) · p_block + s + c_leaf · n`, with `c_leaf = 2 · (e_leaf + b_leaf)`.
  - `e_leaf` is the leaf's entry length in the canonical (RFC 8785) manifest JSON, derived from the schema rather than measured: 3,180 B for the consumer schema.
  - `b_leaf` = 1 KiB of per-leaf bookkeeping.
  - The factor 2 is a stated allowance for allocator retention, not fitted to the measured 25.4 KB/leaf.
  - The term holds once #759 lands.
  - The plateau is `peak(n₂) ≤ (1 + τ) · peak(n₁) + c_leaf · (n₂ − n₁)`. τ = 5 % still catches the zone-statistics regression, and the pre-#759 writer still fails criterion 2.
  - The in-tree `staged_job_memory.rs` omits the term: at most 25.3 KB at its 8 leaves, 0.34 % of `s`.
- **A.2 — criteria 1 and 2:** each W = 4 plateau point runs k = 3 times, and criterion 2 compares the medians, because of the measured +14.9 % run-to-run variance. Criterion 1 is checked on every run (the max).
- **A.3 — criterion 6:** runs in its own ksb job with the session and output on `/dev/shm`. `--mem` is sized by formula: 6Gi for the consumer. The converse tmpfs guard applies there. Criteria 1–5 stay on disk-backed scratch under the existing guard. The shared-disk wall times and `%util` are recorded as context. A shortfall on tmpfs is still the writer's and stops the PR with a design question.
- **A.4 — owner addendum:** timings on ksb's shared HDD (and the seat's `/mnt/HDD`) are never pass/fail evidence; exo-pet/exo-fleet#980 is cited as the known limit. Criteria 1 and 3 on scratch are conservative. A criterion-3 failure is checked against `%util` first.

The `push_table` rustdoc, the CHANGELOG entry, the ADR-0026 bound, the ADR index row and the FEATURE-MATRIX row all state the same formula. No other criterion changes, and τ, `s`, `s_rss`, the ceilings, the 1.5× threshold and the budgets are untouched. No code changes: the only `.rs` hunk is rustdoc.

Closes #760
