# [PR 321](https://github.com/vig-os/tessera/pull/321) feat(cli): collection new — assemble a collection from pre-sealed .tsra (#304 Part 1)

## Why

Until now a `collection.json` could **only** be minted by `ingest --spec` (the atomic, non-resilient path — #302). This decouples *membership* from ingest: seal your `.tsra` products individually, then assemble the collection from them. It's the DUPLET first-user need (#304), and it **structurally defuses #302** — a bad member no longer aborts the whole collection.

## What

```
tessera collection new --member a.tsra --member b.tsra -o <dir> \
    --name study-A [--schema dataset] [--study S] [--role raw|derived] [--timestamp T]
```

A thin CLI over the just-landed model:
- opens each **pre-sealed** member (`Reader::open` verifies its seal),
- pins it by `(id, manifest_hash)` via the typed **`ProductHandle`** (can't mismatch ref/hash),
- seals the catalog under the declared **`--schema`**, validating its `member_rule` (#294 — a `dataset` accepts products, a `project` rejects them → **fail-fast**, nothing written),
- writes a **self-contained** dir: `<out>/collection.json` + each member **hard-linked** (copy fallback across mounts) as `<out>/<id>.tsra`, so `collection verify` resolves + checks it in place.

Collection timestamp defaults to the **latest member's** (deterministic) unless `--timestamp` is given.

## Evidence

Test: assemble a `dataset` from two pre-sealed `.tsra` → a self-contained dir that **recursive `verify` passes** and `inspect` shows `schema dataset`; a `project` schema **rejects** the product members (fail-fast). Full `tessera-cli` suite green; `nix flake check`: **all checks passed!**

## Scope

Part 1 = product members (assemble a dataset). **Part 2 — collection-as-query over OCI by exam-id** rides #291 (oci-client). Sub-collection members (assembling a `project` from child `collection.json`s) is a small follow-up on the same seam.
