# [PR 521](https://github.com/vig-os/tessera/pull/521) fix(bench): six fairness defects in the ecosystem harness, plus the #485 method backport

The #485 ask was to backport median+spread, cold-cache and seal/verify into the 7-format harness. An audit while doing so found the **published matrix was wrong**, not merely under-specified — six defects, every one producing plausible-looking numbers.

## The defects

| # | defect | who it flattered |
|---|---|---|
| 1 | `hdf5.py` wrote `shuffle=False` with gzip-4, on **both** modalities | Tessera |
| 2 | `nexus.py` — the same omission, in a second place | Tessera |
| 3 | `parquet.py` wrote plain `zstd`: no `BYTE_STREAM_SPLIT`, dictionary on | Tessera |
| 4 | `zarr_.py` wrote a bare `ZstdCodec`, no shuffle | Tessera |
| 5 | `root.py` was labelled `ROOT (uproot/TTree)` but uproot 5.7 writes a **`ROOT::RNTuple`** for a dict assignment | **ROOT** |
| 6 | `nifti.py` returned a lazy **`memmap`**, so reads were never performed | **NIfTI** |

#1–#4 are the omission #487 and #503 each caught once. #5 was verified by reading `classname` back from the file — every ROOT row was RNTuple's numbers under TTree's name, and RNTuple is ~11% smaller, so it flattered ROOT. #6 timed uncompressed `.nii` at **96,407 MB/s** warm and 63,342 cold; nibabel's ArrayProxy is memory-mapped, so nothing was read and the cold row was entirely vacuous. Corrected to 4,081 / 2,345 MB/s, in line with uncompressed HDF5.

**Four flattered Tessera, one flattered ROOT, one flattered NIfTI.** The audit was not one-directional, which is the only reason its conclusions are worth anything.

### And a seventh, in my own new code

The `continuous` fixture was **categorical**. Caught by an implausible number in the N=15 run — ROOT RNTuple reporting 655.9× compression — not by reading code. My `xorshift64*` dropped an XOR (`x = (x << 25)` instead of `x ^= (x << 25)`), degenerating to **1143 distinct values in 1,000,000 draws**, and `e1` was derived from `e0`'s own draw (r = −1.0). The test that should have caught it asserted `> 1000` distinct — a magic constant that happened to sit *below* the broken value. It now asserts a fraction of n, plus an independence check.

## Why #1–#4 had to land together

The table fixture was the **periodic** one only — the fixture #497 established is adversarial for value-distribution codecs. So the harness paired a fixture chosen against Tessera with a deflate configuration crippled against it. **Fixing either alone relocates the bias rather than removing it**, which is why the scope was widened (recorded on #485 rather than applied silently).

### What the numbers say

- **Volume, `gradient`:** Zarr zstd-3 is smaller than every Tessera setting — 0.13 MiB vs 0.25 (pcodec) and 0.22 (`auto`, which picked zstd), so **Zarr is 1.69× smaller even when Tessera also uses zstd**. This fixture is a linear ramp whose verdict moves with array size (`common.make_volume`).
- **Volume, `acquired`:** Tessera **ties** the best Zarr config (13.12 vs 13.07 MiB) and is **18% smaller than plain zstd** (Tessera/Zarr-zstd-3 = 0.822). Tessera **loses the read**: 625 vs 1168 MB/s. `auto` picks pcodec here, so it is the same file — and pays 396 → 319 MB/s on write for the double encode.
- **Table, `periodic`:** Tessera **loses badly** — 0.24 MiB vs Zarr blosc+shuffle 0.03 and HDF5 shuffle+gzip 0.05. This is the fixture adversarial to value-distribution codecs.
- **Table, `continuous`:** Tessera is **smallest** (5.15 MiB; HDF5 shuffle+gzip 1.08× larger), tracking #497's 1.10× and 1.03× on real DUPLET listmode. **Parquet reads faster** among compressed formats: read 1937 vs 1489, one column 3815 vs 2599 MB/s.

### Integrity — timed, not just described

fletcher32 and page CRCs are checked *during* a read, so their cost is the checked read vs the same read without them. `verify` is a *separate* whole-file pass. Reported in **milliseconds**: `verify` hashes the stored bytes, so MB/s over raw bytes would show a meaningless 126 GB/s on the compressible gradient.

| ecosystem | fixture | what is timed | warm ms | cold ms | file MiB |
|---|---|---|---:|---:|---:|
| Tessera | acquired | `verify()` — re-hash every block vs manifest | 3.9 | 8.5 | 13.12 |
| Tessera | continuous | `verify()` | 1.7 | 5.6 | 5.15 |
| HDF5 | acquired | read **without** checksum | 122.9 | 157.3 | 13.31 |
| HDF5 | acquired | read **with** fletcher32 verified | 126.3 | 127.4 | 13.31 |
| Parquet | continuous | read **without** page CRC | 8.3 | 30.7 | 6.04 |
| Parquet | continuous | read **with** page CRC verified | 6.1 | 11.1 | 6.04 |

**fletcher32 and the page CRC cost ≈ nothing** — checked and unchecked overlap within the spread on every fixture. Every mechanism above is also tested to **detect** a flipped byte. Parquet's error names the page CRC; Tessera's first catch is the STORED zip entry's CRC32 (`io: Invalid checksum`), ahead of the blake3 re-derivation; HDF5 reports a filter-pipeline failure without saying gzip or fletcher32. The test asserts the checked *path* raises — not that the named mechanism is always the one that fired.

### Two more defects, found late

- **Parquet's "default" wasn't pyarrow's default** (review). It forced 65,536-row groups; pyarrow 24 writes 1,000,000 rows as one group. Fixed, the default continuous size is **8.71 MiB** (was 11.32) — the forced grouping made pyarrow's real default look ~30% worse. It flattered Tessera.
- **Run order changed the answer** (found adding Tessera's `auto` variant). `auto` wrote a file **byte-identical** to `default` (same sha256, same recorded codec) yet its reads timed **27% slower**, because each variant was timed as a block and `auto`'s reads ran straight after its own 15 double-encode writes. Interleaved, the two read in 62.7 vs 60.0 ms. The harness now runs three global phases — prepare and verify everything, then **all reads** with variants interleaved round-robin, then **all writes** last — so no read follows a write burst. In this run the same pair reads at 625 vs 614 MB/s.

**Tessera now has two variants** (#533 merged): `default` = pcodec, `tuned` = `auto` (encode both, keep the smaller). The table backend has no codec knob, so both variants write tables identically and the settings string says so.

## Method changes

- **median + spread**, replacing min-of-N. `stats()` refuses `iters=0` rather than returning a number with no measurement behind it.
- **cold reads with MEASURED residency** — fsync **then** `POSIX_FADV_DONTNEED`, with post-eviction residency from `mincore(2)` printed on every row. Eviction repeats before **every** iteration: one eviction plus N reads would time one cold read and N−1 warm ones. Reported residency was 0.0% on every row of this run.
- **integrity timed and described** — Tessera's blake3 seal + `verify`, HDF5/NeXus `fletcher32`, Parquet page CRC32. Each row states what it detects **and what it does not**: only one answers "is this the artifact that was sealed, and by whom".
- **Parquet page CRCs are measured here**, correcting #503's note. That parquet-rs writes none is a property of *that implementation*; pyarrow 24 writes and verifies them.

## Also fixed

The README build recipe (`cp target/release/libtessera.so ./tessera.so`) names a file that is never produced — the cdylib is `lib_native.so` since the `tessera._native` rename. Following it yields no importable `tessera`, so the **reference adapter was skipped and the suite still reported green**. `test_adapters` now **fails** rather than skips when the subject of the comparison is missing. The adapter also drove the raw extension entry points while its docstring claimed it used the public path; it now uses `array`/`array_roi`/`table_dict`/`column`.
