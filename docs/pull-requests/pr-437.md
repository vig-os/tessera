# [PR 437](https://github.com/vig-os/tessera/pull/437) ci(release): drop the Homebrew cmake dependency — macOS runners ship cmake, and brew bundle exec broke the alpha build (#337)

## Why

The `v0.1.0-alpha.1` cargo-dist Release run failed on BOTH macOS targets (`aarch64-apple-darwin` and `x86_64-apple-darwin`) with:

```
× failed to brew bundle exec (status: exit status: 1)
```

and no inner build output. The Linux targets (`aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-gnu`) built cleanly.

## Root cause

`dist-workspace.toml` declared:

```toml
[dist.dependencies.homebrew]
cmake = '*'
```

That injects a Brewfile step into each macOS matrix entry's `packages_install`:

```
cat << EOF >Brewfile
brew "cmake"
EOF

brew bundle install
```

and wraps the build step in `brew bundle exec`. That Homebrew wrapper failed inside Homebrew itself before the real build even started, so the run died with a bare `exit 1` and no build log.

## The fix

GitHub's `macos-14` (and `macos-15-intel`) runner images ship cmake preinstalled, so the Homebrew dependency is redundant. Removing `[dist.dependencies.homebrew]` lets cargo-dist emit `packages_install: null` for both macOS targets and run a plain `dist build` — no Brewfile, no `brew bundle exec`.

- Linux `[dist.dependencies.apt] cmake = '*'` STAYS: apt still needs to install cmake on the Ubuntu runners for the vendored HDF5 build.
- `installers = ["shell"]` only, so there is no Homebrew *installer* affected by this change.

## Verified matrix delta

`dist plan --output-format=json` on `dev` vs this branch:

| target | before `packages_install` | after `packages_install` |
| --- | --- | --- |
| `aarch64-apple-darwin` (`macos-14`) | Brewfile + `brew bundle install` | `null` |
| `x86_64-apple-darwin` (`macos-15-intel`) | (same Brewfile step) | `null` |
| `aarch64-unknown-linux-gnu` (`ubuntu-22.04-arm`) | `sudo apt-get update && sudo apt-get install cmake` | unchanged |
| `x86_64-unknown-linux-gnu` (`ubuntu-22.04`) | (same apt step) | unchanged |

## Why `.github/workflows/release.yml` didn't change

The generated workflow references `${{ matrix.packages_install }}` and `${{ matrix.dist_args }}` dynamically — the Brewfile wrapping lives in the runtime matrix produced by `dist plan`, not baked into the checked-in workflow file. Regenerating with pinned cargo-dist 0.32.0 (`dist generate --mode ci`) produces a byte-identical release.yml, and the `plan` job's own drift check on this PR confirms that.
