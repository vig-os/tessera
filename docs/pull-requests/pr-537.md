# [PR 537](https://github.com/vig-os/tessera/pull/537) ci: run the bench method tests, and fail when any test file is visible to no check

Based on `dev`. (It was stacked on #521, which has merged.)

The ecosystem bench's tests gated nothing: `tessera/bench/ecosystems` was referenced by no check, workflow, hook or recipe, and `/bench/` is not in the crane `src` filter. This is the **second occurrence** of the class — `ef240cb` fixed trycmd running zero cases in CI for the same reason — so this adds a structural guard, not just a path. Review then found two more instances the first version of the guard missed, and they shaped the final rule.

## The rule: classify every script, not test-like names

The first guard matched *names* (`test_*.py`, `tests/…`). That was a proxy, and review found two holes in it:

1. **"Admitted by `srcFilter`" is not "run".** The filter admits whole directories (`/corpus/`, `/docs/examples/`, `/tests/cmd/`), so a new `corpus/foo/test_x.py` passed the guard unrun.
2. **Names miss real tests.** `corpus/reference_reader/run.py`, an independent conformance reader, matched no pattern and ran nowhere.

So the rule is now about **file type**. Every tracked script under `./tessera` (`.py .js .cjs .mjs .sh`) must appear in **exactly one** of:

| map | meaning |
|---|---|
| `scriptsRunByChecks` | file → the check(s) that run it |
| `scriptsNotRunInCi` | file → *why* it is not run (a declared decision, not a silent gap) |
| `scriptLibraries` | file → the **entry points** that import it — each must itself be a key of one of the two maps above (asserted) |

Filter admission **never** counts for a script. Non-script test files (Rust, trycmd, toml, fixture data) still count as covered when the filter admits them, because for them admission *is* what "run" means. Exact files, never directories.

**Check names are asserted to exist**, in the `checks` wrapper where the full set is known (attribute names only, nothing is forced). This fixed the drift that motivated it: `write_example.py` is also run by `tessera-wheel-import`.

Today's inventory: 22 scripts. 8 run by checks, 2 deliberately not run (with reasons), 12 libraries.

## New checks

**`reference-reader`.** Runs the independent conformance reader: a second implementation of `.tsra` verification, in pure Python, checked against `corpus.json`'s goldens. ~0.4 s, 8/8 fixtures. `jcs` (RFC 8785) isn't in nixpkgs, so it is packaged from its PyPI wheel (0.2.1, pure Python, Apache-2.0) at the version **pinned in `requirements.txt`** (this PR adds `jcs==0.2.1`; it was unpinned). **Evaluation fails if the two ever disagree**, so CI cannot drift from what a human running the reader installs. An empty `corpus.json` would print `0/0 fixtures passed` and exit 0, so the check requires the pass line to read `N/N` with **N equal to the number of `.tsra` files on disk**; on a mismatch it **names** each `.tsra` with no `corpus.json` entry, and each entry with no file.

**`bench-ecosystems`** (Linux only). Runs `test_common.py`: median+spread, **measured** cold-cache eviction, and both table and both volume fixtures. It needs only numpy and pytest. Its source is only `common.py` + `test_common.py`, so editing an adapter or the driver doesn't rebuild it. It runs on ext2/ext3 in the sandbox, which matters: a real page cache is needed for the eviction tests to mean anything. It is Linux-only because `common.py` uses `CDLL('libc.so.6')`, `mincore(2)` and `posix_fadvise`, and `eachDefaultSystem` also evaluates the darwin systems. On non-Linux systems, `test_common.py` is declared in `scriptsNotRunInCi` with that reason, so the name assertion still holds.

**`test-coverage`** enforces the rule above. It reports `ORPHAN` (a script in no map), `DOUBLE` (a script in two maps), `UNSEEN` (a test file the filter doesn't admit) and `STALE` (an entry naming no file), so the maps can't rot into false reassurance.

## Verified

| case | result |
|---|---|
| current tree, x86_64-linux | passes (26 checks); prints the two declared not-run scripts |
| current tree, aarch64-darwin | evaluates (25 checks, no `bench-ecosystems`); verdict passes |
| a script under `/corpus/`, admitted by the filter | **`ORPHAN /corpus/foo/test_x.py`** |
| `reference_reader/run.py` unlisted | **`ORPHAN`** |
| a script listed against a misspelled check | **evaluation fails:** `names checks that do not exist: ingest-producer-equalty` |
| the same script in two maps | **`DOUBLE`** |
| an empty `corpus.json` | **`reference-reader` fails:** `expected '8/8 fixtures passed'` |
| an extra `.tsra` with no golden | **named:** `NO corpus.json ENTRY for files/zz_extra.tsra` |
| `requirements.txt` pins `jcs==0.2.0` | **evaluation fails:** `does not pin jcs==0.2.1` |
| a library naming a non-entry-point | **evaluation fails:** `reader.py -> /corpus/reference_reader/nope.py` |
| a reason containing quotes and `$(touch …)` | **printed literally** — the substitution text survives into the output, so it was not executed (every path and reason goes through `lib.escapeShellArg`) |

**No rebuild cost.** The crane filter became a named `srcFilter`, so the guard asks the same predicate the build uses. `workspace-test`'s derivation path is byte-identical before and after this change, so the `src` hash didn't move and no Rust derivation rebuilds.

Closes #520
