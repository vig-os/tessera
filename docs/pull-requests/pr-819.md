# [PR 819](https://github.com/vig-os/tessera/pull/819) docs(adr): propose ADR-0065, the C ABI bridge for C++ producers

## What

ADR-0065, **Proposed (2026-11-11), awaiting owner acceptance**: the C ABI bridge that lets C++ producers (gPET-sim on
Geant4, gPET-sim2listmode) write `.tsra` through tessera's own writer instead of a C++ re-implementation.

- It is designed from the real writer API (`StreamWriter`, `WriteSession`, `ProductSchema`, the ingest arrow lane),
  with every claim cited to a file and line.
- It starts from how the MorePET producers write today, at pinned call sites.
- It follows the owner's steer: "a C interface that takes Arrow batches from many threads and streams them to
  StreamWriter".
- It is reconciled with the merged #801 gap analysis (`docs/spikes/801-consumer-gap-analysis.md`, `ecc55be`) and
  its schema drafts.

## Decisions

- **Crate.** `tessera-capi` (cdylib and staticlib, `tsra_` prefix, cbindgen header) over
  `StreamWriter`/`WriteSession`. It contains no format logic.
- **Sessions and lanes.** One session per product, with **one table lane per table role**. Each lane has its own
  dense `seq` stream and is fed by a thread-safe `tsra_push(table, seq, ArrowArray*, ArrowSchema*)` from any number
  of threads. The consumer products are multi-table: g4ring-output has 2 tables, and coincidences has 7 plus an
  array. `StreamWriter`/`WriteSession` gain lanes sealed in role order, so no table waits for another.
- **Wire.** The Arrow C Data Interface. Each batch's schema is checked against the declaration before import,
  because an `ArrowArray` carries no type. Only clean-lane types are accepted, nullability is declared, and Vortex
  stays out of the C API.
- **Determinism (#802).**
  - `seq` cuts the schema's `sequence_key` into blocks of a pinned, sealed `B`, because Geant4's own task cut follows
    the thread count. The key is checked on every batch.
  - The due `seq` is never held at the ordering gate, and a credit window back-pressures threads that run ahead.
  - A duplicate, a gap, a `seq` past the horizon, a key outside its block and a lost `seq` (abort, or a **finite**
    stall deadline, `TSRA_E_STALL`) are all typed errors, never hangs.
  - Verified: `StreamWriter` accepts jobs only in push order today. The extensions reuse its `CreditWindow` and its
    ordered commit, with no second scheduler.
- **Schema (#801).** Declared at open, in the drafts' shape: tables keyed by role, with columns, `optional`,
  `sequence_key`, `keys` and `references`. It is made strict against older readers (#830, G6) and its requirements
  match by role (G2). Categorical columns are deferred to #836 (G13).
- **Errors.** Status codes, a thread-local last error, and `catch_unwind` at every entry.
- **ABI.** Versioned apart from the crate. Packaging is pkg-config, CMake, nix and cargo-dist. There is no HDF5 in
  the bridge's graph.

**Owner decisions recorded, not taken:**

- where NaN canonicalisation (H4) lives (recommended: the bridge, §1);
- whether an explicit "no stall deadline" opt-in should exist (proposed: no, §7.2);
- where a C++ product's schema lives (pending the surveys, §8).

## Prototype evidence

From PR #821, folded into §16:

- it seals the native writer's bytes;
- 9 of 9 thread-count and schedule runs give one hash, and arrival order gives 9 distinct hashes;
- throughput is −7 % to +4 % against native `push_table`;
- the import is zero-copy, and the bridge adds one copy;
- the static-archive symbol leak and its fix are measured.
