# [PR 829](https://github.com/vig-os/tessera/pull/829) docs(adr): amend ADR-0064 §8.1 so criterion 2 is a within-run slope

Third amendment to ADR-0064 §8.1, which applies the owner's 2026-11-11 ruling on criterion 2. It is the new section
"Amendment (#797, 2026-11-11)", C.1–C.4. The superseded text in §8.1, B.2 and B.3 is marked
*(Amended by #797, below: …)*.

**Criterion 2 is a within-run slope.** Per `W`, over the tenths of every run with `x_rt ≥ 16 W`:

- **Model:** `y_rt = α_r + b · x_rt + ε`. `y_rt` is the tenth's peak `RssAnon`, `x_rt` the leaves whose input is
  complete at the tenth's end (the last tenth: `n`). One intercept per run absorbs that run's I/O state.
- **SE:** cluster-robust by run (CR1, the nested fixed effects not counted), `t₀.₉₅,G−1`. Tenths within a run are
  autocorrelated; clustering assumes no form for that, only that runs are independent, as B.2 already did.
- **Pass rule and resolution, unchanged:** `b̂ ≤ c_leaf + t · SE`, `2 t SE ≤ δ_z` (121,635 B/leaf) at both `W`, and at
  `W = 1` `≤ c_leaf`. Inconclusive fails.
- **Context:** the across-run slope (B.2) is still computed and printed, labelled as confounded by the disk.

**Why (C.1).** G r4's across-run `W = 4` slope fails (40,437 > 31,109 B/leaf), but every `W = 4` run is flat over its
own input; against the leaves at each run's peak the slope is −26,778 ± 46,234. The run level follows the shared HDD
(99–100 % `%util` on every run; exo-pet/exo-fleet#980), which A.4 already rules out as evidence for timings.

**Still sharp (C.4).** The pre-#759 writer fails the within-run fit on both of its sweeps. r1, with tenths rebuilt
from its job logs' ~1 s sample lines (its 10 ms CSVs are over `ksb out`'s 1 MiB): `W = 1` `b̂` 19,761 vs bound 15,028
B/leaf (and inconclusive on the re-check), `W = 4` 73,901 vs 28,763. `tessera-715-r3-failbefore-2`: 17,219 vs 9,237,
floor 2,513 (resolved).

**Also:** B.3's "family-wise ≤ 10 %" is scoped to the two slope checks (≈15 % overall with `W = 1`'s re-check,
B.5). ADR-0026 and the ADR index quote criterion 2 and are updated; the CHANGELOG and the `push_table` rustdoc
don't quote it. The amendment was written before the estimator was computed on r4's records. The evaluator follows in
PR #767.

Closes #797
