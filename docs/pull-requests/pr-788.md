### Guards rewritten

- `full_span_int_container_bytes_are_build_config_independent` → **`patch_indices_persist_no_sortedness_statistic`**.
  0.93's #468 keeps the byte *count*, so a length guard is blind. The new guard reads back the stored encoding tree,
  requires a `patch_indices` node (non-vacuous), and asserts none persists `IsSorted`/`IsStrictSorted`. It covers the
  bare vortex write and the seal path. Pre-change failure, crates.io 0.93.0 without the fork, debug:
  `persist [IsSorted, IsStrictSorted, Max, Min, NullCount]`, **exit 101**. Release passes either way (the defect is
  debug-only). With the fork, both profiles pass. `flake.nix` runs it under both profiles.
- `float_sum_stat_is_canonical_nan_not_the_platform_default` → **`float_stats_persist_no_nan_for_inf_and_neg_inf`**:
  the bytes of a `[+inf, -inf]` column hold no 64-bit NaN of **either** sign (so it bites on aarch64 too), and no zone
  map carries a sum. The old positive check ("canonical NaN present") can't hold when `Sum` isn't persisted; the
  zone-map assertion fails if a bump starts persisting it again.
- Public API: the `Send` bound and `TABLE_EDITION` are recorded in `CHANGELOG.md` (Unreleased → Changed), and the
  bump commit is marked breaking (`build(deps)!:`).
- Reviewed by a fresh reviewer: approve with nits. Fixed: the CHANGELOG entry, the guard rename, both NaN signs,
  the stale flake comment, and the #468 guard doc (reading also constructs `Patches`; `NullCount` is persisted by
  release builds too, so it can't separate the profiles).

## 6. The sealed `TableSpec.edition` (ADR-0024, 2026-11-15 amendment)

- **Field:** `TableSpec.edition: Option<String>`, the Vortex edition id (`"core2026.08.3"`), the frozen set of wire
  IDs the writer may emit.
- **Writer-set:** `tessera_io::table::sealed_spec` stamps `TABLE_EDITION` at both places a table `BlockRef` is built
  (`table_block`, and the staged ref every staged job and `push_table` leaf uses). A spec naming another edition is
  refused with `Error::Codec` (the staged jobs, `push_table` and `open_table` check it before staging anything). A
  caller that hand-builds a `BlockRef` around `table::encode` bypasses this and must set the field itself.
- **Absence:** the block predates the field (vortex 0.75 writer, no edition gate). It reads and verifies, and its
  manifest bytes and hashes are untouched because `None` is skipped. Old readers open new products, because
  `BlockRef.spec` is raw JSON.
- **The check it enables:** same input + same edition → same bytes, as a **necessary** condition: a different edition
  may legitimately give different bytes, and the products alone now say whether it explains a differing digest. It
  is not sufficient: the edition bounds which encodings the writer may use, not which it picks (tessera's codec set
  excludes ALP, ALPRD, integer Pco, Delta, OnPair, all inside `core2026.08.3`). Whether to also record a codec-profile
  id is #869.
- **Schema convention:** block specs are opaque to the manifest schema (ADR-0020) and not in the product-schema
  registry, so no schema version or registry entry moves. The field follows the additive
  `#[serde(default, skip_serializing_if)]` convention of `Column::nullable`, `Column::referencing` and
  `TableSpec::partition`. SPEC.md §5b states it normatively.
- **Breaking:** `TableSpec` has no `Default` and isn't `#[non_exhaustive]`, so external struct literals must name
  `edition: None` (CHANGELOG).
