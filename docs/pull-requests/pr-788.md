## 2. API breaks (a) — fixed here

| Break (0.75 → 0.93) | Fix |
|---|---|
| **Editions.** The writer refuses any encoding whose wire ID is in no enabled edition. The `vortex` facade enables one for you; tessera's hand-built session had none | `new_session` declares vortex's first-party editions and enables `pub const TABLE_EDITION = CORE_2026_08_3` (the 0.93 default, **frozen**, min library 0.85.0), named explicitly so a bump can't move it |
| `BtrBlocksCompressorBuilder::default()` / `WriteStrategyBuilder::default()` gone. Schemes now live on a `CompressionSession`, and the default preset **drops Pco at build time**; `with_new_scheme(&PcoScheme)` would now panic (already registered) | `from_session(s).with_compact()` (keeps Pco; zstd isn't compiled in) minus ALP/ALPRD, **and minus integer Pco, Delta and OnPair**, which 0.75 never used, so the codec set doesn't widen as a side effect |
| `ScanBuilder::with_projection` takes a `BoundExpression` | `select(..).bind(file.dtype())` |
| `with_row_indices` takes `StrictSortedBuffer<u64>` (vortex-scan) | `StrictSortedBuffer::try_new` (indices are already validated sorted and unique) |
| `vortex_array::accessor::ArrayAccessor` / `with_iterator` gone | `resolved_views()` + the validity mask |
| `VortexWrite: Send` | `W: Write + Send` on `encode_streaming_to` and `TableStreamWriter::finish_to` (public bound tightened; every in-tree caller already passes a `Send` sink) |

New direct deps: `vortex-edition`, `vortex-scan` (both already transitive). `cargo check --workspace --all-targets

### Guards rewritten

- `full_span_int_container_bytes_are_build_config_independent` → **`patch_indices_persist_no_sortedness_statistic`**.
  0.93's #468 keeps the byte *count*, so a length guard is blind. The new guard reads back the stored encoding tree,
  requires a `patch_indices` node (non-vacuous), and asserts none persists `IsSorted`/`IsStrictSorted`. It covers the
  bare vortex write and the seal path. Pre-change failure, crates.io 0.93.0 without the fork, debug:
  `persist [IsSorted, IsStrictSorted, Max, Min, NullCount]`, **exit 101**. Release passes either way (the defect is
  debug-only). With the fork, both profiles pass. `flake.nix` runs it under both profiles.
- `float_sum_stat_is_canonical_nan_not_the_platform_default` → **`float_stats_persist_no_nan_for_inf_and_neg_inf`**:
  the bytes of a `[+inf, -inf]` column hold no 64-bit NaN of **either** sign (so it bites on aarch64 too), and no zone
  map carries a sum. The old positive check ("canonical NaN present") can't hold when `Sum` isn't persisted; the
  zone-map assertion fails if a bump starts persisting it again.
- Public API: the `Send` bound and `TABLE_EDITION` are recorded in `CHANGELOG.md` (Unreleased → Changed), and the
  bump commit is marked breaking (`build(deps)!:`).
- Reviewed by a fresh reviewer: approve with nits. Fixed: the CHANGELOG entry, the guard rename, both NaN signs,
  the stale flake comment, and the #468 guard doc (reading also constructs `Patches`; `NullCount` is persisted by
  release builds too, so it can't separate the profiles).
