# [PR 280](https://github.com/vig-os/tessera/pull/280) feat(ingest): populate DICOM series world_frame + surface rescale (#271)

## Why

`tessera slice --world` and `stats`' world-affine were **dead on real DICOM ingests**: `read_series` never built a `world_frame`, so a stacked CT/PET volume shipped in index space only — the reviewer's #271 finding ("DICOM world_frame not populated → `--world` dead on real ingests; rescale not in meta").

## What

- Build the voxel→patient (**LPS mm**) affine from **ImagePositionPatient** (origin), **ImageOrientationPatient** (in-plane direction cosines), **PixelSpacing**, and the measured **first→second inter-slice vector** (captures real spacing, direction, and gantry tilt; a single slice falls back to `slice-normal × SliceThickness`). DICOM patient coordinates are already LPS, so no RAS→LPS flip (unlike NIfTI). Columns are in Tessera `[k=slice, j=row, i=col]` order; translation = first slice's origin.
- `None` when the header lacks the geometry — `slice --world` then stays index-only rather than inventing coordinates.
- Wire it through `DicomImage.world_frame` → `ArraySpec.world_frame` → the sealed array block.
- Surface `rescale_slope`/`rescale_intercept` as `recon` schema **metadata** fields (the block spec still owns the operational transform `stats --physical` applies; metadata is for discovery — a reader shouldn't open the array block to find the HU/Bq·mL⁻¹ scaling).

## Evidence
- Exact affine golden: `world(k,j,i) = [10+3i, 20+2j, 30+5k]`, column-norm spacing `[5,2,3]`, single-slice fallback, and the no-geometry→`None` branch.
- 2-slice synthetic-DICOM end-to-end (deliberately out-of-instance-order → sort → correct origin + inter-slice vector → affine survives into the sealed block spec).
- Existing content-hash-pinned golden DICOM test unaffected (rescale metadata is content-hash-independent; only `manifest_hash` moves).
- Hermetic `nix flake check`: **all checks passed!**
