# [PR 988](https://github.com/vig-os/tessera/pull/988) docs(adr): collection refs, version edge and gc through members (Proposed)

A Proposed ADR (ADR-0067) for #947: refs to collections, a version edge on collections, and `gc` that marks through
members. These are what a kit workspace needs to be a second lineage of `current` collections over a shared base.
Docs only.

## What it decides (each with options, honest costs, one Recommended)

- **D1, refs.** There is one `refs/` namespace, and the ref keeps holding one address. The object says its kind
  through an exact `product`/`members` discriminator. A plain try-each-parser rule doesn't work, because a zero-block
  manifest parses as a collection today. A `refs/collections/` sub-directory is rejected: an alpha.7 `gc` skips
  sub-directories and would sweep everything they reach, then exit 0.
- **`commit_collection`** runs under the fenced writer. It checks the CAS, the lineage's kind and id, and a member
  closure over stored or supplied members, and it stores new members in the same locked call so no `gc` can run in
  between.
- **D2, version edge.** Collections get a sealed, additive `sources` list. `supersedes` pins the predecessor's
  `manifest_hash` and stays out of `id_inputs`. The change is corpus-neutral. Old readers verify it as a newer field,
  warn, and refuse a re-seal.
- **D3, gc through members.** `gc` marks through members recursively. Members are closed: a missing, unreadable or
  wrong-kind member aborts the run and nothing is deleted. Edges stay open. There is no depth limit, and cycles are
  impossible by construction.
- **D4, pins.** A pin is a typed `pin <address>` ref record that alpha.7 reads as corrupt, so it fails closed. The
  ADR says when a pin matters: once a lineage is forgotten, and once #906 retention applies, which a pin overrides.
- **D5, the kit mapping.** A `forked_from` origin edge and a caller-supplied `fork` token in `id_inputs`. Fork,
  conflict check and merge stay kit code. The ADR lists exactly what tessera must provide (T1 to T8).
- **D6 to D9.** The member diff, discard cost (deferred to the measurement in #987), retention and WORM across a fork,
  and the non-goals: no branches and no content merge, with the restated ADR-0036 sentence.
- It also covers failure modes, a test plan per acceptance item, and a seven-step build plan (each step under
  1500 lines).

Why it is a new ADR and not a dated ADR-0036 amendment: one half is a seal-affecting format change on collections,
which is ADR-0049's and SPEC §4's territory. The ADR extends ADR-0036's one versioning story rather than adding a
second.

Every factual claim about the code was checked against `dev` by a fresh reviewer. Its two design findings were fixed
before this commit: the member-closure order, and pins under a `gc` that follows `supersedes`.

Refs: #947
