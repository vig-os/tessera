## #235 — PET/CT study migration shape
The operator runbook for landing **one real PET/CT study** as a fine-grained Tessera **collection**: normalized hot-tier `recon` products (CT + PET, range-readable + cohort-pruneable) joined by `derived_from` to the **original vendor file preserved bit-faithfully as a `blob`** cold-tier member.

- `tessera/docs/MIGRATION.md` — the WHY (tiering diagram) + step-by-step runbook, with the **NEVER-COMMIT-PHI** guardrail spelled out.
- `tessera/docs/examples/migrate-petct-study.toml` — a real, validating declarative `--spec` template (ADR-0035): vendor-raw blob + recon-ct + recon-pt, each tagged `[product.metadata] study=` for cohort pruning, with backend-choice guidance inline.
- `migrate_petct_study.rs` — proves the shape on **synthetic** data: 2-member collection, `derived_from` edges pin parent `manifest_hash`, provenance chain verifies, **re-run → byte-identical** `content_hash`/`manifest_hash`.
- `spec.rs` drift-guard test — the committed template parses + validates (topo + DAG), so doc-rot fails CI.

## #236 — Compute-node caching architecture
ADR-0039: caching is **infrastructure, not a `tessera` subcommand**. Two swappable tiers — (A) a Tessera versioning repo as the cache (`objects/<digest>` de-dups, `gc` + atime-LRU sweep); (B) `zot` pull-through with `pulledWithin` access-recency retention (the axis MinIO ILM lacks). The one new in-scope verb is a thin, cache-agnostic `tessera get <ref>→path`.

- `docs/adr/0039-compute-node-caching.md` + README row.
- `tessera/docs/examples/cache-node/{README.md,flake.nix,zot-config.json}` — a standalone, green example flake (`nixosModules.tessera-cache`).

README ADR-index conflict resolved: keeps both the real `0039` (caching) row and the `0040` (data-protection) row.
