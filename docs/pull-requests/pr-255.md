# [PR 255](https://github.com/vig-os/tessera/pull/255) feat(ingest): port curated DICOM tags to recon fields + full header to extra/ (PHI-scrubbed on de-id)

Closes the "why isn't the DICOM metadata in the .tsra?" gap. DICOM-series ingest kept only modality + rescale; the rest of the header was dropped.

## Curated tags → `recon` schema fields (sensitivity-tagged, ADR-0040 §1)
All **recommended** (a missing tag never blocks): `study_instance_uid`/`series_instance_uid` (**Identifying** — PS3.15 UID family), `study_date` (**Sensitive**), `manufacturer`/`model_name`/`kvp`/`slice_thickness`/`pixel_spacing` (**Public**). Extracted in `dicom.rs`, carried through the series, set via `with_field`.

## Full header → `extra["dicom_header"]`
Deterministic `BTreeMap<"GGGG,EEEE", {vr, value}>` of the representative slice, SQ sequences recursed, **PixelData excluded** (it's the `volume` block). Sealed + hashed via the `extra/` namespace (not schema-validated).

## PHI handling (load-bearing)
On the de-identified path (`read_*_deidentified`), the header snapshot is taken **after** PS3.15 `deidentify`, so PHI never reaches `extra/`. Test `de_identified_ingest_scrubs_phi_from_dicom_header_extra` proves PatientName/PatientID/InstitutionName are **absent** post-de-id (+ PatientIdentityRemoved=YES present) and present on the non-de-id path.

Seal-changing (recon embedded-schema shape changed) → corpus + one versioning.trycmd literal regenerated; `content_hash` untouched, `manifest_hash` shifted. Full `nix flake check` green; core+io+ingest+cli tests + clippy `-D warnings` clean.
