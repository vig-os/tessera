# [PR 861](https://github.com/vig-os/tessera/pull/861) feat(core): check blocks against the column contract (#809 part B)

Part B of #809. Part A (the contract types, parsing and byte-identical builtins) landed as #846.

## What
- `ProductSchema::check_table(role, &TableSpec)` and `check_array(role, &ArraySpec)` (ADR-0065 §8). On a refusal they
  return `Error::Contract { product, violation }`, where the `#[non_exhaustive]` `ContractViolation` names the role and
  the column: unknown role, undeclared, repeated, misplaced or missing non-optional column, column dtype or
  nullability mismatch, or array dtype, rank or axes mismatch. `Column::optional()` is the builder for the flag.
- What is carried but not compared is documented on the module, on each method and in the book: the other column
  attributes, `sequence_key`/`order` (#833), `keys`/`references` (#780), the array `unit`, and the contract's own
  consistency (#844).
- One serialisation rule, from the #846 review: `TableContract` used to write empty `sequence_key`, `keys` and
  `references` but skipped a default `order`, `axes` and `unit`. Now every defaulted contract field is skipped at its
  default, and `columns`, `dtype` and `rank` are always written. No contract has been sealed yet, so no sealed bytes
  move. A byte test pins the rule.

## Acceptance (#809)
| criterion | test (`tessera-core/tests/column_contract.rs`) |
| --- | --- |
| builtins byte-identical | `builtin_schemas_serialise_byte_identically` (part A) |
| #801 drafts parse | `the_801_drafts_parse_into_the_contract_without_losing_a_key` (part A; the strict-parse half is #830) |
| unknown role | `an_undeclared_role_is_refused` |
| column order | `columns_out_of_the_declared_order_are_refused` |
| dtype | `a_column_dtype_mismatch_is_refused` |
| nullability | `a_nullability_mismatch_is_refused_in_both_directions` |
| missing non-optional column | `a_missing_non_optional_column_is_refused` |
| array rank/dtype | `array_dtype_rank_and_axes_mismatches_are_refused` |
| schema reference docs | `docs/book/src/schemas.md`, column-contract section |

Pre-change proof: with the table/array check bodies stubbed to `Ok(())` and the old serde attributes restored,
`cargo test -p tessera-core --test column_contract` exits 101 with 7 of 12 tests failing: every column/array
refusal plus the byte test. The unknown-role lookup sits in `ProductSchema::check_*`, so the stub keeps it. Without
this PR none of the refusal tests compile. With it, 14 of 14 pass (exit 0), including two tests added after
review: an array contract without axes accepts any axes, and a contract that lists a column twice refuses every
block (#844 will make that a contract error).

Review fixes folded into the first commit: `UnknownRole.kind` is a `BlockKind`, not a string. `ArrayRank` is `u32`
on both sides. `ColumnOrder.position` is now `block_position`, the block's index. The `# Errors` text gives the
real pass order. The docs say the checks are library calls that validate and seal don't run yet.

Closes #809
