# [PR 250](https://github.com/vig-os/tessera/pull/250) feat(provenance): source-file integrity hashes + sealed producer stamp

Closes two provenance gaps found in real-data use (a `recon` from a DICOM series had an `ingested_from` edge with the path but **no content hash**, and nothing recorded **which tool** wrote the file).

## Source-file integrity (B)
The `ingested_from` edge now carries a `content_hash` = blake3 **merkle root** over the source files' digests — cryptographically tying the product to the exact source-of-record bytes. Independent of the (possibly PHI-scrubbed) `--source-label`, so the integrity link survives de-identification. Shared `tessera_ingest::provenance::{source_digest, ingested_from}`; wired through **raw / blob (×2, reuses the blob block digest — no second read of a multi-GB file) / ge-hdf5 / nifti / dicom** (series merkle root threaded from the engine, which holds the slice paths).

## Producer stamp (C)
`seal()` stamps `manifest.producer = "tessera/<version>"` (a new sealed manifest field, re-stamped per version) so a reader knows what built the file.

## Display
`tsra inspect` prints `producer` and the per-edge `content_hash`; `tsra ls sources` shows the integrity hash on the group header.

Seal-changing (producer + source hashes enter `manifest_hash`) → corpus + trycmd regenerated; `id`/`content_hash` unchanged. Tests: raw asserts the edge hash equals the recomputed source merkle root; ls-sources shows it. Full `nix flake check` green.

Second of the FAIR/provenance batch (after #248 embedded schema). Remaining: DICOM curated-tags→fields + full-header→extra/ (D) and the full schema field-roster display.
