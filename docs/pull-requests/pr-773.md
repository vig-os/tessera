# [PR 773](https://github.com/vig-os/tessera/pull/773) docs(adr): amend ADR-0064 §8.1 so the plateau is a slope test over every run

Second amendment to ADR-0064 §8/§8.1, which applies the owner's 2026-11-08 ruling on the plateau. It is the new
section "Amendment (#770, 2026-11-08)", B.1–B.4. The superseded text in §8, §8.1, A.1 and A.2 is marked
*(Amended by #770, below: …)*.

**Criterion 2 is now a slope test.** For each `W ∈ {1, 4}` it takes every run at `n ≥ 16 W`, all `k` repeats with
no medians, and fits an OLS slope of peak `RssAnon` against `n`. A run passes when:

- **Slope:** `b̂ ≤ c_leaf + t₀.₉₅,N−2 · SE(b̂)`, the one-sided 95 % bound.
- **Resolution:** `2 · t₀.₉₅,N−2 · SE(b̂) ≤ 121,635 B/leaf`, the 0.029 B/row zone-statistics half. A run too
  noisy to see that regression fails.

**What else changes.** `τ` is retired, and the amendment states what replaces it. Criterion 1, `s`, `s_rss`,
`c_leaf`'s definition, the sweep with `k = 3`, criteria 3–5 and criterion 6's `/dev/shm` job are unchanged.

**Worked numbers.** These come from `tessera-715-r3-sweep-2` (`records.json`). There were no new runs.

| Case | `W = 4` slope vs bound (B/leaf) | `W = 1` slope vs bound (B/leaf) |
| --- | --- | --- |
| r3 as measured | 19,961 ≤ 33,160, pass | 5,787 ≤ 21,290, pass |
| r3 + 0.058 B/row zone stats (+47 MB) | 263,231, fails | 249,057, fails |
| r3 + 0.029 B/row zone stats | 141,596, fails | 127,422, fails |
| Pre-#759 writer, its own data (`tessera-715-sweep-1`) | n/a (r1 ran k = 1) | 24,265 > 10,652, fails |
| r3 + reverting #759 (+18,478 B/leaf) | 38,439, fails | 24,265, fails |

**Power.** At r3's noise, `k = 3` detects a growth of 0.0120 B/row at `W = 4` and 0.0063 B/row at `W = 1` with
95 % probability, so `k` doesn't change.

**Departure from the issue text.** The issue says the "pre-#759 per-leaf cost (≈12.8 KB/leaf)" must fail.
12.8 KB is that writer's live heap per leaf. The criterion measures `RssAnon`, where that writer grew by
24,265 B/leaf, and that fails. A 12.8 KB/leaf growth in `RssAnon` is below what `k = 3` resolves at `W = 4`
(that would take about 35–46 runs per point). `tessera-io/tests/session_leaf_memory.rs` checks the live
per-leaf heap exactly. B.4 explains this.

**Where §8.1 is quoted.** ADR-0026 and the ADR index are updated to match. The `push_table` rustdoc, the CHANGELOG
and the FEATURE-MATRIX don't quote the plateau, so they're unchanged. `tessera/bench/ksb/677-rss-proof/` isn't on
`dev`, so the computation is a worked table in the ADR, not a script. The evaluator changes come after this merges.

Closes #770
