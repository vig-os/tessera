# [PR 491](https://github.com/vig-os/tessera/pull/491) fix(docs): the versioning walkthrough documented its own diff/publish/verify failing

Closes #489.

## The fault

`versioning.trycmd`'s last three cases asserted this as their **expected** output:

```
? 1
error: io: No such file or directory (os error 2)
```

`diff` was asked for version `c40501d7…`, which does not exist. The version `commit` actually prints —
four cases earlier in the same file — is `f5fc37b4…`. So `diff` failed, `publish` never wrote
`published.tsra`, and `verify` then failed on the file that was never created. The suite stayed green
because the snapshots recorded the errors.

These files are `{{#include}}`d into the book, so the **rendered versioning chapter showed readers that
`diff`, `publish` and `verify` do not work** — and those three verbs, the most interesting part of the
CoW path, had no working walkthrough coverage at all.

## The fix

Repointed at the real version. The prose needed no change: it already described what the commands do,
and the output now agrees with it.

- `diff` — "0 blocks re-encoded, one metadata field added" is exactly what it reports
  (`blocks: 0 changed, 1 unchanged` · `metadata: 1 changed` · `+ tracer "FDG"`).
- `publish` — writes the history-free artifact and prints its `snapshot_of` breadcrumb.
- `verify` — `OK  published.tsra verified (1 blocks)`.

Every expected block was produced by running the command and reading the result, not by
`TRYCMD=overwrite`. The hashes stay hardcoded: they are content hashes of fixed inputs, which is what
the file's own header promises, and the run confirms they are stable.

## Audit of the other walkthroughs

Checked all 14 for the same fault. Seven nonzero-exit cases exist suite-wide; the four that remain are
all deliberate:

| File | Case | Intended? |
| --- | --- | --- |
| `bench.trycmd` | `--auto` conflicts with `--workers` | yes — teaches the clap conflict |
| `sql.trycmd` | `sql requires the 'sql' feature` | yes — teaches the feature gate |
| `persona_signing.trycmd` | `untrusted: key_id … not in the trust store` | yes — impersonation rejected |
| `persona_signing.trycmd` | `signer policy: required …` | yes — signer policy enforced |

No `.stdout` / `.stderr` sidecar files exist, so there was nowhere else for blessed output to hide.

## The guard

`TRYCMD=overwrite` cannot tell an intended error from a regression — it records whatever the binary
printed — so a blessed snapshot is only as good as the read afterwards. `no_walkthrough_asserts_an_
accidental_io_error` does that read in CI.

It deliberately does **not** flag nonzero exits, since four of them are the lesson. It flags
*filesystem* errors, because no walkthrough teaches "the file I just told you to create is not there".

Verified by reintroducing the fault: the gate fails and names the file and line
(`tests/cmd/versioning.trycmd:79: expects "No such file or directory" — a walkthrough step is broken,
not teaching`, 14 files scanned).

Found while adding `provenance-walk.trycmd` in #490, which is why every case in that file was
hand-verified rather than blessed.
