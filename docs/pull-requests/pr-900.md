# [PR 900](https://github.com/vig-os/tessera/pull/900) docs(spike): seal-encoding bake-off A vs A′ vs B and ADR-0066 (accepted: A′)

**Decided: A′ (owner, 2026-11-18); further decisions recorded 2026-11-19.** ADR-0066 is **Accepted**. It records the
sealing design and a nine-step ordered implementation plan, each step with its crates, scope, acceptance criteria and
dependencies, for filing as sub-issues of #897.

This PR is the evidence for the decision in #897, plus ADR-0066. It changes no product code, SPEC, corpus or golden.
The amendments to ADR-0020 D4, ADR-0022, ADR-0037, ADR-0054 and ADR-0060 land with the implementation; the ADR index
only notes on those rows that ADR-0066 will amend them.

- Spike: `docs/spikes/897-seal-encoding.md` (verdict table first)
- ADR: `docs/adr/0066-seal-encoding.md` (+ index row, + a planned row in `tessera/docs/FEATURE-MATRIX.md`)
- Prototypes and raw results: `docs/spikes/897-seal-encoding/`. `run.sh` regenerates every `results/*` file
  byte-for-byte (verified twice).

## The decision (A′)
`manifest.json` is stored as exactly its RFC 8785 JCS bytes, without a `manifest_hash` key. The seal is `blake3` of the
stored bytes, kept in a `manifest.seal` member (entry 2 of the `.tsra`). Readers refuse bytes that are not their own
JCS form and keep the I-JSON check. 64-bit values are schema-typed strings (#895). The mechanism keeps every existing
seal (13 tracked products, 12 distinct manifests; 8/8 goldens). Options weighed: **A** (alpha.6, re-serialise and
hash, plus #895) and **B** (deterministic CBOR with dCBOR-style numeric reduction); B0 (without reduction) is kept as
a contrast.

## Decisions of 2026-11-19 (ADR rules 10–13)
- **10. No migration verb.** There are no real products to keep, so there is no migration verb and no second
  reading path. Readers refuse products written before this ADR, with an error naming the format found and the format
  required. The format-version string `TESSERA_VERSION` stays `"0.0.0"`, decided in ADR-0066 itself: it is sealed in
  `producer` (a bump would move every seal and lose the cutover's preservation proof), ADR-0052 §1 keeps the format
  unfrozen before 1.0, and both layouts declare `0.0.0`, so the reader tells them apart by layout. ADR-0052's Update
  of 2026-07-03 is cited only as the description of today's value.
- **11. The format break ships alone, before the bridge work** (#454 → #811), as its own alpha.
- **12. #720 rides the break:** `content_hash` covers the primary blocks only (ADR-0028 §4); `manifest_hash` still
  commits to every block.
- **13. #828 rides the break:** `tessera-table-v2` becomes the default table codec profile, after a design note.

## Implementation plan (ordered)
Rule: every step's PR keeps CI green on its own; a step that moves a seal regenerates the goldens it moves in that
same PR and explains each one. Step 1 can move seals (built-in schemas are embedded in manifests); steps 2 and 3 do
not.
1. #895: schema-typed 64-bit strings and ranges (`tessera-core`, `tessera-ingest`, `tessera-py`).
2. Writers emit the JCS form of every sealed JSON document (`tessera-io`, `tessera-cli`, `tessera-ingest`,
   `tessera-py`).
3. The stored-bytes API and the canonical-bytes check (`tessera-core`).
4. The A′ format cutover, closing #901 (all crates, corpus, reference reader): the alpha layout is refused, and the
   13 products (12 distinct manifests) verify with every golden unchanged from its base.
5. #720: `content_hash` over primary blocks only.
6. #828 design note for `tessera-table-v2`.
7. #828: `tessera-table-v2` as the default profile.
8. The final corpus and conformance cross-check; every moved hash traces to step 1, 5 or 7.
9. Cut the alpha; the bridge work starts afterwards.

|---|---|---|---|

| New deps | none | none | CBOR codec + own strict decoder ×3 |

**Recommendation (accepted): A′ with #895.** A′ and B are equally sound on the attack replay. The choice is native
64-bit integers (B) against keeping every seal and signature, no new dependency, stock writers and `jq` legibility
(A′). For readers, A′ requires both the canonical check (S7) and I-JSON (S5b).

## Proof
- `cargo test --release` (spike crate): 4/4 pass, covering the profile codec at the 64-bit edges, preferred floats
  incl. f16 subnormals, numeric reduction, and every refused form.
- `./run.sh`: exit 0. Python (`jcs` 0.2.1, `cbor2` 6.3.0) and node (`canonicalize` 5.1.0, `cbor-x` 1.6.9) run on the
  same bytes. Float formatting agrees on 200,000/200,000 doubles in Rust, Python and JS.
- Fresh-context reviews of the spike, and of the ADR after the 2026-11-19 decisions; their findings are fixed.
- CI: guardrails gates, including adr-matrix, are green.
