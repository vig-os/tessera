# [PR 786](https://github.com/vig-os/tessera/pull/786) refactor(identity): move the ADR-0047 envelope into the hdf5-free tessera-identity crate

Closes #762. Unblocks MorePET/visionx-rs#186.

## What

This PR moves the ADR-0047 crypto-shred envelope primitives out of `tessera-ingest`, which links libhdf5, into a new
crate, `tessera-identity`. The primitives are `IdentityDocument`, `AUX_IDENTITY_NAME`, `encrypt_identity`,
`decrypt_identity`, `parse_recipient` (the recipient validation) and `generate_keypair`. The new crate depends on
`tessera-core`, `age`, `serde` and `serde_json`, and nothing else. A Rust producer can now write `aux/identity/identity.age`
with `tessera-io` and `tessera-identity`, without `tessera-ingest`.

## Why a new crate (design choice)

The dependency graph decides it:

- `tessera-core` is ruled out. It is `tessera-wasm`'s only dependency and the abi3 wheel's, so `age` and its RNG would
  reach both. ADR-0047 keeps decryption host-only.
- `tessera-io` is ruled out. `tessera-py` (the wheel) depends on it, and the wheel has no `age` today.
- That leaves `tessera-identity`. The new `identity-deps` flake check enforces the contract: it runs `cargo tree` only
  and compiles nothing.
  - `tessera-identity` has no hdf5 crate in its graph.
  - `age` is absent from `tessera-wasm` and from `tessera-py`.
  - Each graph must also contain a crate it is known to have, so an empty tree can't pass.

New-crate wiring:

- **Workspace and release:** workspace member and dependency entry. release-plz is workspace-wide, and the crate has its
  own `CHANGELOG.md`. cargo-dist builds only the `tessera-cli` binaries. The flake `srcFilter` already admits
  `/tests/fixtures/`.
- **cargo-deny:** nothing new to admit; `age` was already in the tree. The comment about how it is reached is
  corrected.
- **Gate B (`feature-snapshots`):** regenerated, and the delta is inert (below). The snapshot normaliser learns the
  `tessera-identity` name.
- **Pre-commit:** the whitespace fixers now skip `tests/fixtures/`, as they already skip `*.trycmd`. The fixer had
  rewritten the byte-exact golden plaintext by appending a newline.

## Semver

No public path or type changes. `tessera-ingest` does `pub use tessera_identity as identity`, so every
`tessera_ingest::identity::*` path names the same item. The one addition is `tessera_identity::Recipient`, a
re-export of `age::x25519::Recipient`, so callers don't need a version-matched `age` dependency of their own.
`tessera-ingest` drops its direct `age` dependency. The root CHANGELOG has an entry, and ADR-0047 carries an
amendment.

### Envelope bytes unchanged

An `age` ciphertext is random by design: each call draws a fresh file key and ephemeral share. So
`tessera-identity/tests/pre_move_golden.rs` pins everything the code decides, against an envelope plus plaintext
written by `tessera_ingest::identity::encrypt_identity` at `26159de`, before the move:

- The pre-move envelope decrypts, through the moved code, to the fixture document.
- A new envelope's plaintext, decrypted with `age` alone, is byte-equal to the pre-move JCS plaintext. The fixture's
  keys are written out of order, so this also pins field order.
- Both envelopes have the same armor and an X25519 first stanza.

The fixture key is a throwaway committed in the test with `gitleaks:allow`; it protects only a dummy document. The
framing check de-armors and matches header bytes. An earlier base64-prefix version failed about 1 run in 5 because
the last character depends on the random share. After the fix, 200 runs had 0 failures.

### Producer to ingest reader

`tessera-ingest/tests/identity_envelope.rs` packs a conformance fixture and writes the envelope through
`tessera_identity` plus `tessera_io::add_aux_members`. It reopens the product, decrypts the envelope through
`tessera_ingest::identity::decrypt_identity`, compares documents across the re-export (same type), and checks that the
payloads still verify. The `identity-deps` check covers the "builds without ingest" half.

### Gate B delta is inert

Only `blake3.txt` moved: `tessera-ingest`'s subtree now sits one level deeper, behind `tessera-identity`. No changed
line names a third-party crate. With tree depth ignored, the only new lines are `tessera-identity feature "default"`
and `tessera-identity vWORKSPACE`.
