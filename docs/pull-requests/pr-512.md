# [PR 512](https://github.com/vig-os/tessera/pull/512) chore(deps): standardise on Renovate and retire dependabot.yml

## Description

Standardise tessera on Renovate as its single dependency bot, per the org-level move of vulnerability-fix PRs from Dependabot to Renovate (vig-os/org-config#307). Resolves the dual-bot configuration described in #467, and with it the class of failure in #466 (Dependabot's `dependabot/*` branches fail devkit's `Commit Messages` gate; see vig-os/devkit#1755).

## Type of Change

- [x] `chore` -- Maintenance task (deps, config, etc.)

## Changes Made

- `renovate.json` `enabledManagers`: add `cargo`, remove `npm`.
  - Renovate's cargo manager defaults to `managerFilePatterns: ["/(^|/)Cargo\\.toml$/"]` (checked in renovate 43.263.3), so the nested workspace under `tessera/` (`tessera/Cargo.toml` + six crates) is found with no extra config.
  - There is no `package.json` anywhere in the tree, so the npm manager was dead.
- Delete `.github/dependabot.yml`. Each entry is covered or dead:
  - `github-actions` (`/`): covered by Renovate's github-actions manager. The preset deliberately skips devkit-managed workflows (they are bumped upstream and shipped with each devkit release); the hand-written ones (`nix-check.yml`, `release-nix.yml`, `release-plz.yml`) stay covered.
  - `pip` (`/tessera/bench/ecosystems`): covered by `pep621`, which reads that `pyproject.toml` and maintains its `uv.lock`.
  - `npm` (`/`): no manifest.
- `ci.yml` is left alone (managed file). Its local `dependabot/.+` branch clause, and the mirrored one in `scripts/check-branch-name.sh`, become unused but harmless; they go away with the next devkit upgrade or vig-os/devkit#1755.

Dependabot **alerts** are independent of `dependabot.yml` and are unaffected.

**Obsolete after merge:** Dependabot's open version-update PRs #444 and #475 no longer have a config behind them. They are left open here for the maintainer to close.

**Note:** Renovate is not yet running on this repo (no `renovate/*` branch or Dependency Dashboard has ever appeared); getting the App to process it is being checked separately. Until then this repo has no version-update bot.
