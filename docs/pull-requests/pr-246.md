# [PR 246](https://github.com/vig-os/tessera/pull/246) spike(#241): ADR-0041 — provider-mediated field decryption (rung 2)

Research/design spike for #241 → **ADR-0041**. Docs-only (one new ADR + one README index row); no engine/format change. Full `nix flake check` green.

Frames **rung 2** of ADR-0040's confidentiality ladder (static `age` → **provider-mediated** → TEE) and pins the honest threat model so we never oversell "encrypted" as "copy-proof."

### Key decisions
- **Envelope:** per-tier DEK (AEAD) encrypts the field; the **DEK is wrapped by a KEK held in an external provider**. Wrapped-DEK + opaque provider ref + policy handle ride in the **same additive sidecar ADR-0040 §4 established** — *forced*, because KMS/AEAD ciphertext is nonced/non-deterministic and cannot enter `content_hash`/`manifest_hash`. Seal still commits to plaintext (or a per-field commitment, §6) → **writer-determinism preserved**, reusing the ADR-0037 detached-signature precedent.
- **unwrap-DEK over decrypt-as-a-service** (default): smaller compliance surface (provider sees key material, not PHI), lower latency, better vendor abstraction. Decrypt-as-a-service kept as a `mode="decrypt"` opt-in for regulators who require provider-as-sole-PHI-handler.
- **Provider shape:** a **thin Tessera key-broker fronting a real KMS** (AWS/GCP KMS or Vault Transit). Native bare broker rejected (re-solves durability/HA/rotation). Format stays **provider-blind** via a 4-method `KeyProvider` trait (`wrap`/`unwrap`/`policy_check` + optional `decrypt`), with AAD binding `manifest_hash` to kill cross-product replay. Providers are *infra, not a `tessera` subcommand* (ADR-0039's discipline).
- **What it buys:** time-gating, revocation, audit, **crypto-shred at scale** (the consent-withdrawal endgame of ADR-0040 §2.2 that finally reaches leaked copies), consent linkage.
- **The honest limit (§4):** the **analog hole** — provider gates key release + access over time, NOT what an authorized recipient does with decrypted plaintext (screenshot / memory dump / re-export). TEE/confidential-computing named as the *partial* rung 3, explicitly a future ADR. A full threat-model table (§9) shows rung 2 wins exactly where rung 1 lost and loses exactly where copying happens.

### Deferred / flagged open questions
Per-field commitment storage location (rhymes with ADR-0037 §3's signatures-as-hashed-block fork) · KEK rotation / `kek_version` · break-glass vs crypto-shred-permanence tension · cross-vendor audit-log normalization · consent-system integration shape · in-memory DEK caching + TTL semantics.

Closes #241.
