# [PR 765](https://github.com/vig-os/tessera/pull/765) fix(io): hold each committed block as its journal line, not a BlockRef

Closes #759

## What

`WriteSession` held a clone of every committed `BlockRef` until the seal, each spec a `serde_json::Value` tree of
small allocations (every leaf of a partitioned table repeating the same column specs). It now holds each committed
block as `Committed { name, line }`: the name, for the checks every append makes, and the journal line `commit`
already computed, the `BlockRef` as compact JSON. The seal parses the lines back into the manifest's `BlockRef`s,
as `recover` always has (`recover` now keeps the journal's own lines). Each commit parses its line back once, so a
block the seal couldn't parse (a spec nested past `serde_json`'s 128 levels) is refused at its append, before its
journal line, not at the seal after every block is encoded. `serde_json` keeps key order (`preserve_order`) and floats (`float_roundtrip`, which
`serde_jcs` enables), so the sealed bytes are unchanged.

`WriteSession::blocks` is private: no public API or semver change. `BlockRef` is untouched. The seal still builds the
manifest's `BlockRef`s in memory, once, after the last commit (documented on `WriteSession::seal`).

## Proof

- `tests/session_leaf_memory.rs` (new, one `#[test]` per binary, counting allocator): commits 64 and 256 leaves of a
  12-column table and bounds the heap the session keeps by the leaves' serialized manifest entries (taken from the
  sealed manifest) plus 128 B per leaf.
  - before the fix: 64 leaves 865,632 B (13,525 B/leaf), 256 leaves 3,461,664 B (13,522 B/leaf) for entries of
    2,403 / 2,404 B/leaf: FAILED (exit 101)
  - after: 157,397 B (2,459 B/leaf) and 628,913 B (2,456 B/leaf): ok
- `write::tests::a_committed_block_seals_as_the_reference_appended` (new): key order, `u64::MAX`, float bits
  (subnormals, `-0.0`, `f64::MAX`) survive a seal, and the `manifest_hash` equals the batch seal of the same reference.
- `write::tests::a_block_the_seal_could_not_parse_back_is_refused_at_its_append` (new): a 200-deep spec is refused
  at append (watermark stays 0), and the session appends and seals afterwards. It failed while the check parsed into
  `serde::de::IgnoredAny`, which skips values without serde_json's depth limit.
- Byte identity, unchanged tests: `write::tests::streamed_product_is_identical_to_batch_and_verifies`,
  `stream::tests::streamed_equals_batch_for_many_blocks`,
  `stream::tests::content_hash_is_identical_across_workers_and_windows`,
  `stream::tests::push_table_of_one_block_is_byte_identical_to_table_job_streaming`, the `recover_*` tests,
  `tests/conformance.rs` (`corpus_hashes_match_goldens`, …) and `tessera-ingest`'s
  `ingest_corpus_hashes_match_goldens` (streams through `WriteSession`).
