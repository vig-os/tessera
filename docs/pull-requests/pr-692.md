# [PR 692](https://github.com/vig-os/tessera/pull/692) docs(spike): bound the Vortex writer's memory and weigh logical tables over bounded blocks (#681)

Refs #681

Design note for bounding the Vortex writer's memory (`docs/spikes/681-vortex-writer-backpressure.md`).
Docs only; no code change. Revision 3. The note opens with a **Decision needed** section for the owner.

- **The writer fix F** is an input gate on pending sink bytes, with a starvation override.
  - It is deadlock-free (88 gated runs, including `B = 0`) and byte-identical.
  - It removes sink starvation: the consumer shape at 268 M rows drops from 834 to 134 MB.
- **F alone does not bound the RSS.** Per encode worker the peak is `B + D(width) + ε + K(width) + c·rows`.
  - The order debt `D` grows with width (73 MB → 4,566 MB for 1 → 64 `u64` columns), and no budget
    pushes it down.
  - `c·rows` is about 0.058 B/row, about half of it zone statistics.
- **Bounded blocks bound it.** With input staged to disk per block and `W` workers, the peak heap is
  ≤ `min(W, n) × p_block + s`. For the consumer shape at `W = 4` it measures 128–143 MB from 67 M to
  1.07 G rows.
- **No partitioning option meets #677 as written.** #677 rejects suffixed physical blocks. The note
  compares three options:
  - P: `pairs_NNNN` blocks.
  - P-logical: ADR-0063 `pairs/NNNN` leaves, read as one logical `pairs`.
  - R: Vortex row groups in one block.
- **The recommendation is P-logical, via a new ADR**, if the owner retires "one logical block stays one
  canonical block". Streamed tables above `BLOCK_ROWS` would then get other bytes than alpha.4 wrote;
  readers are unchanged.
- **F goes upstream after a maintainer conversation** on vortex-data/vortex#10046. The comment is
  drafted in the note, for the owner to post.
- **ksb runs**, all exit 0:
  - `vortex-681-sweep-1`: 64 runs, 3 of them deadlocks reproduced as predicted.
  - `vortex-681-sweep-2a`: 12 runs.
  - `vortex-681-sweep-2b`: 54 runs.
  - `vortex-681-sweep-3`: 63 runs.
