# [PR 357](https://github.com/vig-os/tessera/pull/357) fix(ci): make the local gates actually run — hook install, dead hooks, trycmd sandbox

## Why

The pre-commit gate suite has not been running in this repo. Three independent causes, each masking the others — and together they are why `--no-verify` became the house style, which then bypassed every *working* gate too.

## What was broken

| Cause | Effect |
|---|---|
| `shellcheck-py` fails to build a wheel in prek's uv cache (`cp313`/`cp312` tag mismatch) | prek installs in file order → **all six guardrails agent-drift gates, rustfmt, clippy, cargo-deny and gitleaks never installed** |
| `typos` is fetched as a generic-linux dynamically linked binary | NixOS cannot exec it at all (stub-ld) |
| `pip-licenses`, `check-action-pins`, `bandit`, `validate-commit-msg` all call `uv run <script>` | **There is no `pyproject.toml` or `uv.lock` anywhere in the repo** since the fd5 graduation. `validate-commit-msg` runs at commit-msg stage → failed on *every* commit |
| `check-skill-names` pointed at `scripts/check-skill-names.sh` | Script was never committed |
| Branch-name regex allowed only `chore/<summary>` + `<type>/<issue>-<summary>` | Rejected `feat/`, `fix/`, `perf/`, `polish/`, `land/`, `spike/` — **14 of the last 30 merged PR branches** |
| trycmd walkthroughs ran in-place in `*.in/` | `tessera sign` **rewrites the tracked fixture `study.tsra`** with fresh bytes each run; `versioning` accumulated repo state so the *second* `cargo test` failed and cancelled 49 other tests |

## What this changes

- **shellcheck + typos** now come from the devShell (flake.nix), like every other tool here.
- **Three hooks reimplemented** as shellcheck-clean repo scripts: `validate-commit-msg.sh` (implements `docs/COMMIT_MESSAGE_STANDARD.md`, including the chore/dependabot `Refs:` exemptions), `check-action-pins.sh`, `check-skill-names.sh`.
- **Two hooks dropped** — `pip-licenses` and `bandit` target a Python app this repo no longer contains; Rust dependency licensing is already covered by `cargo-deny`.
- **Branch regex** derived from branch names actually used on merged PRs. Issue number optional, because `.gitmessage` already puts `Refs: #N` on the commit.
- **trycmd sandbox** enabled via sibling `*.out/.keep` — trycmd turns the fs sandbox on iff `<name>.out/` exists (`trycmd-0.15.11 src/schema.rs:104`); a `<name>.toml` is a *test file* in its own right and is silently ignored.
- **`bash -euo pipefail`** on the three cargo hook entries — without `-e`, a multi-command entry reports only the last command's status, so a failing `cargo fmt --check` passes silently.
- **Docs**: `tessera/CLAUDE.md` pointed agents at the deleted `spike/tessera-core` branch, a non-existent worktree, a finished P0-ADR task list, and *"cargo test (17 pass)"* against an actual **346**. `AUTONOMOUS-GOAL.md` archived — as written it sends an autonomous run onto a branch that no longer exists.

## Verification

- **trycmd fix proven**: two consecutive `cargo nextest run -p tessera-cli --test cli` both PASS (the second used to fail), and `sha256(persona_signing.in/study.tsra)` is unchanged.
- **commit-msg validator**: 10 cases covering both outcomes (valid feat/chore/dependabot/merge; invalid type, trailing period, missing blank line, missing `Refs:`, misplaced `Refs:`, `Refs:` without an issue).
- **branch regex** checked against all 60 merged-PR branch names.
- `shellcheck`, `yamllint --strict` clean.
- **This is the first commit in the repo to pass the full hook suite without `--no-verify`.**

## Follow-up (blocked on token scope)

The companion change to `.github/workflows/` is split out: `main`'s required status check is the bare context `nix flake check`, but the matrix job reports as `nix flake check (x86_64-linux)`, so **the requirement matches nothing and is unenforceable**; `dev` has no protection at all. Pushing that needs a token with `workflow` scope.
