# [PR 902](https://github.com/vig-os/tessera/pull/902) chore(deps): fix RUSTSEC-2026-0544 (libz-sys), unyank async-executor, document chrono/humantime ignores

Fixes `cargo-deny` (Lint & Format), which has failed on dev b290237 and on every PR since the advisory DB update.

| ID | Crate | Kind | Resolution |
|---|---|---|---|
| RUSTSEC-2026-0544 | libz-sys 1.1.31 (zlib `gz_vacate` heap overflow) | **vulnerability** | **upgraded** to 1.1.33 (`cargo update -p libz-sys`) |
| yanked | async-executor 1.14.0 | yanked | upgraded to 1.14.1 (`cargo update -p async-executor`) |
| RUSTSEC-2026-0543 | chrono 0.4.45 | unmaintained, all versions, no safe upgrade | documented `ignore`, removal tracked in #899 |
| RUSTSEC-2026-0542 | humantime 2.3.0 | unmaintained (wraps chrono), all versions | documented `ignore`, removal tracked in #899 |

Only those two crates move in `Cargo.lock` (4 lines). No blanket `cargo update`.

## Paths (`cargo tree -i <crate> -e normal,build,dev --workspace --all-features`)

**libz-sys**: one lock entry, two paths, both fixed by the bump:

- build dependency of zarrs 0.23.13 → tessera-io → tessera-cli / tessera-ingest / tessera-py
- hdf5-metno-src / hdf5-metno-sys → hdf5-metno → tessera-ingest / tessera-cli: the zlib that the `static-hdf5`
  (cargo-dist release) builds link statically

**chrono**:

- arrow-array 58.4.1 / parquet 58.4.1: the arrow-58 ingest pins (tessera-cli; tessera-ingest dev)
- arrow-array/-cast/-ord/-select 59.3.2 → vortex-arrow/-file/-layout 0.93 → tessera-io (every binary, tessera-py included)
- dicom-core 0.10 → dicom-* → tessera-ingest
- object_store 0.14: the tessera-io `cloud` feature and a tessera-cli dev-dependency
- datafusion 54, arrow-* 58.3, object_store 0.13.2, chrono-tz: the tessera-cli `sql` feature only

**humantime**:

- object_store 0.14: the tessera-io `cloud` feature and a tessera-cli dev-dependency
- object_store 0.13.2 → datafusion 54: the tessera-cli `sql` feature only
- trycmd 0.15 (directly and via humantime-serde): a tessera-cli dev-dependency

**Direct use:** none. No `crates/*/Cargo.toml` names chrono or humantime, and nothing in `crates/` calls
`chrono::` or `humantime::`. So there's no code of ours to migrate to `jiff`. #899 tracks dropping the ignores once
upstream moves off chrono.
