# [PR 470](https://github.com/vig-os/tessera/pull/470) fix(ingest): normalise the NIfTI spatial unit to mm and read big-endian NIfTI-1

The three NIfTI follow-ups from #447, as one PR because they are one story: two header fields the
decoder was not reading, and the test that proves the geometry math against a third-party writer.
Two commits — the red tests, then the fix.

| | Was | Now |
|---|---|---|
| **#446** | `xyzt_units`' **spatial** code ignored, `unit` hard-coded `"mm"` — a micron volume sealed an affine whose numbers were microns, labelled mm | affine scaled to mm at the door (m / mm / µm) |
| **#449** | big-endian NIfTI-1 refused outright | read in both orders; a BE file and its LE twin seal the **identical** `content_hash` |
| **#448** | the #447 real-FSL cross-check existed only as a throwaway probe | committed as a test, using FSL's own header parameters |

## #446 — normalise, don't carry

The sform/qform affine **and** `pixdim` are expressed in the `xyzt_units` length unit. #396 taught this
decoder the *time* half of that byte and left the space half ignored, so a micron-unit volume — routine in
preclinical / µCT / light-sheet work — sealed a **1000× wrong** affine labelled `"mm"`. No gate catches it,
because such an affine is perfectly non-degenerate.

The decision — and why it needs no format change: **ADR-0030 §1** makes `mm` the world-coordinate default
and says sources are "normalised at the door" (ADR-0025), and **ADR-0032**'s `CANONICAL_UNITS` admits no
other length, so `"um"`/`"m"` would fail `unit_is_canonical`. Scaling is therefore the ADR-conformant
route, and it is the same move as the existing RAS→LPS flip. The factor scales the rotation block *and*
the translation (every entry of a NIfTI affine is a length in that unit) and is resolved once for both
transforms.

Unspecified (`0`) assumes mm at **debug** level, not a warning: it is common enough — nibabel's own
`standard.nii.gz` leaves it `0` — that warning there would only train operators to ignore warnings. An
*undefined* code (`4`–`7`) is junk bits, so that one **is** a warning, but the volume is still read rather
than refused.

**Hash impact, deliberately narrow:** mm (`2`) and unspecified (`0`) are byte-identical to before, so the
common case moves nothing — asserted with `assert_eq!`, not approximately. Micron and metre inputs *do*
move `manifest_hash`; that is the fix. No NIfTI product is in the conformance corpus, so no golden moves.

## #449 — value-preserving and unrecorded

Half the `.nii` files in nibabel's own test data are big-endian — ANALYZE-era and SPARC/PowerPC data,
precisely what an archival format is asked to read *because* nothing modern can. NIfTI has no endianness
flag, so the order is inferred from `sizeof_hdr`: the format defines it as 348, so reading it byte-swapped
means every multi-byte field is swapped. That is why the header opens with a known constant.

Per **ADR-0056 H6** the byte order is value-preserving and **never recorded** — byte order needs no
recovery instructions, and recording it would make a BE file and its LE twin seal differently, which is
the one thing that gate forbids. `the_big_endian_and_little_endian_twins_agree_with_each_other` asserts
the relation directly (equal `content_hash` *and* `manifest_hash`), mirroring what #461 established for
NumPy `>f8`/`<f8`. It covers every supported datatype, not just int16 — the widths are where a naive swap
goes wrong — and a big-endian `.nii.gz`, so the two features compose.

Structurally the four `*le` free functions become a `Raw { bytes, endian }` reader plus an `Endian` voxel
decoder, so exactly **one** place per width knows about byte order and a half-swapped read is not
expressible. There is deliberately no `Raw::i32`: the only `i32` header field is `sizeof_hdr`, read before
the order is known because it is what *reveals* it. (Clippy caught that as dead code — a useful signal
that the refactor was complete.)

`sizeof_hdr_error` loses its big-endian arm, since that case is now supported rather than diagnosed, and
keeps NIfTI-2 detection.

## #448 — what the licence allows, and what it doesn't

The ambiguity **stands** after checking both places: nibabel's `nibabel/tests/data/README.rst` documents
only the PAR/REC provenance and says nothing about the `.nii` files, and `COPYING` carves out PAR/REC as
PDDL and `doc/source/someone.nii.gz` as MNI/ICBM while never naming `tests/data/*.nii`. MIT is a
*software* licence, so those files are covered only by omission.

So **no third-party bytes are shipped.** What is not encumbered is the **header parameters**, which are
facts about the format rather than a work — so
`a_real_fsl_qform_reproduces_the_affine_fsl_itself_wrote` carries the exact qform of
`nibabel/tests/data/functional.nii` and asserts the decoder reproduces the affine **FSL itself wrote into
that same file's sform**, measured during #447 as an exact match. The bytes are ours; the numbers, and the
answer they must produce, are FSL's. It exercises the two parts the conversion is easy to get wrong: the
`pixdim[0] = -1` qfac k-column flip, and `b² + c² + d² = 1` exactly, which takes the `a = 0` 180°-rotation
branch of `nifti_quatern_to_mat44` rather than the ordinary `a = sqrt(1 − …)` path.

**A deviation worth naming:** the plan approved a *generator script* producing fixture files. I didn't add
one, because it would be a second, redundant generator — the in-tree `Synth` builder already is one, it is
documented, and every test uses it, whereas files written by our own code carry **zero** third-party
validation value, which was #448's entire point. Capturing FSL's *parameters and expected answer* is what
actually closes the gap. Happy to add an on-disk generator if you still want the artifacts.

## Hostile-input coverage

`malformed_big_endian_headers_are_typed_errors_too` re-runs the #396 B1/§P2 guards in the new byte order:
out-of-range / zero / fractional / NaN `vox_offset`, zero and negative extents, dim-product overflow,
short reads, negative and unnameable xform codes, an unsupported datatype, and a non-finite sform written
in the big-endian encoding of NaN. Stated plainly: this test **passes both before and after** — before,
only because every BE file is refused outright — so it is a guard on the new path, not a red-to-green
test. Its value is that the `.nii.gz` CRC bug was exactly a new read path that checked nothing.
