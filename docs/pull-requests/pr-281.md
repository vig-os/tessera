# [PR 281](https://github.com/vig-os/tessera/pull/281) fix(ingest): --source-label also redacts the sealed blob filename (#269)

## Why

A blob's `BlobSpec.filename` was always the input path's own filename. A vendor filename (`PATIENT_SMITH.l64`) is itself PHI, and it rode into the **sealed** manifest even when `--source-label` redacted the `ingested_from` reference — a side-channel the reviewer flagged (#269).

## What

`--source-label` now doubles as the stored `filename` (directory separators collapsed so it stays a valid single name for `extract`). Without a label, the real filename is kept (legacy behavior). Applies to both `to_blob_product` and the streaming `to_blob_product_streaming` the engine drives.

Corpus blobs use no `source_label` → **corpus unaffected** (seal is byte-identical).

## Evidence
- Extended `source_label_overrides_ingested_from_reference` to assert the sealed `BlobSpec.filename` is the label (`DUPLET-07_raw`), never the PHI-bearing `scan.l64`, on both constructors.
- Hermetic `nix flake check`: **all checks passed!**
