# [PR 1004](https://github.com/vig-os/tessera/pull/1004) feat(core): sources on Collection with supersedes/forked_from roles (ADR-0067 step 2)

Collections record the version they replace or fork from in sealed `sources`, using the shared `Source` type and `supersedes` / `forked_from` role constants. Edges reference the predecessor’s id and pin its manifest seal while leaving the lineage identity and member MMR unchanged. Empty sources are omitted, preserving existing collection bytes.

`CollectionBuilder::add_source` records edges and `with_id_inputs` accepts the caller’s declared identity. One validator enforces the collection writer rules at `CollectionBuilder::seal`, `Collection::canonical_bytes` and `Collection::to_stored`; seal recomputation goes through canonical bytes. A missing or empty fork token, or a `supersedes`/`forked_from` source without a non-empty predecessor seal pin, returns `Error::Invalid`, including after mutations to public fields. Other roles can remain reference-only. Readers keep verifying received bytes; pretty JSON remains a display API.

The CLI and ingest write paths both go through `tessera_io::stored` to `Collection::to_stored`. Tests exercise the exact seal → mutate → recompute → store bypass, independently supplied valid seals, every writer door, empty tokens, both missing version pins, and unchanged reader acceptance. SPEC §§4/8 and the Unreleased changelog document the rules.

The compatibility test freezes the existing `stored_bytes.rs::sealed_collection` fixture from pre-PR revision `4f569cf8b1d27964d9fe9b14a14a0958e5ce42f6`. Its bytes and seal were captured by compiling that revision’s actual CollectionBuilder and to_stored in an isolated checkout, copying the existing fixture constructor unchanged. The current builder and reader must reproduce that fixed historical pair; the new model and seal-vector generator do not generate the expected bytes.

Thirteen generated collection vectors extend the shared corpus to 184 cases. Four additional vectors prove that missing/empty fork tokens or absent version pins are writer rules, with unchanged native, reference and wasm reader verdicts.
