# [PR 973](https://github.com/vig-os/tessera/pull/973) fix(io)!: a fenced single writer per repository (ADR-0036 §2)

Closes #946.

The repository promised a compare-and-set ref advance (ADR-0036 §2) and did not keep it. This implements the owner's decision of 2026-11-22: **one fenced writer per repository**.

## Pre-change failure (origin/dev `3b022960`)

A probe against the old API (not committed) failed 5 of 5, `cargo nextest run -p tessera-io --test probe_946` **exit 100**:

| Probe | Result on origin/dev |
|---|---|
| 8 processes commit on one tip | `8 Ok commits, 7 lost` |
| commit built on tip A after the ref moved to B | accepted |
| torn object, then the same bytes written again | still `Integrity` (not replaced) |
| empty ref | `read_ref = Ok(Some(""))`, `gc` reclaimed 2 of 2 objects |
| `gc` over a torn tip manifest | `Ok`, reclaimed 1 |

## What changed

- **The lock.** Every write (`commit`, `set_ref`, `write_object`, `put_manifest`, `forget`, `gc`) holds one exclusive advisory lock, `std::fs::File::lock` (flock) on `<repo>/lock`, from its first check to its last write. No new dependency, so `feature-snapshots` is untouched.
- **`commit` takes the caller's parent.** `Repository::commit(lineage, expected, manifest, payloads)` checks `expected` under the lock before it stores anything.
  - A ref elsewhere is the new typed `Error::RefMoved { lineage, expected, found }`.
  - With a parent, the manifest must carry exactly one `supersedes` edge, to that parent (`Error::SupersedesMismatch`).
  - `tessera commit` passes the tip it read.
- **Durable writes.** Objects, then the ref, are each written to `<repo>/tmp/`, fsync'd, renamed into place, and their directory fsync'd. Missing shard directories are created durably. `tmp/` is cleared when the lock is taken.
- **Object repair.** A write hashes an object already at its address before it skips it, and replaces a torn one.
- **Refs.**
  - An empty or unparsable ref is the new `Error::CorruptRef`, never "no commits yet". Trailing whitespace is allowed.
  - `set_ref` returns `RefMoved` and requires a stored `blake3:<64 hex>` address.
- **`gc`.**
  - It holds the lock for its whole run.
  - A ref, a tip or an edge-reached object it cannot read, or a manifest-shaped object it refuses, aborts the run with the new `Error::GcAborted` naming it, before anything is deleted. This includes the #942 orphan-index tip.
  - It keeps the set of marked objects apart from the set of walked ones. Before, a tip whose address another version stores as a block (a blob holding the manifest's bytes) was never walked. A fresh review found this; the old `gc` had it too.
- **`tessera import`** into a lineage whose tip is another version is refused. Importing the tip's own version again moves nothing and rewrites its torn objects.
- **Refactor (first commit, a move).** The #695 durable fs steps, test seams and `Replay` model go from `write.rs` to a crate-private `durable` module, so the repository shares them. The second commit adds a kill seam (abort after the n-th step), a step watcher and a recorded `remove_file`. All three are test-only.

## Tests

Each test fails without its part of the change. For the race-sensitive ones, a mutation run confirmed this.

| Acceptance criterion | Test (`tessera-io/src/repo.rs` unless noted) |
|---|---|
| N processes, no commit lost | `concurrent_writers_lose_no_commit`: 8 child processes build on one tip and are released at once over stdin. Exactly 1 returns Ok, 7 return `RefMoved`, and the Ok one is the tip. With the CAS removed: `8 Ok, 7 lost`. |
| Finding 2 | `a_commit_built_on_a_moved_tip_is_refused` (also covers the `supersedes` mismatch) |
| Kill points | `a_crash_at_every_step_of_a_commit_leaves_the_old_or_the_new_version`: a child process is aborted after each file-system step of a commit (new block, manifest, ref). After reopening, the ref names the old or the new version and every object it reaches reads back by hash. The next writer commits and collects. |
| Durability order | `every_object_a_ref_names_is_durable_before_it` replays the steps against what a power loss can undo (#695's `Replay`). |
| Truncated object repaired | `a_torn_object_is_replaced_by_the_next_write_of_its_bytes`, plus a CLI test, `import_into_a_lineage_with_a_version_is_refused` |
| `gc` beside `commit` | `gc_running_beside_commits_keeps_every_committed_object` (committer and `gc` child processes). It passed with `gc`'s lock removed, so the deterministic proof is `a_commit_holds_the_writer_lock_at_every_step` plus `gc_holds_the_writer_lock_for_its_whole_run`. The latter fails without the lock: `the writer lock is free at GcWalk`. |
| `gc` over an unreadable manifest | `gc_over_an_unreadable_manifest_deletes_nothing_and_names_it`: the #942 orphan tip on a lineage with history, a torn tip, and a torn ancestor |
| Empty or garbage ref | `an_empty_or_garbage_ref_is_corrupt_not_absent` |
| Review regression | `gc_walks_a_tip_another_version_stores_as_a_block` deleted 2 objects under the old single set. |

No test sleeps or retries. The child processes synchronise on what they print and on stdin.

## Docs

- **ADR-0036** gets a dated amendment covering:
  - the writer model;
  - the lock's limits: advisory, local filesystem only, not valid on NFS;
  - the durability order;
  - that the object-store form maps to a conditional put (#288) and is **not built** here.
- **Book** (`versioning.md`): a new "Concurrent writers and crashes" section.
- **CHANGELOG** Unreleased: Changed (breaking `commit` API, `import`) and Fixed.

## Not in this PR

- **Refs to collections, and marking through their members** (#946 item 6): #947 and #781.
- **The `log/` cache.** It can lag or tear after a crash, and a failed append fails a commit that landed. Its behaviour is documented and filed as #971.
