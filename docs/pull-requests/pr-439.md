# [PR 439](https://github.com/vig-os/tessera/pull/439) ci(release): chain release-nix off the Release workflow via workflow_run (#438)

## Summary

- `.github/workflows/release-nix.yml` triggered on `release: types: [published]`, but cargo-dist's `release.yml` creates the GitHub Release from its `announce` job using the built-in `GITHUB_TOKEN`. GitHub silently drops workflow triggers for `GITHUB_TOKEN`-caused events, so `release-nix` never ran automatically after the v0.1.0-alpha.1 publish and had to be re-run by hand via `workflow_dispatch` (input `tag=v0.1.0-alpha.1`) to attach the wheel.
- Switch the automatic trigger to `workflow_run` chained off the `Release` workflow (that name is used by cargo-dist's `release.yml` verbatim), which DOES fire for `GITHUB_TOKEN`-driven runs. Preserve `workflow_dispatch` with its `tag` input unchanged (needed to backfill releases created before this fix and for transient-failure recovery).
- Gate the wheel job with:
  ```yaml
  if: >-
    ${{ github.event_name == 'workflow_dispatch'
        || (github.event.workflow_run.conclusion == 'success'
            && startsWith(github.event.workflow_run.head_branch, 'v')) }}
  ```
  cargo-dist's `Release` also runs in a `plan`-only mode on PRs — those never create a GitHub Release, so the `startsWith(head_branch, 'v')` guard skips them.
- Resolve the tag once into `env.TAG` (`inputs.tag` on `workflow_dispatch`, else `github.event.workflow_run.head_branch`), and reuse it for the checkout `ref:` and `gh release upload`. `workflow_run.head_branch` IS the tag when the upstream workflow ran on a tag ref (e.g. `v0.1.0-alpha.1`).

Single matrix job (`wheel`) — no need for a separate upstream gate job.
