# [PR 318](https://github.com/vig-os/tessera/pull/318) fix(ingest): make the --spec collection engine atomic (#302)

Closes #302. **Stacked on #300 (PR #317)** — branched off it; review/merge #317 first (the diff here is just the engine change).

## Problem
The engine wrote each member `.tsra` directly to `out_dir` as it went, so a failure on member N left members 0..N orphaned with **no `collection.json`** — a half-written collection indistinguishable from a complete one (surfaced during the DUPLET first-user run).

## Fix — transactional staging
Run the whole spec into a private `<out_dir>/.staging-ingest` dir, then **promote** it into `out_dir` only on full success (atomic per-file renames, same filesystem). Any failure removes the staging dir → **no orphans, no partial `collection.json`**. A leftover staging dir from a prior crashed run is cleared before starting.

- `run()` is now the transactional wrapper; the previous body is `run_into()` + `promote_staging()`.
- Test `failed_member_leaves_no_orphans_or_partial_collection`: a spec whose 2nd member references a missing dataset fails the run and leaves `out_dir` with no `.tsra`, no `collection.json`, no staging dir. Happy-path test still green.
