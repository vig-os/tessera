# [PR 735](https://github.com/vig-os/tessera/pull/735) feat(io): resolve table names through table_group in every reader

ADR-0064 PR B, **part 1 of 2** (split at the ~400-line budget: this part is 399 diff lines, 288 added and 111 removed). Readers resolve a table name through `tessera-core`'s one resolver, so `logical_table("pairs")` reads a partitioned table (`pairs/0000`, `pairs/0001`, …) as one table.

## What changes

- **`Reader::table_group(name) -> Result<TableGroup>`** (new): a thin call to `tessera_core::block::table_group` over the manifest, the same function the seal validates with (ADR-0064 §3).
- **`Reader::logical_table` / `LogicalTableView`** are built on `table_group`, and the schema is checked by `tessera_core::block::group_specs` (new, the one implementation of §2.1's schema rule; the node validation calls it too). Errors are `Error::LogicalTable { name, reason }` instead of `Error::Container` strings. The old io-side schema check is deleted.
- **`Reader::block_group`** is `#[deprecated]`, pointing to `table_group`. Its behaviour is unchanged, and it now delegates to `is_legacy_flat_member`, so the legacy flat rule has **one** implementation. The existing `container.rs` cases pass unchanged.
- **Callers (ADR-0064 §6):** `multiblock.rs` (production and its test) and `tests/block_names.rs` migrate to `table_group`. `container.rs` and `accumulate.rs` keep the legacy-rule tests under a test-local `#[allow(deprecated)]`.
- CHANGELOG (Unreleased): added `table_group`/`group_specs`; changed the `logical_table` error variants; `block_group` deprecated.

## Acceptance covered here

| Criterion | Test | Before the change |
| --- | --- | --- |
| `logical_table("pairs")` over a marked `pairs/NNNN` product returns the concatenation | `multiblock::tests::logical_table_concatenates_the_leaves_of_a_partitioned_table` | `Container("logical_table: no blocks for prefix 'pairs'")` (run output in the report) |
| An invalid node returns its typed variant from every **reader** entry point | `tests/logical_tables.rs::an_invalid_node_is_refused_with_its_variant_by_every_entry_point` | `table_group` didn't exist; `logical_table` gave a `Container` string |

Reader entry points in `tessera-io` that resolve a table name: `Reader::table_group` and `Reader::logical_table`. `Reader::block_group` is deprecated and returns no errors. CLI `read`/`sql` and Python `read_logical_table_column` call `logical_table`, so they inherit the typed errors (their own surfaces are C1/C2). Each leaf of the invalid node still reads by its full name (`read_block`, and `table_group("pairs/0000")` is `Single`).

## Note on ADR-0064 §6

§6 says the `tests/block_names.rs:415` migration asserts `Single`. That pyramid's `volume` is an **array** block. §3 defines `Single` as a table block, its rule 5 gives `NotATable { kind: "array" }`, and the merged core resolver (PR A) does the same. The test asserts `NotATable { kind: "array" }`.
