# [PR 867](https://github.com/vig-os/tessera/pull/867) feat(io): lanes on StreamWriter and WriteSession, sealed in lane order

Lanes on `StreamWriter` and `WriteSession`, sealed in lane order, as ADR-0065 §7.3 item 1 specifies.

## What changed

- **`Lane`** (`tessera_io::Lane`): `Table(role)` or `Arrays`. The derived order puts the table lanes by role name, then the arrays lane last.
  - The existing lane-less calls (`push`, `push_staged`, `push_table`, `open_table`, `append_block`, `append_staged`) use the arrays lane, so their products are unchanged.
- **`WriteSession`**
  - `append_block_on` / `append_staged_on` commit a block on a given lane.
  - The seal orders blocks by lane, then by commit order within the lane.
  - Each lane keeps its own running Merkle accumulator. The seal checks each one against the root over that lane's digest subsequence in the sealed manifest, and checks the digests in seal order against `content_hash`.
  - `running_root` is the root in seal order.
- **Journal**
  - A table-lane block's line is `{"lane": …, "block": …}`. It is parsed back before it is written, so `recover` can always read it.
  - An arrays-lane block keeps its bare line, so existing journals recover unchanged.
  - `recover` restores every block's lane. A build that predates lanes refuses a lane line as a corrupt journal rather than reordering the product.
- **`StreamWriter`**
  - `push_on` / `push_staged_on` / `push_table_on` / `open_table_on` push on a given lane.
  - Each lane has its own sequence counter. The committer's reorder buffer is keyed by `(lane, seq)`.
  - The credit window's no-stall rule is per lane: each lane's next job to commit always passes the encode gate.

Nothing from #812 (the sequenced input) is included.

**Failure without the change**, using temporary mutations (`cargo nextest run -p tessera-io --lib`):

- Seal without the lane sort, plus a no-stall rule keyed to one lane only: 4 of 7 lane tests fail (exit 100). The interleaving, two-open-tables, session lane-order and no-stall tests fail; the single-lane and corrupt-journal tests are preservation tests and pass.
- A journal that drops the lane: `recover_replays_a_multi_lane_journal…` fails (exit 100).
- No parse-back of lane lines: `a_lane_line_recover_could_not_read…` fails (exit 100).
