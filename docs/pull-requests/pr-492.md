# [PR 492](https://github.com/vig-os/tessera/pull/492) ci(nix-check): harden the per-check summary from review

Follow-up to #488 (merged) with the five review nits. **Two are correctness, three are hygiene** — worth
separating since the first two change behaviour.

## Correctness

**A failed evaluation reported `0 passed, 0 failed or not built`.** That reads like an empty-but-fine
result rather than a broken one — precisely the misleading-signal class #483 exists to remove. An empty
or `{}` evaluation now emits a loud warning naming the flake as the suspect, and still re-raises the
real exit code so the leg cannot pass on it.

**The validity probe is now unambiguously local.** Plain `nix path-info` may consult substituters, so it
can report a path as present because a *cache* has it rather than because this leg built it — turning a
failed check into a green row. `nix-store --check-validity` cannot. No extra substituter is configured
today, so this closes a **latent** trap rather than a live bug — but it would have opened silently the
day a cachix cache was added, and that is the worst kind of bug to inherit.

## Hygiene

- `matrix.arch` and the check's exit code reach the script through `env:` instead of inline `${{ }}`.
  Both are repo-controlled, so this is not a live injection — but interpolating workflow expressions
  into shell is the shape the zizmor gate exists to catch, and selective adherence is not adherence.
- **One evaluation replaces eighteen:** `builtins.mapAttrs (_: c: c.outPath)` yields every check's name
  and path together, instead of `attrNames` plus one `outPath` eval per check. Beyond being faster, a
  name and its path can no longer disagree — they come from the same attrset.
- The file header now prints the same flags CI runs (`nix flake check -L --keep-going --fallback`). The
  header's whole argument is that one command runs in both places; printing a different one undercut it.

## Verification

All three paths exercised locally rather than assumed:

| path | result |
|---|---|
| single eval + `jq` parse | 17 name/path pairs |
| `--check-validity` on a **built** check | reads as passed |
| `--check-validity` on an **unbuilt** check | reads as failed |
| empty-eval guard (bad system attr) | fires, warns, re-raises rc |

The built/unbuilt pair matters most: a summary that reported everything as failed would be worse than
no summary, so both directions were checked rather than just the happy path.

## Unchanged, deliberately

Still no `--max-jobs`. The sampler's first numbers (from #488's own green legs) show peak memory 10.2 GB
(x86_64) and 11.6 GB (aarch64) against 16 GB, with **74–92 GB of disk free throughout** — so disk is
definitively not the constraint, and memory has 27–36% headroom *on legs that passed*. That is a
baseline, not a measurement of a failure. Capping parallelism costs wall-clock against a 90-minute
budget where legs already take 43–57 minutes, so it waits for an actual eviction sample. The sampler is
on every leg now, so the next one arrives with the deciding number.
