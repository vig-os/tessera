# [PR 879](https://github.com/vig-os/tessera/pull/879) fix(core,io): refuse a block name listed twice in one product

Closes #734

## The bypass

A manifest listing block `data` twice, the second entry carrying `blake3("NOT THE BYTES")`, re-sealed over that list,
verified as `OK … verified (2 blocks)`. `stream_block` resolves a name with `.find` (first match) and `check_members`
collapses the listed names into a set, so the second digest was never checked against any bytes.

## The rule (ADR-0063 amendment §2a, SPEC §5 and §7)

Block names are unique within a product, compared by **exact byte equality** (the grammar makes every name ASCII).
`Data` and `data` stay distinct: case-fold collisions are #690's concern, and this PR does not widen into it.

## Where it is enforced: one check, one typed error

`tessera_core::block::check_unique_names` returns `Error::DuplicateBlockName { name }` (rustdoc names every door).

- **Readers**, before any digest lookup: `Manifest::from_json_verified` (so `Reader::open` local and cloud, every
  read, `verify`, both payload verifiers, the repository, `pack_dir`) and `Manifest::verify` (wasm, Python
  `verify`). `check_members` runs it too, as defence in depth, next to the set that would hide a repeat.
- **Writers**: `ProductBuilder::seal`, and so everything that seals through it (a write session's seal, the
  `StreamWriter` and its lanes, `tessera commit --add-block`, ingest, the Python `Builder`); a write session's
  append; `pack` / `pack_streaming` / `pack_dir` through one `check_packable`; the repository's `commit` and
  `put_manifest`, before any object is stored or a ref moves (`commit` resolves payloads through a name-keyed map
  built after the check, not a first-match `.find`). The session append and
  `commit --add-block` had their own `Error::Invalid` checks; those are gone, not duplicated.
- **Reference reader**: refuses the repeat by name (`duplicate_block_names`) in `verify_tsra` and
  `manifest_verdict`, before reading any payload, not by happening to meet a digest mismatch.

Two distinct names may share one digest: each name maps to its own `blocks/<name>` member, and each member is
checked (stated in ADR-0063 §2a and SPEC §5).

Rebased onto #875 and #788. #788's partition naming (`<table>/NNNN`) and `TableSpec.edition` don't touch names. Because its `from_json_verified` no longer goes through `verify()`, the check is in both.
`seal-cases.json` gains `recon_int16/block-listed-twice` → `refused`, which both readers reach.
