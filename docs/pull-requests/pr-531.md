# [PR 531](https://github.com/vig-os/tessera/pull/531) docs(adr): ADR-0059 — the chunk-index statistics schema (#522 spike)

**Design-only.** No sealed-layout code is written until the owner ratifies. Every size and cost number
was measured in the nix devShell on the 127,664,128-voxel `int16` volume #347 is about; the overflow
bounds are computed.

Refs #522 · gates #347 P1 · consumes #523 · carries #526 as a separable section

## The decision, in one table

| | | |
|---|---|---|
| **M1** | Bind the index to its block's **content digest** | **mandatory** |
| **M2** | Fail closed on accumulator overflow, never wrap (#523) | **mandatory** |
| **M3** | Per-chunk digest over **native element bytes**, not the `i64` gather buffer | **mandatory** |
| S1 | Keep `count / min / max / sum / sum_sq` | unchanged |
| S2 | Add `nan / pos_inf / neg_inf / masked` counts | recommended |
| S3 | Add **one block-level histogram**, integer counts | recommended |
| S4 | Do **not** add `sum³` / `sum⁴` | recommended against |
| S5 | Derive quantiles, skew, kurtosis, fences from S3 at read time | recommended |
| **C1** | Hash-algorithm agility (#526) | **separable — include or exclude on its own** |

## Determinism decides this, not accuracy

`f64` addition is order-independent only *by convention* (it needs a fixed fold order). Integer
addition is order-independent *by algebra* — any worker count, any merge order, identical bytes.
**#472 already found a cross-arch seal divergence caused by a persisted float NaN.**

So: **the `.cidx` stores integers only**, and every real-valued statistic is derived at read time.
That rejects **t-digest** (order-dependent merge) and **KLL** (randomised) before accuracy enters the
discussion — under either, sealed bytes would depend on how many workers happened to run.

## `sum³`/`sum⁴` do not fit, and no width fixes them

Largest sample count before `Σxᵖ` overflows:

| dtype | `Σx²` | `Σx³` | `Σx⁴` |
|---|---|---|---|
| `int16` | 1.6e29 | 4.8e24 | 1.5e20 |
| `int32` | 3.7e19 | 1.7e10 | **7** |
| `int64` | **1** | **0** | **0** |

`int32` kurtosis overflows `i128` at the **8th sample**. Widening to `i256` does not rescue it —
`int64 Σx⁴` still overflows at n=7. A statistic that silently corrupts at n=8 is #523 with a new name.

## The histogram subsumes all of it

Quantiles, skewness, kurtosis, Tukey and k·σ fences, mode — all derived from one integer count vector,
no overflow risk, decode-free, **zero extra bytes beyond the histogram itself**.

Placement is measured, against a baseline of 85,373 B / 512 chunks = **167 B per entry**:

| placement | bins | resulting `.cidx` | vs today | % of a 151 MiB file |
|---|---|---|---|---|
| per chunk | 256 | 382 KiB | 4.6× | 0.25 % |
| per chunk | 1024 | 1206 KiB | 14.5× | 0.78 % |
| **block level** | **4096** | **94 KiB** | **1.13×** | **0.061 %** |

Per-chunk buys only sub-region histograms, which nothing asks for; pruning is already exact from
per-chunk `min`/`max`.

**And for ≤16-bit integers the quantiles are exact, not estimated.** The measured CT recon spans 4096
levels with 4096 distinct values present — one bin per value is a *complete* description of the
distribution. "Approximate quantiles" is a problem we mostly do not have.

## Write cost, measured

| phase | time | vs encode |
|---|---|---|
| `array_block` (pcodec encode) | 280 ms | 1.00× |
| `array_chunk_index` (today's fold) | 1459 ms | **5.21×** |
| histogram fold (1024 bins) | 290 ms | 1.03× |

The histogram adds ~20 % to the index build. **The surprise is the second row**: the existing stats
fold already costs 5.2× the encode (odometer walk + a `Vec<i64>` copy + blake3 per chunk). That, not
the histogram, is the write-path cost worth watching.

## M1 — why digest-binding is mandatory *in this event*

The `.cidx` records the **name** of the block it indexes, never its digest, so it cannot be proven to
describe that block's current bytes:

```
tessera commit --remove-block volume --add-block other.tsra:volume
```

left `volume.cidx` in place and `stats` served the **old** volume's numbers for the **new** block,
labelled `exact: true`. #524 closed that path and added dtype/shape guards — but those are guards
around a missing binding. `indexed_digest` closes the class (stale, swapped, regenerated,
copied-from-another-product) for ~80 bytes. It must land here: after default-on there will be indexes
in the wild that cannot be validated retroactively.

## M3 — the per-chunk digest, added in the ratification round

`array_chunk_index` hashes a **derived** buffer today: every element widened to `i64` and written
little-endian, so an `int16` chunk is hashed as 8 bytes per voxel — 4× the necessary work, over a
representation that is not the data's own.

**Now or never.** The digest feeds the index root, so redefining it moves every `.cidx`. That is free
today (no product carries one) and, after this event's default-on seal, a second corpus regeneration
*plus* a break for every index already written.

Pinned precisely: blake3 over the chunk's elements in C-order, last axis fastest, edge chunks clipped
(unchanged — the existing odometer order), each element in a fixed little-endian width per dtype, with
`bool` as `0x00`/`0x01` rather than the host's representation. **Little-endian is fixed by the format,
not the host**: a big-endian machine byte-swaps into the hasher rather than `memcpy`-ing, which is the
only way the digest is a function of the data and not the architecture. Proven cross-arch (CI runs
x86_64 and aarch64) and cross-profile, alongside worker-count invariance.

## C1 — hash agility (#526), separable

blake3 stays the default identity hash. Optional top-level sha256 fixity from the **same single seal
pass**, plus a `hash_alg` label.

Spelled out for the decision: what the sha256 covers must be reproducible **from the file alone** (a
file cannot hash itself, so "sha256 of the product" is circular); **per-block co-digests are what
BagIt actually consumes**, which makes #527 an export rather than a re-hash; and it must stay
**additive** — folding sha256 into `content_hash` would move every existing id, corpus golden and
published artifact.

| | throughput | 151 MiB product |
|---|---|---|
| blake3 alone | 2930 MB/s | 54 ms |
| sha256 alone | 1305 MB/s | 121 ms |
| dual, one thread | ~900 MB/s | ~176 ms |
| dual, threaded | ~1305 MB/s | ~121 ms |

3.2× serial / 2.25× threaded. `sha2` is **already in the dependency graph**, so no new dependency.
Recommended default: **off**, on request or implied by BagIt/OCFL export.

`sha2` becomes a direct dependency, so it **joins Gate B's crate list** (a 12th snapshot) in the same
commit — ADR-0057 §5 defines that list as everything that can move sealed bytes, and a co-digest in the
manifest qualifies whenever the flag is on. Declared here rather than discovered as a ~60-minute CI
failure, which is how the same omission bit #503.

## Explicitly not in the event

Per-chunk histograms · `sum³`/`sum⁴` · t-digest/KLL · float chunk indexes (deferred behind `kind`) ·
folding sha256 into `content_hash`.

## Landing plan

One PR, one corpus regeneration, one changelog entry — §11 of the ADR.
