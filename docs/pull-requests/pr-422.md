# [PR 422](https://github.com/vig-os/tessera/pull/422) fix(py): decode str and b1 table columns in the ergonomic reads

Closes #421.

`Reader.table_dict` / `table_arrow` / `table` crashed on any table block containing a `str` column — `_ndarray` assumed every FFI code is a numpy dtype and called `np.frombuffer(buf, "<str")`. `b1` was adjacent: `"<b1"` happens to parse as int8, so bools silently decoded as integers rather than erroring.

The native side was already correct (`read_table` returns the documented `[u32 LE len | bytes]*` framing with code `"str"`); only the wrapper couldn't get the values back out. Write side unaffected.

Choices:
- **`str` → object array**, so values round-trip exactly — a fixed-width `U` dtype would silently pad/truncate.
- **`b1` → `bool_`** via u1 cast, fixing the silent wrong-dtype case.
- `shape` is honoured for both, matching the numeric path.

The smoke test gains a str/b1 round-trip (including the empty-string edge) — **verified failing with the exact #421 TypeError on the unpatched wrapper, and passing with the patch**, both against the same native binary, so the test pins the wrapper specifically.

Found mid-migration in [private-repo] (ADR-096): 65 of our 143 physics tables carry a string column, and our write→read-back fidelity gate hit this on the first table it checked.

May interact trivially with #420 (both touch tessera-py tests); happy to rebase whichever lands second.
