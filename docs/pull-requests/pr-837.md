# [PR 837](https://github.com/vig-os/tessera/pull/837) ci(dist): pin the aarch64-apple-darwin build host to macos-15

Closes #790

## Root cause

The aarch64 leg's runner label comes from `dist plan`. Both release.yml's build job and the `macOS build` gate run
on `matrix.runner` from that plan. The repo pinned no runner, so cargo-dist 0.32.0's built-in default applied:
`aarch64-apple-darwin` runs on `macos-14`. In the failing run, the `dist plan (darwin legs)` log shows
`"runner": "macos-14"`, and the job's `labels` field is `["macos-14"]`.

GitHub retired the macOS 14 image for GitHub Actions arm64 on **2026-11-02**. See the
[GitHub changelog, 2026-10-01: "macOS 14 runner image retirement"](https://github.blog/changelog/2026-10-01-github-actions-macos-14-runner-image-retirement/),
which covers `macos-14`, `macos-14-large` and `macos-14-xlarge`, and
[actions/runner-images#13518](https://github.com/actions/runner-images/issues/13518), which gives "GitHub Actions
and ADO arm64 on November 2". `macos-14-arm64-us-default` is the internal image configuration behind the plain
`macos-14` label. It is not a larger-runner or region setting of ours, and the label itself is what was retired.
The changelog recommends `macos-15`, `macos-latest` (macos-26) or the matching `-xlarge` labels as replacements.

Upstream fixed the default in cargo-dist **0.34.0**
([axodotdev/cargo-dist#2555](https://github.com/axodotdev/cargo-dist/pull/2555), "default Apple Silicon builds to
macos-15").

## Change

`dist-workspace.toml` gets a `[dist.github-custom-runners]` table with `aarch64-apple-darwin = "macos-15"`. It is a
named version rather than `macos-latest`, so a future image move stays a reviewed edit. It is also the same value
dist 0.34 now defaults to, so the pin stays correct after a dist bump. `x86_64-apple-darwin` keeps dist's
`macos-15-intel` default. `[dist.github-action-commits]` is untouched.

`release.yml` does **not** change, because it reads runners from the plan's matrix at run time. With the pinned
dist 0.32.0, inside `nix develop`:

- `dist generate --mode ci` exits 0 with an empty `git diff`.
- `dist plan --output-format=json` exits 0 and emits:
  - `aarch64-apple-darwin` on `macos-15` (was `macos-14`)
  - `aarch64-unknown-linux-gnu` on `ubuntu-22.04-arm`
  - `x86_64-apple-darwin` on `macos-15-intel`
  - `x86_64-unknown-linux-gnu` on `ubuntu-22.04`

Other workflows: none hard-codes `macos-14`. `git grep` finds only "macOS 14.0" as an example OS in the two
issue templates. ci.yml, codeql.yml and nix-check.yml have no macOS jobs.

**Consumer impact (minimum macOS), a pre-existing defect tracked in #838:** no darwin leg sets
`MACOSX_DEPLOYMENT_TARGET`. cc 1.2.65 then falls back to the build host's SDK version (`xcrun --show-sdk-version`),
not rustc's 11.0, and cmake 0.1.58 forwards that into the vendored HDF5's `CMAKE_C_FLAGS`. So the HDF5 objects
follow the runner image's default Xcode, and the host change likely moves them from about 14.x to about 15.x. This
is unverified: no `minos` inspection yet, and no linker warning in the logs. `x86_64-apple-darwin` has been in
the same position on `macos-15-intel` since dist 0.30.1. The runner pin is still the right fix for #790, because
`macos-14` arm64 no longer exists. Holding a declared floor is #838's job: set the env var and assert `minos` in
`macos-build.yml`.
