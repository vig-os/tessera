# [PR 465](https://github.com/vig-os/tessera/pull/465) fix(io): close the encode-trace callsite race under CPU contention

## What

`array::tests::encode_emits_a_structured_compression_trace` failed in a full-suite run and
passed alone. Fixed properly — no `#[ignore]`, production `debug!` call sites untouched.

## The diagnosis in the issue was incomplete

It does **not** fail deterministically. On an 88-core host it never fails: 0/40 full-suite
release runs, 0/25 single-threaded. It needs CPU contention:

```
taskset -c 0-3 <test-bin> --test-threads=8     # ~20/25 runs fail
```

reproducing the reported `missing encode event: ` with an empty log. That is why CI's small
runners see it. Thread count matters non-monotonically (2 → 5/25, 3 → 0/25, 4 → 18/25, 8 → 20/25).

Two theories from the issue were tested and falsified:

- *"another test registers the callsite against `NoSubscriber` before this test runs"* — a probe
  that hits the callsite unsubscribed and then captures on the **same** thread passes, because
  creating a `Dispatch` rebuilds the interest cache.
- *"the `write.rs` INFO-level trace test interferes"* — skipping that test still fails 19/25.

Instrumenting a real failing run was decisive. Inside the closure at failure time:

```
level_filter_current=LevelFilter::DEBUG  event_enabled=true  dispatch_is_noop=false
buflen_in_closure=141
```

The subscriber is live, the level permits the event, and marker events emitted in the same
closure *are* captured — only the `encoded array block` callsite is silent. `event_enabled!` and
those markers are separate callsites with their own cached verdicts, so they report on
themselves, not on the one that matters.

## Root cause

`tracing` caches each callsite's `Interest` process-wide on first use. How that verdict is
computed depends on how many dispatchers are registered — `tracing-core` 0.1.36, `callsite.rs`:

- **at most one registered** (`Dispatchers::has_just_one`): `Rebuilder::JustOne` asks
  `dispatcher::get_default` — the **registering thread's own** current default;
- **two or more**: every live registered dispatcher is asked, and the verdicts fold with
  `Interest::and`, which yields `sometimes` whenever two disagree.

So the flake is: the only dispatcher ever registered is one test's scoped subscriber, so
`has_just_one` stays true; an unsubscribed thread reaches the callsite first; its default is
`NoSubscriber`, which answers `Interest::never`; and that is cached for the whole process. It is a
race against every other `encode` caller in the binary.

## Fix

`test_support::init()` installs a global default that records nothing and is **never dropped**, so
it stays permanently registered. That is what makes it work:

- with a scoped subscriber also active there are **two** dispatchers, `has_just_one` is false, and
  the scoped subscriber is therefore consulted at registration instead of being invisible;
- with no scoped subscriber, `get_default` returns the floor rather than `NoSubscriber`, so the
  cached verdict is still not `never`.

`Interest::sometimes` rather than `always` is deliberate: `always` would let events bypass the
current subscriber's `enabled()` and defeat each test's own level filter. Threads with no capturing
subscriber still emit nothing, because `InterestFloor::enabled()` is `false`.

## The regression test lives in its own binary, on purpose

Interest is cached **once per process**, so inside the lib's unit-test binary an earlier `encode`
caller registers the callsite first and the assertion passes whether or not the bug is present —
a false green. Verified: with the fix removed, the whole `--lib` suite is green at
`--test-threads=1`. A test that only fails in isolation is not a regression test.

So it is `tests/encode_trace_interest.rs`: one test per process, so it takes the first hit and the
interleaving it forces is the only one possible.

That split the setup — the floor is in `test_support` (public, `doc(hidden)`, solely so a separate
test binary can reach it), while `capture()` stays `#[cfg(test)]` because `tracing-subscriber` is a
dev-dependency. The test binary carries its own small writer for the same reason and says so.

## No test can bypass the fix by accident

`CaptureWriter` is private to `test_trace`, so `capture()` — which calls `init()` — is the only way
to capture events in-crate. Enforced by construction rather than by comment. This also removed the
near-identical `CapWriter`/`BufWriter` that `array.rs` and `write.rs` had each grown a copy of.

## Verification

Release, in a private target dir, after `cargo clean -p tessera-io` (a shared target dir can serve
a stale rlib and give a false pass, so every number here was re-taken clean):

| check | result |
|---|---|
| `tests/encode_trace_interest.rs` with the floor disabled | **FAILS** |
| same test with the fix | passes, 0/25 flaky |
| `taskset -c 0-3 <lib-bin> --test-threads=8` | **0/30** failures (was ~20/25) |
| `cargo test -p tessera-io` | 147 lib + 3 conformance + 1 regression + 6 |

Commits are ordered so the repro is reviewable on its own: the failing test, then the fix, then the
review corrections (accurate mechanism + moving the test out of the lib binary).

Closes #356
