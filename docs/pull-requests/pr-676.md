# [PR 676](https://github.com/vig-os/tessera/pull/676) fix(deps): clear four new RustSec advisories so cargo-deny passes

## Description

Makes `cargo deny check` clean on `dev` again. Four new RustSec advisories against crates already in
`tessera/Cargo.lock` were failing every PR's `Lint & Format` job at the `cargo-deny` hook (#664). This unblocks
#660, #661 and #662.

## Type of Change

- [x] `fix` -- Bug fix
- [x] `build` -- Build system or dependency changes

## Changes Made

| Advisory | Crate | Kind | Action |
|---|---|---|---|
| RUSTSEC-2026-0382 | `rustls-webpki` | vulnerability | 0.103.15 → **0.103.16** (first patched 0.103) |
| RUSTSEC-2026-0383 | `webpki-root-certs` | vulnerability | 1.0.8 → **1.0.10** (first patched, 1.0.9 isn't) |
| RUSTSEC-2026-0386 | `tokio` | unsound | 1.52.3 → **1.53.3** (smallest fixed release, 1.52.4 isn't) |
| RUSTSEC-2026-0374 | `basic-toml` 0.1.10 | unmaintained, no fix | narrow, dated `ignore` in `tessera/deny.toml`; removal tracked in #665 |

- **basic-toml:** it comes in through `i18n-config` 0.4.8, the latest release, which only the `i18n-embed-fl` and
  `i18n-embed-impl` proc-macros of `age` 0.11 use. At compile time they parse `age`'s own bundled `i18n.toml`.
  It isn't linked into any binary and never sees runtime input. `age` 0.12 needs the same `i18n-config ^0.4.7`,
  so a bump can't remove it. Upstream kellpossible/cargo-i18n#176 (merged 2026-09-26, unreleased) swaps it back
  to `toml`. #665 drops the ignore once that ships.
- **Minimal lockfile diff:** the diff is just these three version/checksum pairs.
  `cargo update -p tokio --precise 1.53.3` also re-picks about 14 unrelated `windows-sys` edges
  (0.61 → 0.60/0.52, all inside their ranges). To avoid that, tokio's lock entry was set directly. Its dependency
  set and requirements are identical to 1.52.3's. `cargo metadata --locked` and `cargo fetch --locked` accept the
  lock unchanged, and the registry checksum is verified on fetch.
- **Seal path / Gate B:** none of the four crates is on the seal path. `scripts/feature-snapshots.sh` regenerates
  identical to `tessera/tests/feature-snapshots`.
