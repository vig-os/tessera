# [PR 539](https://github.com/vig-os/tessera/pull/539) feat(core,io): chunk-index statistics schema v2 (ADR-0059, C1-C3 of 7)

> **DRAFT — the format event has NOT happened yet.** This is C1–C3 of ADR-0059's seven-commit
> sequence. **No sealed bytes have moved**: no product in the corpus carries a `.cidx`, and the
> sidecar is still opt-in. C4 is the commit that flips default-on and regenerates the corpus, and it
> is deliberately held pending review of the frozen-format pieces below.

Implements [ADR-0059](https://github.com/vig-os/tessera/blob/dev/docs/adr/0059-chunk-index-statistics-schema.md)
(ratified). Refs #522 · gates #347 P1 · closes #523's write path.

## Why it is one PR

Attaching a `.cidx` adds a block digest, and `content_hash = merkle_root(&digests)` over every block
ref (`product.rs:177`). So default-on **and** any later field change each move `content_hash` and
`manifest_hash`. Both are free today and each one after the first is a separate corpus regeneration,
so everything that wants to be in `ChunkStats` lands together: **one PR, one corpus regeneration, one
changelog entry.**

## The three commits so far

**C1 `fix(core,io)` — fail closed when statistics cannot be exact** (M2, #523 write path).
`from_values` returns `Option`, `push` returns a `#[must_use] bool`, and the builders return
`Result<Option<ChunkIndex>>` so a *fault* and *"not indexable"* stop being the same outcome. That type
change immediately earned its keep: two existing tests asserted `is_err()` for a float array and a
non-integer stat column, which were never errors — leaving them as errors would have made C4's
default-on flip **fail to seal every float recon**.

It also exposed a second, quieter instance of the same bug: `TableStreamWriter::flush` folded the live
integrity MMR with `.unwrap_or_else(ChunkStats::identity)`, recording `count: 0` for a *non-empty*
group whenever the stat column was not exactly foldable. The live root is built to reconcile with the
sealed batch index, so that false statistic would have survived the seal.

**C2 `feat(core,io)` — schema v2** (`chunk_index@1` → `@2`). The S2 counters
(`masked`/`nan`/`pos_inf`/`neg_inf`), the `Histogram` type, and `indexed_digest` (M1). Every new field
is `skip_serializing_if = "Option::is_none"`, so **absent reads as absent, never zero** — "no
histogram" and "an all-zero histogram" must not be confusable, and nor must "no nulls" and "nobody
counted the nulls".

`masked` recovers information that is currently **lost**: `as_i64` drops nulls deliberately (a chunk's
min/max must describe the values actually present, or pruning would exclude chunks that do contain
matches), so a 100-row group with 40 nulls was indistinguishable from a 60-row group.

Wiring it **uncovered a panic on `dev`**: `table_chunk_index` sliced the already-null-filtered vector
by ROW indices, so a nullable column ran off the end — a 4-row column with 2 nulls panicked with
`range end index 4 out of range for slice of length 2`. Reproduced before fixing; per-group filtering
is both the fix and what makes `masked` computable.

**M3** lands here too: the per-chunk digest is now over **native little-endian element bytes**, not an
`i64`-widened buffer (an `int16` chunk was hashed as 8 bytes per voxel). This also resolves a
disagreement nobody had noticed — the *table* builder already hashed native per-column LE bytes while
the array builder hashed `i64`, so the two meant different things by "a chunk digest".

**C3 `feat(io)` — the histogram, and the determinism gate.** The histogram is pass 2 of 2 and cheap:
pass 1 is the existing chunk loop whose aggregate fixes the edges, and pass 2 is a linear scan over
the values `as_i64` already materialised, because integer counts commute and so need no odometer.
`bins = span` when the span is ≤ 4096, else 4096 linear; `exact` is computed, never asserted.

## The determinism proof

M3's digest cannot be revised after C4, so it is pinned on three axes and a literal is trusted for
none of them:

| axis | how |
|---|---|
| **the encoding** | re-derived inside the test from the ADR's definition and hashed; plus an assertion that it is *not* the old `i64`-widened buffer |
| **worker count** | the same data sealed through `StreamWriter` at **1, 4 and 16** threads → byte-identical `.cidx` **and** `content_hash` |
| **profile + arch** | wired into `seal-profile-determinism`, which runs the suite under dev **and** release; CI runs that check on x86_64 **and** aarch64 |

A literal alone would still pass if the implementation and the literal were updated together in the
wrong direction, which is why the derivation test exists. And the pinned digest was cross-checked
**outside Rust entirely**: the same byte sequence generated in Python and hashed with `b3sum` gives
`57df27cd…`, matching the builder, while the `i64`-widened buffer gives `52403b87…`. That difference
is the evidence M3 changed *what is hashed* rather than merely being stable.

Confirmed from the nix build log rather than assumed:

```
[ADR-0059] the chunk-index determinism gate under both profiles
+++ command cargo test -q -p tessera-io --test chunk_index_determinism
running 4 tests ... ok. 4 passed
+++ command cargo test -q --release -p tessera-io --test chunk_index_determinism
running 4 tests ... ok. 4 passed
```

**A trap worth knowing:** the new test file was invisible to every nix check until it was `git add`ed,
because a flake copies only git-**tracked** files. `cargo test` found it locally while the gate
reported `no test target named chunk_index_determinism` — the same shape as the trycmd cases that once
ran **zero** times in CI. Running the real gate caught it; reasoning about crane's source filter would
not have.
