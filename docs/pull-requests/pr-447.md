# [PR 447](https://github.com/vig-os/tessera/pull/447) fix(ingest): close the five NIfTI decoder bugs — panic on malformed vox_offset, .nii.gz, qform, hard-coded space, silent 4-D truncation

Fixes all five NIfTI decoder bugs in #396 — the P0s (B1 panic, B5 silent truncation, B3 qform) and
the P1s (B4 hard-coded space, B2 `.nii.gz`) — plus the §P2 bounds audit. Two commits: the five
regression tests first (verified failing on `origin/dev`), then the fix.

## What each bug was, and what it is now

| | Bug on `dev` | Now |
|---|---|---|
| **B1** | `vox_offset` used as a slice start *before* any bounds check → `1e9` **panicked** ("range start index out of range"); the length check inside `read_vec!` came after the slice, so it never ran | Every header-derived index checked before use → `Error::Invalid`. FEATURE-MATRIX §A's "never panic" holds |
| **B2** | `.nii.gz` failed with the misleading `sizeof_hdr != 348 (not NIfTI-1 …)` | Gzip magic sniffed (not the filename) and decompressed transparently, bounded by the header's own declared size |
| **B3** | `sform_code == 0, qform_code > 0` → `world_frame: None`: Tessera declared an array to be in index space when it demonstrably was not | Precedence sform → qform → none, `nifti_quatern_to_mat44` verbatim incl. the `pixdim[0]` qfac flip |
| **B4** | every volume stamped `"scanner"` | `1/2/3/4/5 → scanner / aligned / atlas:talairach / atlas:mni152 / atlas:other`, all inside the ADR-0032 pinned frame vocabulary |
| **B5** | a 200-frame series ingested volume 0 and **silently dropped 199** — sealed and verified with 99.5 % of the data gone | `[t,z,y,x]` (5-D `[u,t,z,y,x]`) with every volume, `t` carrying ADR-0032 `time_regular` |

## Acceptance criteria

- [x] Out-of-range `vox_offset` → `Error::Invalid`, no panic — asserted, and the error names the field.
- [x] A 4-D NIfTI ingests **all** volumes; the test asserts volume 199 is present byte-for-byte.
- [x] A qform-only file (`sform_code = 0, qform_code = 1`) produces a `world_frame` matching the
      quaternion, against a hand-derived voxel→world point (90° about RAS x, pixdim (2,3,4),
      qoffset (10,20,30) → voxel [1,1,1] = (−12,−16,33) LPS; qfac −1 → (−12,−24,33)).
- [x] `sform_code = 4` → `atlas:mni152`, not `"scanner"`.
- [x] `.nii.gz` seals to the same `content_hash` as its gunzipped twin (and a gz declaring ~17 GiB is
      refused before a byte of payload is expanded).
- [x] `reads_nifti_volume_with_lps_world_frame_and_builds_recon` passes **unchanged** (the `Synth`
      fixture builder's defaults reproduce the original fixture byte-for-byte).

## Hash safety — verified, not assumed

The issue flagged B3/B4 as hash-moving for affected inputs. Checked rather than trusted:

- **No NIfTI product is in the committed conformance corpus** (`tessera/corpus/`), so no golden moves.
- **`scripts/feature-snapshots.sh` output is byte-identical** — `flate2` touches none of the 11
  seal-path crates.
- **Everything that already worked is hash-neutral by construction:** the declared rank keeps a higher
  NIfTI axis only while it has >1 element, so a `ndim = 4, dim[4] = 1` file stays the 3-D volume it is
  (tested); `axis_names(3)` is byte-identical to `default_axes(3)`; `geometry_source` is reported on the
  decode and traced, deliberately **not** a new manifest field (which would move the `content_hash` of
  every NIfTI product, including the ones whose geometry did not change).
- B3/B4 **do** move `manifest_hash` for the inputs they fix — a qform-only file gains the frame it should
  always have had, a non-scanner file gets its real frame name. That is the agreed change in #396.

## Decisions a reviewer should look at

1. **An unknown xform code is an error, not a guess.** NIfTI-1 defines codes 1–4 (+5 template-other);
   guessing `"scanner"` over anything else is precisely B4. `"unknown"` was rejected as an alternative
   because it is not in `CANONICAL_FRAMES`.
2. **An sform whose *code* is unnameable errors even when a valid qform exists.** The file names the
   sform as primary; quietly substituting a differently-coded qform is the same silent-substitution sin
   in reverse. A *degenerate* sform (singular affine) **does** fall through — that is uninterpretable
   geometry, not an uninterpretable label.
3. **The 4-D `world_frame` addresses the trailing three axes.** The 3×4 affine on a rank-4 array follows
   the existing `[3,z,y,x]` deformation-field convention (ADR-0030 §5, `deformation_displacement`), not a
   new one.
4. **A DWI stack gets no time axis.** `dim[4]` counts gradient directions; such files leave `pixdim[4]` /
   the `xyzt_units` time code unset, so that axis stays a bare index rather than being given a guessed
   cadence. Reuses `Referenced::time_regular` verbatim — no axis convention invented here.
5. **The `.nii.gz` bomb guard is the header's own claim.** Pass 1 expands only the 352-byte header; pass 2
   is capped at `vox_offset + voxel bytes`, so a hostile file can never claim more than a legitimate one
   of the same declared shape, under an 8 GiB in-memory ceiling (tested: a gz declaring ~17 GiB is
   refused before a byte of payload is expanded).

## Scope

`read_nifti` is now `parse_header` → `read_voxels` — that split is what lets the gz path bound its own
decompression with the parsed header. `dtype_width` is the single bytes-per-voxel table (the decode arms
take their stride from it, so a width can never disagree with the type reading it), guarded by a new
test that exercises all six datatype codes at their real widths.

Docs: FEATURE-MATRIX's NIfTI row now states what the decoder actually does and names all six gates;
ADR-0056 §11's four gaps are marked resolved **in place**, because the reasoning is what records *why*
each was a bug. `docs/MIGRATION.md` already advertised `.nii.gz` — that line is now true.

**Filed, not smuggled in:** #446 — the `xyzt_units` *spatial* half is still ignored, so a micron- or
metre-unit affine is stamped `"mm"` (a 1000× geometry error, routine in preclinical/µCT). Same class as
B4, but it moves hashes for those inputs, which is outside #396's agreed set.

**Known non-goals, still refused — but now named.** A third commit (`9deeee1`) replaces the catch-all
`sizeof_hdr != 348 (not NIfTI-1, or big-endian — unsupported)`, which blamed the file, with a message
that says what was actually found: `big-endian NIfTI-1 is not supported (sizeof_hdr is 348
byte-swapped)` or `this is NIfTI-2 (sizeof_hdr = 540), not NIfTI-1`. Message-only — both are still
`Error::Invalid`. Same misleading-error complaint as B2, and both cases are measured rather than
hypothetical: of the six `.nii`/`.nii.gz` files in nibabel's test data, **three are big-endian** and one
is a NIfTI-2 CIFTI. Support for big-endian is **#449** (and belongs there: it must normalise byte order
at the door so a BE and an LE file of the same volume seal to the same `content_hash`). `.hdr`/`.img`
pairs stay out — two files, so they interact with the collection model, not the decoder.

## Review round (independent fresh-context review — one BLOCKER, fixed)

**BLOCKER: a corrupt `.nii.gz` sealed as if it were sound.** flate2 verifies a gzip member's
CRC32/ISIZE trailer only when the deflate stream reaches EOF, so reading just the bytes the header asks
for (`take(need)`) never touched the trailer. Measured on the previous commit:

```text
flipped CRC byte    take=Ok(368)   drained=Err("corrupt gzip stream ... matching checksum")
flipped ISIZE byte  take=Ok(368)   drained=Err("corrupt gzip stream ... matching checksum")
trailing garbage    take=Ok(368)   drained=Err("unexpected end of file")
one stray byte      take=Ok(368)   drained=Err("unexpected end of file")
```

A damaged `.nii.gz` whose payload still inflated was therefore sealed with a valid `content_hash` —
**worse than gunzip-then-ingest**, and the trailer is the *only* integrity check a NIfTI source carries
(a raw `.nii` has none). Fixed by draining the remainder into `io::sink()` to force the check; the drain
discards as it goes, so memory stays bounded by the declared size while the total stays capped. The
header peek keeps a separate non-verifying reader (its only job is to learn the declared size) and the
final header is re-parsed from the bytes that *were* verified.

**One deliberate deviation from the review note:** concatenated members are **accepted**, not rejected.
RFC 1952 defines a gzip file as a *series* of members and `gunzip` concatenates them, so rejecting would
refuse files other tools legitimately produce; every member's trailer is still verified, and content past
the declared volume is ignored exactly as trailing bytes are in a plain `.nii` (extensions). Pinned by a
test so it reads as a decision rather than an accident. Container-level trailing *garbage* — including a
single stray byte — **is** rejected.

The nits, all done in the same pass:

| Nit | Resolution |
|---|---|
| Cap names the ratio, not the claim | Renamed `MAX_GUNZIP_BYTES` → **`MAX_DECLARED_BYTES`**, documented that uint8→uint16 widening means a file at the ceiling peaks at a multiple of it |
| `is_nondegenerate` misses NaN and parallel columns | Local `affine_is_finite` + `affine_conditioning` (`|det| / Π‖col‖`, **scale-invariant** so a micron-spacing affine isn't mistaken for singular). **Non-finite = typed error** (corruption ≠ absence); finite-but-singular falls through to the qform |
| Negative xform code read as absent | Typed error — malformed header |
| Fractional `vox_offset` truncated | Typed error |
| `geometry_source` was a trace, not a record | Now in the **ADR-0056 §6a / ADR-0058 sealed provenance bag**, key `nifti_geometry_source` |
| Tests for NaN/inf + odd qform behind a valid sform | Added, incl. the pinned asymmetry (an unnameable code on the *unused* transform stays ignored) |

**Correction to the review's hash note:** the provenance bag moves **`manifest_hash`**, not
`content_hash` — the latter is `merkle_root(block digests)` only (`product.rs:161`), so the sealed volume
bytes are untouched. No NIfTI product is in the conformance corpus, so no golden moves either way.

**Not done here, filed instead: #459.** Tightening `WorldFrame::is_nondegenerate` itself would change the
format-wide `ArraySpec::validate` gate that *every* array product passes, so narrowing it is a format
decision needing its own review — #459 proposes promoting these helpers into `WorldFrame` with the
epsilon stated in ADR-0030, and auditing the corpus first.

### The quaternion IS validated against real FSL data — just not in a committed test

#396 asked for the qform to be tested "against a real FSL-produced qform-only file, not only a synthetic
one". The committed tests are synthetic (the brief forbids real data in fixtures), but the math was
verified against real third-party data locally before this PR was finalised, using `functional.nii` from
nibabel's test data — which carries **both** a qform and an sform, written by FSL itself:

```text
functional.nii: ndim=4 dims=(17,21,3,20) dt=4(int16) qform_code=2 sform_code=2
                pixdim[0]=-1 (qfac)  pixdim[1..3]=(4,4,8)
                quatern=(b=0, c=1, d=0)  qoffset=(32,-40,0)  xyzt_units=10 (mm|sec)

decoder, sform branch (as shipped):   affine = [-0,-0, 4,-32,  -0,-4,-0, 40,   8, 0, 0, 0]
decoder, qform branch (sform zeroed):  affine = [ 0,-0, 4,-32,   0,-4,-0, 40,   8, 0, 0, 0]
MAX |qform - sform| = 0        <- exact
```

Reproducing FSL's own sform from its own quaternion, bit-for-bit, is a genuine third-party check — and
this file exercises exactly the two parts #396 warned about: `pixdim[0] = -1` (the **qfac k-column
flip**) and `b² + c² + d² = 1` (the **`a = 0` 180°-rotation branch**, not the ordinary
`a = sqrt(1 - …)` path).

The same run confirmed B4 and B5 on real data too: `functional.nii` decodes all **21420** voxels (on
`dev`: 1071, i.e. volume 0 of 20), its `sform_code = 2` yields `space = "aligned"` — a real file `dev`
would have mislabelled `"scanner"` — and its TR comes out as `time_regular(0, 2.0)`. Real
`standard.nii.gz` (143 B, gzipped uint8) decodes to 140 uint16 voxels, exercising B2 and the
uint8→uint16 widening on a real `.nii.gz`.

**#448** tracks vendoring those two files (143 B + 43 KB, verified non-PHI phantom/test patterns) so the
evidence becomes a committed test. Two corrections it records, from reading the bytes and the licence
rather than assuming: nibabel's PDDL carve-outs are its **Philips PAR/REC** files, not its NIfTI ones
(the `.nii` files are MIT by omission, and `doc/source/someone.nii.gz` carries a separate MNI/ICBM
licence and must be avoided); and **no** `.nii` in that directory is strictly qform-only, so the
criterion is better reframed as "a real FSL-written qform cross-checked against an independent writer",
which `functional.nii` satisfies better than a qform-only file would.

Closes #396
