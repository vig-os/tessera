## Each decision → its reason

- **Naming `<table>/{index:04}`, padded per index (§1).** It is deterministic and has no ceiling (`10000` follows `9999`). It looks the same as `_NNNN` below 10000 blocks. A fixed 4-digit width caps a table at 41.9 G rows, which a one-hour acquisition nearly reaches. A width derived from the block count makes every name depend on the total.
- **A sealed `TableSpec.partition {index, last}` marker (§2).** Each leaf describes itself, so a user's `pairs/0003` can't silently join a table: it's either a foreign child or a leaf after the terminal one. Gaps and lost tails show up from the manifest alone. Rejected: reserving numbered names (a reader can't verify it, and it collides with pyramid levels), a contiguous run without a marker (doesn't fix nit 2), and a product-level map (duplicates the name tree).
- **One resolver, `Reader::table_group` (§3).** It runs over the manifest only, and the seal and every reader share it, so any product the seal accepts, every reader resolves. Failures come back as typed `Error::LogicalTable` variants.
- **Legacy `_NNNN` (§4).** Readers keep today's rule verbatim for format v0, and writers never produce it again. A mixed product is refused as `Ambiguous`, never merged. All writers switch in one PR (D), after every reader reads both forms (A, B, C1, C2).
- **No `TESSERA_VERSION` bump (§6).** This is a schema-compatible v0 addition. Old readers keep the unknown field (`BlockRef.spec` is a `Value`) and fail a logical read with a typed error, never with wrong rows. A bump would gate nothing (`SUPPORTED_MAJOR = 0`) and would move every `manifest_hash`. PR D is marked `!`.
- **`StreamWriter::push_table` with per-block disk staging (§5).** The bound is `min(W, n) · p_block + s` with `s` stated (§8), staged input stays ≤ `W + 1` blocks, and a ksb RSS proof checks six pass criteria (§8.1). Filling blocks in memory and a bounded channel were rejected on the note's measurements.
- **P, R and F are rejected (§10),** each with the note's evidence.
