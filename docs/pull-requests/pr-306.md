# [PR 306](https://github.com/vig-os/tessera/pull/306) feat(core): recursive-collection mechanism — MemberKind + domain-separated leaf + level tag (ADR-0049 Part 1)

## Why

Collections could express a patient exam (products) but **not** a cohort (a collection *of* collections) — ADR-0033 §2 promised recursion the flat model didn't support. This is the **mechanism** half, decided by spike **#293** (4 fresh-context reviews) and recorded in **ADR-0049**. Level *semantics* (what a level means, living/frozen cohorts, FAIR mapping) are deliberately deferred to **#294**; **Part 2** (recursive `verify` in the CLI consumer verbs) rides on **#282** once it merges.

## What (`tessera-core`)

- **`MemberKind { Product, Collection }`** on `CollectionMember` — bare `#[non_exhaustive]` enum, `#[default] Product`, **skip-on-default** so pre-recursion collections serialize byte-identical (corpus-neutral); an unknown `kind` is **refused** by serde.
- **Domain-separated content-hash leaf** — `BLAKE3("tessera-collection-member-v1" ‖ kind_byte ‖ manifest_hash)`, so MMR inclusion proofs are **kind-bound** and `kind` can't be flipped without moving `content_hash`. (No pinned collection goldens exist — the 3 consumers are same-run round-trips — so the construction is adopted outright, pre-1.0.)
- **Open, domain-supplied `level: Option<Coded>`** — carried + sealed but **never interpreted**; level taxonomies are domain data, not an engine enum (RFC §12). Dissolves the DICOM-"Study" collision; the engine's nouns stay generic.
- **Typed `ProductHandle`/`CollectionHandle`** (`pub(crate)` fields + `::of()` + accessors) and `add_product`/`add_subcollection` builder methods — `(reference, manifest_hash)` carried as one unit; `derived_from` peers-only.

## Interim guards (`tessera-io` projections)

Projection nesting is #294, but the projections ship here, so they must not **silently** break on a nested member:
- `prefix_layout` → resolves `<id>.collection.json` for a sub-collection member.
- `to_oci_index` → **refuses** a nested member loudly (recursive index-of-indexes = #294).
- `to_rocrate` → marks a nested member `conformsTo` a nested crate (not silent-flat).

## Review trail (spike discipline)

Round-1 reviews shaped the design (ADR-0049); **round-2 reviews of the shipped code** caught what the green gate didn't — the string-leaf fragility (→ byte-tag) and the kind-blind projections (→ guards). Both fixed in the second commit.

## Tests

13 core + a new io test: corpus-neutral serialize · **kind-bound content_hash** · **kind-flip-tamper on a sealed doc caught by `verify`** · optional+sealed+validated `level` · refuse-unknown-kind · `add_member`-vs-`add_subcollection` divergence · nested collection via typed handles round-trips · **projections handle a nested member honestly**. `nix flake check`: **all checks passed!**

Closes the Part-1 scope of #293.
