# [PR 350](https://github.com/vig-os/tessera/pull/350) feat(referencing): log-spaced axis transform for calibration LUTs (ADR-0032)

## What

Adds a **log-spaced axis** to the ADR-0032 transform taxonomy — `Transform::Log { ln_lo, ln_step }`, where `physical = exp(ln_lo + ln_step · stored)`. It's the log-space analogue of `affine_1d`: a *geometric* progression stored as a regular integer index.

This is the first, self-contained piece of #349 (giving fd5 a compute-access derived view for `calibration`/lookup-table products).

## Why

The `calibration` archetype's defining case is a physics **cross-section σ(E) curve** or a **2-D inverse-CDF sampler** whose energy axis is **log-spaced** — so a handful of nodes span keV→MeV at ~constant *relative* resolution. Neither existing member fits:

- `affine_1d` is linear (arithmetic spacing) — wrong grid for decade-spanning energy.
- `Lookup` would store every node explicitly — throwing away the closed-form, O(1) index that makes the hot-loop gather fast.

`Log` is the regular, closed-form member that was missing. It slots into the taxonomy exactly like the others (self-describing `kind = "log"`, additive, `apply_scalar`/`invert_scalar`).

## Changes (`tessera-core::referencing`)

- `Transform::Log { ln_lo, ln_step }` + `apply_scalar` / `invert_scalar` (invertible iff `ln_step != 0` **and** `physical > 0` — no `ln` of ≤ 0).
- `Referenced::log_axis(lo, hi, n, unit)` constructor — a log grid over `[lo,hi]` at `n` nodes, frame `"physical"` (mirrors the `time_regular`/`time_ticks` constructor style).
- Tests: geometric-grid endpoints + constant step-ratio, index roundtrip, invert guards, self-describing serde roundtrip; added to the two `every_constructor_*` pinned-vocabulary sweeps.

`cargo test -p tessera-core referencing` → 17 passed / 0 failed; `cargo fmt --check` clean.

## Follow-on (rest of #349, not in this PR)

The other two additive asks from #349 — the **interp / ICDF-sampler descriptor** (how to reconstruct/sample *between* nodes: linear / log-log / nearest, and the inverse-CDF semantics) and the **aux-carried thin reader** (ADR-0042 territory) — are separate concerns (reconstruction & packaging, vs. coordinate transform) and are left for follow-on PRs so this one stays a clean, single-axis addition.

Context: this comes out of the strata/PPU Monte-Carlo work — the physics tables are exactly this `calibration` archetype (log-spaced σ(E), 2-D ICDF samplers), measured on an RTX 5090 at ~7 G gathers/s.
