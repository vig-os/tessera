# [PR 282](https://github.com/vig-os/tessera/pull/282) feat(cli): collection consumer verbs — inspect / ls / verify (#272)

## Why

A `collection.json` catalog (the declarative ingest engine's output, ADR-0033) had **no consumer surface**: you could produce one but not read or integrity-check it without re-running the ingest. This adds the collection-level analogue of `tessera inspect` / `verify`.

## What

- `tessera collection inspect <collection.json>` — identity + **seal badge** (`sealed✓`/`sealed✗`, recomputed like #268) + each member's role / reference / pinned `manifest_hash`.
- `tessera collection ls <collection.json> [--full]` — one line per member with its **human name + product**, resolved by opening each member `.tsra` (the human-friendly view over the content-hash-named files); `--full` adds full hashes + in-collection `derived_from` edges.
- `tessera collection verify <collection.json>` — the collection seal (`id`/`content_hash`/`manifest_hash`), **then** every member is present + intact (its own seal) + exactly the version the catalog pinned. A swapped-but-valid member, or a missing one, is a typed integrity error.

Members resolve as `<reference>.tsra` next to the `collection.json` (the `prefix_layout` / engine convention).

## Evidence
- New `tessera-cli/src/collection.rs`; a "Collections" help group (drift test + `help.trycmd` updated).
- Test builds a 2-member collection on disk and exercises `inspect`/`ls`/`verify` + the missing-member failure path.
- Hermetic `nix flake check`: **all checks passed!**
