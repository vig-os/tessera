# [PR 320](https://github.com/vig-os/tessera/pull/320) docs(adr): ADR-0051 — GE listmode HDF5 decomposition (tables as products) (#305)

Closes #305 (a `discussion · large` spike). The design work was done live during the DUPLET first-user run; this ADR records the decisions.

## Decisions (ADR-0051)
1. **One product (`.tsra`) per table**, not one per file. Driven by fetch-granularity + integrity: OCI push = one whole-blob sha256, so a **pruned fetch's integrity dies** at the layer → the **prune boundary = the artifact boundary**. Pull only `events`, leave the 81 GB `singles`, integrity intact per artifact. (blake3 Merkle survives partial fetch, but only via Tessera's range-reader — not `docker pull`.)
2. **Acquisition = a Collection** (ADR-0033/0049); the `derived_from` **root is cohort-dependent** — DP01–06 `BLF-singles → coin → events`, DP07+ `GE-coinc → coin → events` — so a per-cohort DAG, not a fixed template.
3. **Shared index tables** (`time_markers`/`coin_counters`/… ~21 MB = 0.017%) **duplicated freely** — content-addressing dedups at the registry/cache; avoids a fetch-dependency edge.
4. Columns **annotated** (#307) + optionally **quantized** (#310) at ingest.
5. Tight analytical coupling does **not** force co-location (cross-object DataFusion spans artifacts); multi-block-same-`.tsra` reserved for always-together/never-fetched-apart.

Adds the `docs/adr/README.md` matrix row + a `_typos.toml` allowlist (the hook was corrupting `OME-Zarr` in the index).

Refs: #305 · relates ADR-0033/0049/0035, #307/#310/#304, #291/#292.
