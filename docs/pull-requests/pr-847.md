# [PR 847](https://github.com/vig-os/tessera/pull/847) feat(io): stream a partitioned table whose row count is known only at close

Closes #806

## What

ADR-0065 §7.3 item 3, plan item 1: a streamed partitioned table whose row count is known only at close.

- `StreamWriter::open_table(name, spec)` (`spec.rows = 0`) returns an `OpenTable`. Feed it with
  `OpenTable::push(&mut writer, group)` and end it with `OpenTable::close(&mut writer) -> Result<u64>`.
  The handle borrows no writer: each call takes the `&mut StreamWriter` the table was opened on, checked
  by identity.
- **One leaf of lookahead.** A full leaf is handed to a worker as the non-terminal `<name>/NNNN` as soon as
  a row follows it, and before the next leaf's staging file is created. Only the last leaf waits for
  `close`, which makes it the terminal leaf, or the bare single block `name` if it is alone. Nothing is
  renamed.
- **Bounds.** `push_table`'s bounds hold unchanged: `W + 1` staged input leaves and the same heap bound.
  With `T` tables open on one writer the staged bound is `W + T`. All of this is in the rustdoc.
- **Failure.** An error, a drop, or a `close` on another writer abandons the table and deletes the staging
  file of the leaf being filled. The seal then refuses a partitioned remnant (`LogicalTable`). The handle
  is `#[must_use]`.
- `push_table` is now this writer with a declared row count, so both share one staging and dispatch path.
  Its behaviour, error order and messages are unchanged, and its existing tests pass as they are.
- Docs: a FEATURE-MATRIX row, and a pointer in the book's push_table migration note. That note's alpha.5
  line citations are left as they are.

The prototype on `spike/800-capi-prototype` staged an unknown-count table in full before encoding, so no
code was taken from it.
