# [PR 1009](https://github.com/vig-os/tessera/pull/1009) fix(io): refuse a table whose leaves disagree on a column contract

Closes #978

A table could seal with leaves that disagree on dtype or nullability and then fail every logical read.
Writers now refuse differing column names, order, dtypes, nullability, or column counts. Sealing and decoded
column concatenation share the same value-contract comparison, and typed errors identify both contracts.

Group membership comes from the table resolver, and only table members participate in contract comparison.
An array `img` beside table `img_0001` remains valid. Both packers, streaming table paths, and ingest refuse
incompatible contracts; reads remain strict for previously sealed products. Independent tables with a
shared legacy numbered prefix must agree on their contracts or be renamed (for example `run_first` and
`run_second`); SPEC, ADR-0064's dated amendment, and the breaking writer changelog entry document this.

Tests cover builder and streaming refusals, both naming forms, packers, old sealed products, mixed block
kinds, reordered and extra columns, descriptive metadata, and maximum-length single-block names.
Deliberately invalid reader fixtures are assembled below writer validation. The CLI nav regression still
checks that a gapped table displays its error, and now also asserts the writer refuses that fixture.

Pre-fix evidence:
- Four dtype/nullability builder and streaming regressions: exit 100, all four fail.

- Previous CI exposed the CLI nav invalid-fixture writer call; the fixture now uses canonical ZIP primitives.
