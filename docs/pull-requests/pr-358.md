# [PR 358](https://github.com/vig-os/tessera/pull/358) ci: add an aggregate gate job so the required status check can pass

## The bug

`main`'s branch protection requires the status context **`nix flake check`**.

The matrix job reports per-leg as **`nix flake check (x86_64-linux)`** and **`nix flake check (aarch64-linux)`**.

Branch protection matches context names **exactly**. So the requirement has never matched any run that GitHub produces — it is unsatisfiable, and every PR has looked mergeable regardless of what CI did. Verified:

```console
$ gh api repos/vig-os/tessera/branches/main/protection --jq '.required_status_checks.contexts'
["nix flake check"]

$ gh api repos/vig-os/tessera/commits/main/check-runs --jq '.check_runs[].name'
sync
Scorecard Analysis          # <- no "nix flake check" anywhere

$ gh api repos/vig-os/tessera/branches/dev/protection
404 Branch not protected
```

`dev` has no protection at all, so "gated on `dev`" has been honour-system throughout — including for #354/#355, which were merged with `--admin` to bypass checks that were not actually required.

## The fix

A `gate` job whose name is **stable across matrix changes**, so protection can point at it once and stay correct when an arch is added or renamed.

`if: always()` plus an explicit result assertion is deliberate, not defensive noise: a **skipped** required check is treated as *neutral* (i.e. passing) by branch protection. Without `always()` the gate would be skipped when a leg fails — silently vanishing instead of blocking.

`needs.check.result` is the aggregate over every matrix leg; it is `success` only when all legs succeeded.

