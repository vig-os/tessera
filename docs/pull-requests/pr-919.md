# [PR 919](https://github.com/vig-os/tessera/pull/919) docs(design): tessera-table-v2 codec profile design note

## Summary

This adds the design note for the `tessera-table-v2` codec profile: [`docs/spikes/915-tessera-table-v2.md`](docs/spikes/915-tessera-table-v2.md). It is step 6 of the ADR-0066 implementation plan, and #828 (step 7) cannot start until the owner accepts it. ADR-0066 step 6 now links to the note. No product code, SPEC, corpus or goldens change.

## What the note decides

The note decides the seven items #915 asks for, with evidence from the #828 sweep, #822 and #826:

1. **Profile.** The codec is chosen per column by its dtype, and it is forced, never sampled:
   - integers of 16 bits or more, and floats: Vortex Pco, level 8;
   - 8-bit integers: Vortex Zstd, one frame per row-group, no dictionary;
   - `b1` and `utf8` columns: v1's codec set, unchanged.

   One rule covers every product type. There are no per-product-type level tables and no logical transforms.
2. **Naming.** The profile is recorded in the existing sealed `TableSpec.codec_profile` field as `"tessera-table-v2"`. Two invariants keep SPEC §5b's rule "readers never refuse an unknown profile" sound:
   - a profile never changes the decoded values;
   - a profile writes only arrays that the edition's readers decode.

   The note also says where an unknown profile is refused and how this fits ADR-0060's opaque `blocks[].spec`.
3. **Trade-off.** Size from the sweep: GE −18.6 %; Siemens ≈ −5.4 % with Zstd framed per row-group. The cost: random take and non-contiguous filters decode a whole 65,536-row group, where v1 has O(1) kernels. Projection, zone-map pruning and DuckDB interop are kept.
4. **Determinism.** The existing corpus gate, plus:
   - a new `table_v2_dtypes` fixture;
   - a check that 1 worker and N workers write the same bytes;
   - an aarch64 run on the #828 head before merge;
   - the `pco` and libzstd versions added to the profile's drift guard.
5. **Acceptance numbers for #828:**
   - size: GE ≤ 3.25 B/ev, Siemens ≤ 7.10 B/ev;
   - lossless round trip on both #822 fixtures;
   - whole-writer encode ≥ v1 per core;
   - full-scan decode ≥ 500 MiB/s per core;
   - floors for take, projection and pruning;
   - a size table for the whole corpus.
6. **Alternatives rejected**, each with its reason.
7. **Pre-mortem** with nine failure stories.

## Owner decisions needed

- **O0.** The owner adopted "the per-column codec profile" on #828. The note reads that as the dtype rule, not #828's per-product-type tables. Recommended: the dtype rule.
- **O1.** The codec for 8-bit columns. Recommended: Vortex Zstd. Native 8-bit Pco would make a stock reader of the edition panic.
- **O2.** Accept take at row-group granularity. Recommended: yes.
- **O3.** Record no codec per column. Recommended: no record.
- **O4.** Require an aarch64 run before #828 merges. Recommended: require it.

## Review

Two independent review rounds. Round 1 found three blockers, all fixed:
- the take-granularity claim was wrong;
- native 8-bit Pco broke the edition contract;
- the owner's adoption of the per-column profile had not been put to the owner as a question.

Round 2 approved with nits, which are fixed too.
