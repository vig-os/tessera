# [PR 687](https://github.com/vig-os/tessera/pull/687) fix(deps): guard and ignore the four unreachable zstd advisories

## Description

Makes `cargo deny check` clean on `dev` again. Four zstd-family RustSec advisories fail every PR's
`Lint & Format` job at the `cargo-deny` hook. The issue names one of them; the advisory db has since added three
more against the same crates.

| Advisory | Crate (locked) | Fixed in | Reachable? |
|---|---|---|---|
| RUSTSEC-2026-0391 | `zstd` 0.13.3 | >= 0.14.3 | no: parquet, zarrs and arrow-ipc (`sql`) use only the bulk API and `decode_all`, never `with_context` |
| RUSTSEC-2026-0398 | `zstd-safe` 7.2.4 | >= 8.2.0 | no: the `seekable` feature is off |
| RUSTSEC-2026-0403 | `zstd-safe` 7.2.4 | >= 8.2.0 | no: `stream::write::Decoder` is never used |
| RUSTSEC-2026-0410 | `zstd-sys` 2.0.16 | >= 2.1.2 | no: wasm32 only, and zstd-sys isn't in the tessera-wasm wasm32 graph |

No bump is possible. zarrs 0.23.14 (latest) and zarrs main require zstd 0.13.3. The first parquet on zstd 0.14 is 60.0,
and it needs arrow 60, which the vortex 0.75 fork (arrow 58.3) and datafusion 55 (arrow 59) can't take.

## Changes Made

- `tessera/deny.toml`: four narrow ignores, each dated 2026-10-26 with its reason and the tracking issue, plus
  `[[bans.features]]` denying `seekable` on `zstd-safe` and `zstd-sys`.
- `tessera/clippy.toml` (new): `disallowed-methods` for the four `stream::{raw,read,write}::*::with_context`
  constructors and `zstd_safe::DCtx::decompress_stream`, and `disallowed-types` for `zstd::stream::write::Decoder`
  and `zstd::stream::raw::Decoder`. Banning the raw decoder closes the `Operation::run` / `zio::Writer` route to
  `decompress_stream`, which the method ban can't see.
  Each reason points at #684. With these, the ignores can't silently become wrong through our own code.
- #684 tracks removing the ignores. It holds the file:line reachability evidence, the exit criteria, and the rule
  that every parquet or zarrs bump must re-verify reachability (precedent: apache/arrow-rs#11922).

No `Cargo.lock` change, so feature snapshots and seals are unaffected.

## Testing

- `cargo deny check` on origin/dev `41de440`: exit 1 (all four advisories). On this branch: exit 0.
- `cargo clippy --workspace --all-targets -- -D warnings`: exit 0.

Closes #683
