# [PR 315](https://github.com/vig-os/tessera/pull/315) feat(core): collection level schemas — terminology as registered/versioned data (ADR-0050, #294)

## Why

The recursion mechanism (#306/#309) gave collections *structure* (2 member kinds + recursion) but no *semantics* — nothing said whether a level is a *dataset*, *project*, *cohort*, *exam*. Rather than hardcode a clinical ladder into the engine (opinionated), **terminology becomes schema** — the collection analogue of `ProductSchema`, symmetric with how products already work (RFC §12). Decided in the #294 design thread.

## What (`tessera-core`)

- **`CollectionSchema { collection_schema, version, description, member_rule }`** + **`MemberRule { allowed_member_kinds, recursive }`** + **`CollectionSchemaRegistry`** (mirrors `SchemaRegistry`). Core ships three levels: **`collection`** (generic, any kind — the permissive default), **`dataset`** (products only — acq + derived from one physical setup), **`project`** (sub-collections only, recursive). A **domain registers its own** opinionated levels (`exam`/`cohort`/`site`/`trial`/…) — **unlimited named levels via schema, zero new engine machinery** (each is structurally a `kind:Collection`, named + rule-constrained by its schema). Unknown level → permissive (open-world), like unknown product schemas.
- **`Collection.collection_schema`** (default `collection`, **sealed** — part of `manifest_hash`) + `CollectionBuilder::with_collection_schema`.
- **`member_rule` validated at seal (fail-fast) + `Collection::verify`** — a `dataset` can't seal with a sub-collection member; a `project` can't with a product.
- **`acq`/`derived` = `Role`, not a level.** CLI `collection inspect` surfaces the schema.

The engine stays generic (two kinds + recursion); **all opinion lives in registered, versioned schemas** — the reviewers' fixed clinical ladder is demoted to *one domain's registered vocabulary*.

## Seal impact

Additive: `collection_schema` enters the canonical bytes → collection `manifest_hash`es shift. **No pinned collection goldens** (the corpus pins only products) → no regen; existing collections deserialize to the permissive `collection` default and validate.

## Tests / evidence

4 new core tests (registry has the 3 levels · dataset accepts/rejects · project accepts/rejects · generic+unknown permissive + **schema sealed / kind-flip caught**). core 108 + io 114 + ingest 36 + cli green; clippy clean; `nix flake check`: **all checks passed!** ADR-0050 + README index.

**P1 (deferred, in ADR-0050):** `allowed_member_schemas` (cross-file "cohort ⇒ subject-members" — verify-time), `CollectionSchema.fields[]`, embedding the schema (offline self-describing), `id_inputs`-binding (identity vs seal), a worked domain-plugin level ladder.
