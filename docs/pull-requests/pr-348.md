<h2>v0.2.0</h2>
<h3>Added</h3>
<ul>
<li>Bounded retry with exponential backoff for transient GitHub API failures (<code>404</code>, <code>5xx</code>, <code>429</code>, and <code>403</code> when the error message indicates rate limit or abuse), configurable via <strong><code>MAX_ATTEMPTS</code></strong> and <strong><code>CommitOptions</code></strong> (<code>maxAttempts</code>, <code>logger</code>, optional <code>baseDelayMs</code> / <code>maxDelayMs</code>); new retry module helpers <code>isTransientError</code>, <code>classifyError</code>, <code>calculateDelay</code>, and <code>withRetry</code> (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/20">#20</a>).</li>
<li>Efficient multi-file commits via GitHub <code>createTree</code> <strong>inline <code>content</code></strong> for text files (blobs created server-side), <strong><code>createBlob</code></strong> only for binary files (NUL detected in the first 8 KiB), and <strong>chained <code>createTree</code></strong> requests in chunks of <strong><code>TREE_ENTRY_CHUNK_SIZE</code> (100)</strong> entries for very large change sets and payload limits (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/19">#19</a>).</li>
</ul>
<h3>Changed</h3>
<ul>
<li>README Action example uses a tagged release (<code>@v0.1.5</code>) instead of <code>@main</code> for reproducibility; unreleased behavior remains documented in the same section.</li>
<li>Exported helpers for library use: <code>isBinaryFile</code>, <code>getFileMode</code>, and <code>TREE_ENTRY_CHUNK_SIZE</code> from <code>commit.ts</code>.</li>
<li>Binary blob creation is now sequential instead of concurrent to avoid secondary rate-limit bursts.</li>
</ul>
<h3>Fixed</h3>
<ul>
<li><code>withRetry</code> could surface <code>undefined</code> when <code>maxAttempts</code> was non-positive or non-finite; values are now normalized to at least one attempt.</li>
<li>HTTP-like error detection for retries now requires <code>status</code> to be a number (avoids misclassifying odd error shapes).</li>
<li>Non-UTF-8 text fallback in <code>createTree</code> delegates to <code>createBlob()</code> so blob behavior stays consistent.</li>
<li><code>isBinaryFile</code> false positives when <code>readSync</code> returns fewer bytes than requested (zero-filled buffer tail).</li>
<li>Silent data corruption for non-UTF-8 text files by validating with <code>TextDecoder({ fatal: true })</code> and falling back to <code>createBlob</code>.</li>
</ul>

<h3>Fixed</h3>
<ul>
<li>The <code>e2e-smoke</code> and <code>published-tag-smoke</code> verify steps no longer flake on GitHub's read-after-write replication lag. Their &quot;branch head points at the reported commit&quot; assertion read the scratch-branch head via the REST API immediately after the action's <code>updateRef</code> returned, and could observe the stale pre-commit head — the action had committed correctly, but the check reported a mismatch. Both steps now poll the branch head for the reported <code>commit-sha</code> with a bounded retry (up to 5 attempts, 3s apart) before failing, while keeping the hard failure after the budget so a genuine no-op (the <a href="https://redirect.github.com/vig-os/commit-action/issues/58">#58</a> class of bug) is still caught (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/96">#96</a>).</li>
</ul>
<h2><a href="https://github.com/vig-os/commit-action/releases/tag/v0.3.0">v0.3.0</a> - 2026-07-15</h2>
<h3>Added</h3>
<ul>
<li>A new consumer-owned <code>js-quality</code> workflow gates every PR on <code>just lint</code> and <code>just format-check</code> (a new read-only recipe backed by <code>prettier --check src</code>). Neither eslint nor prettier was enforced anywhere before: the scaffold-managed <code>ci.yml</code> has a &quot;Lint &amp; Format&quot; job, but it runs only the prek hook suite, which contains no JS linter or formatter. That is precisely how the broken globs above survived — the scripts were never run by anything but a human. Fixing them without a gate would have let them rot again the same way (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/66">#66</a>).</li>
<li>A new <code>e2e-smoke</code> workflow executes the <strong>committed bundle</strong> against the real GitHub API on every PR, running the action the way a consumer does (<code>uses: ./</code>) rather than importing its source. It commits a file to a scratch branch through the full REST flow and asserts the commit exists, is <strong>signed</strong>, and carries the expected content, then deletes the branch. Nothing previously executed <code>dist/index.js</code>: the unit tests import <code>main()</code> directly and the repo dogfoods <code>commit-action</code> at a pinned released SHA. That gap is not theoretical — the ESM migration found that the CommonJS <code>require.main === module</code> entry guard does not survive bundling to ESM, leaving the bundled action a silent no-op (exit 0, nothing committed) that 84 passing unit tests could not see (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/58">#58</a>).</li>
<li>CI now gates the committed ncc bundle against source drift so a stale <code>dist/index.js</code> can never reach a tag. A new consumer-owned <code>dist-check</code> workflow rebuilds the bundle on every PR to <code>release/**</code>/<code>main</code> and fails when the committed <code>dist/index.js</code> differs, and the release-time <code>release-extension</code> hook re-verifies the finalized commit before it is tagged (rolling the release back on drift). Both rebuild with the pinned dev-shell toolchain (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/59">#59</a>). The gate is deliberately scoped to the release boundary — <code>dev</code> is not gated, since nothing ships from <code>dev</code> and gating it would fail every Renovate runtime-dependency bump (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/71">#71</a>).</li>
</ul>
<h3>Changed</h3>
<ul>
<li>Adopted vigOS devkit <code>1.2.1</code> and declared the per-repo release tag scheme in <code>.vig-os</code>: <code>DEVKIT_TAG_PREFIX=v</code> restores this repo's historical <code>v</code>-prefixed tags (<code>vX.Y.Z</code>) through the release pipeline, and <code>DEVKIT_FLOATING_TAGS=major,minor</code> force-moves the floating <code>v0</code> / <code>v0.X</code> tags to each promoted release automatically — both were previously moved by hand. Consumers can pin <code>@v0</code> (floating major), an exact <code>@vX.Y.Z</code>, or a SHA (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/62">#62</a>). The first attempt to ship 0.3.0 on devkit <code>1.2.0</code> failed in the automated release workflow: the scaffolded <code>release-core.yml</code> applied the draft + approval gate to every release kind, so a release-candidate dispatch aborted against its still-draft PR. 1.2.1 guards that gate behind <code>release_kind=final</code><code>vig-os/devkit#1095</code><a href="https://redirect.github.com/vig-os/commit-action/issues/79">#79</a>). 1.2.1 also folds the <code>dist/src/</code> <code>tsc</code>/<code>ncc</code> declaration byproducts into the managed <code>.gitignore</code><code>vig-os/devkit#1092</code><code>dist/.gitignore</code>, and moves the flake-generated <code>.pre-commit-config.yaml</code> symlink ignore to the new consumer-owned <code>.gitignore.project</code>; the <code>vigos</code> flake input is bumped to <code>1.2.1</code> to match the scaffold (issues <a href="https://redirect.github.com/vig-os/commit-action/issues/62">#62</a>, <a href="https://redirect.github.com/vig-os/commit-action/issues/79">#79</a>).</li>
<li><strong>Migrated the action to ESM.</strong> The <code>@actions/*</code> toolkit went ESM-only at its next major (no <code>require</code> condition in its <code>exports</code> map at all), so <code>@actions/core</code> v3, <code>@actions/github</code> v9 and <code>@actions/http-client</code> v4 were unlandable individually and had to move together (issues <a href="https://redirect.github.com/vig-os/commit-action/issues/49">#49</a>, <a href="https://redirect.github.com/vig-os/commit-action/issues/50">#50</a>, <a href="https://redirect.github.com/vig-os/commit-action/issues/51">#51</a>). The package is now <code>&quot;type&quot;: &quot;module&quot;</code>, TypeScript resolves with <code>module</code>/<code>moduleResolution: nodenext</code>, relative imports carry explicit <code>.js</code> extensions, and <code>ncc</code> emits an ESM bundle (plus a small <code>dist/package.json</code> declaring the bundle's module type, now tracked alongside <code>dist/index.js</code>). Jest runs in ESM mode: the module mocks moved from <code>jest.mock</code> + a <code>__mocks__</code> manual mock to <code>jest.unstable_mockModule</code> with dynamic imports, and the old <code>src/__tests__/setup.ts</code> is gone. All 84 tests are preserved unchanged (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/58">#58</a>).</li>
<li>Dropping the classic <code>moduleResolution: node</code> also fixed a <strong>silent type hole</strong>: classic resolution ignores <code>exports</code> maps, so <code>@octokit/core/types</code> never resolved and every <code>octokit.rest.*</code> call in <code>src/commit.ts</code> degraded to <code>any</code> — the entire signed-commit REST flow was unchecked. Those calls are now type-checked against real Octokit types. This additionally unblocks TypeScript 7, which removes <code>moduleResolution: node</code> outright (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/54">#54</a>).</li>
<li>Removed the <code>@actions/http-client</code> and <code>undici</code> <code>overrides</code> pins. The <code>http-client</code> pin (<code>3.0.2</code>) was what actually blocked the v4 major, and the <code>undici</code> pin is now redundant: <code>@actions/http-client</code> v4 depends on <code>undici: ^6.23.0</code>, which resolves to the same <code>6.27.0</code> the pin was added to force (<code>npm audit</code> reports no runtime vulnerabilities).</li>
<li>Migrated ESLint to flat config (<code>eslint.config.mjs</code>, replacing <code>.eslintrc.json</code>) and bumped <code>eslint</code> from <code>8.57</code> to <code>10.x</code>. ESLint 9 made flat config the default and ESLint 10 removed the legacy <code>.eslintrc</code> path entirely. The rule set is a faithful port — same base configs and the same two overrides — with the <code>node</code>/<code>es6</code>/<code>jest</code> environments becoming <code>languageOptions.globals</code>. <code>@typescript-eslint/eslint-plugin</code> and <code>@typescript-eslint/parser</code> are replaced by the <code>typescript-eslint</code> meta package, the canonical v8 flat-config entry point (issue <a href="https://redirect.github.com/vig-os/commit-action/issues/64">#64</a>).</li>
<li><strong>Renovate: update <code>undici</code> from <code>6.23.0</code> to <code>6.27.0</code></strong> (<a href="https://redirect.github.com/vig-os/commit-action/pull/41">#41</a>)</li>
</ul>
