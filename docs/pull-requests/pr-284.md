# [PR 284](https://github.com/vig-os/tessera/pull/284) docs(adr): decide provenance edge shape — merkle-rooted ref, not a path list (ADR-0048, #267)

## Why

#267 asked to turn the multi-file provenance edge (a DICOM series' `ingested_from`) from a comma-joined `reference` string into a **structured list**. The export half shipped in **#275** (opaque `urn:tessera:source:<merkle>` entities — no path, no PHI). This closes the remaining **data-model half** — and the answer is *not* the obvious one.

## The finding

Turning `Source.reference` into `Vec<SourceFile{reference=path, digest, size}>` is **actively harmful**:
1. **Regresses PHI** — an 890-slice series would put 890 patient-bearing absolute paths **back into the sealed manifest**, re-opening exactly the leak `--source-label` (ADR-0040) was built to close.
2. **Forces a schema break + corpus regen** (every `manifest_hash` moves) to carry information that is either deliberately redacted (`--source-label`) or already committed cryptographically as the merkle root.

## The decision (ADR-0048)

- **The sealed edge stays a single merkle-rooted reference** `{role, reference, content_hash = blake3-merkle-over-source-files}`. No list of paths in the seal → no PHI regression, no corpus regen.
- **Per-file structure, when a consumer needs it, rides a PHI-safe `aux/sources/<role>.json`** — digests + sizes, **never paths**; outside the seal (ADR-0042 → corpus-neutral); its `merkle_root` reconciles with the sealed `content_hash` (so the unsealed aux manifest is still authenticated transitively).

The aux emission is a clean additive follow-up (`source_digest` already computes the per-file digests it would list). The format contract — *don't put the list in the seal* — is what had to be decided first, because the wrong shape is the expensive one to undo.
