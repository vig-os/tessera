# [PR 317](https://github.com/vig-os/tessera/pull/317) feat(ingest): dicom-series --rescale-mode global-int16 — quantitative PET per-slice rescale (#300)

Closes #300 — makes GE quantitative PET (per-slice `RescaleSlope`) ingestable.

## Problem
GE PET stores a **per-slice** `RescaleSlope` (Bq·mL⁻¹) so each axial slice uses the full int16 range. The stored samples can't be stacked losslessly under one slope, so `read_series` rejected the whole (clinically primary) series with *"non-uniform series"*. Empirically (issue #300): a 487-slice Q.Clear PET had 487 distinct slopes.

## Fix — opt-in `RescaleMode` (default off → byte-identical)
- **`bit-exact`** (default): reject differing slopes, exactly as before.
- **`global-int16`**: requantize the physical field (`stored × per-slice slope`) to **one global int16 scale** sized by its max magnitude — **physically lossless** (error ≪ measurement resolution — 1.6% worst-case in the #300 benchmark, ≪ PET's ~10–20% SUV noise), **64³-clean**, single scalar slope.

## Self-documenting lossy transform
`to_recon_product` emits `rescale_mode` + **`rescale_slope_per_slice`** (the original slopes — makes it invertible without re-reading the raw DICOM) + `rescale_max_abs_err`, plus a matching `WARN`. Shape/modality/intercept must still be uniform.

## Surface
- CLI: `tessera ingest dicom-series … --rescale-mode global-int16`
- Spec: a `rescale_mode` field on the `dicom-series` format.
- `read_series_rescaled(paths, strip_phi, mode)` is the mode-aware entry; `read_series`/`read_series_deidentified` stay bit-exact (no caller churn).

## Tests
`per_slice_rescale_rejected_bit_exact_then_requantized_global_int16` — proves reject → requantize → provenance recorded → sealed manifest carries the metadata. Full `clippy --all-targets --all-features -D warnings` + all gates green. (Also adds a `_typos.toml` allowlist so the hook stops corrupting DICOM `VR::PN` literals.)
