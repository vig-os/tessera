# [PR 1023](https://github.com/vig-os/tessera/pull/1023) feat(core)!: SchemaMismatch names the column and field that differ, typed

Closes #1021

Schema refusals now carry a typed mismatch kind for column counts, names/order, or the first differing value-contract field, with structured expected/found values. The shared comparison preserves equality semantics and reports differences in column and field order; messages show only the differing item with the table and leaf. Expected/found values are boxed to keep the core error small.

Malformed table specs now produce `Error::MalformedTableSpec`. Updating the existing malformed-spec test to assert this separate error is intentional, following the design ruling. The changelog documents the breaking API changes, including replacing `detail` and removing `Eq` from `LogicalTableError`.

Python continues to surface core `Display` through `TesseraError`; CLI propagates the core error; wasm's existing refusal mapping covers both variants. No specialized schema-error mapping needed changing.
