# [PR 972](https://github.com/vig-os/tessera/pull/972) chore(deps): bump parquet past RUSTSEC-2026-0595

Closes #970

## Why
`cargo-deny` fails every branch on RUSTSEC-2026-0595 (parquet 58.4.1, "Bloom filters written as plaintext when writing encrypted Parquet"). From rustsec/advisory-db `crates/parquet/RUSTSEC-2026-0595.md`:

```toml
[versions]
patched = [
    ">= 60.2.0",
    ">= 59.3.3, < 60.0.0",
    ">= 58.4.2, < 59.0.0",
    ">= 57.3.3, < 58.0.0",
]
```

58.4.2 is the patched release in the 58 line tessera pins. No `deny.toml` ignore is added.

## What moved
- `tessera/Cargo.toml`: the `=`-pins for `parquet`, `arrow-array`, `arrow-buffer`, `arrow-schema`, `arrow-ipc` go 58.4.1 → 58.4.2. `cargo update -p parquet --precise 58.4.2` alone is refused: parquet 58.4.2 requires `arrow-* ^58.4.2`, which conflicts with the arrow pins (lockstep releases).
- `tessera/Cargo.lock`: seven crates, all 58.4.1 → 58.4.2: `parquet`, `arrow-array`, `arrow-buffer`, `arrow-schema`, `arrow-ipc` (the pins above), plus `arrow-data` and `arrow-select`, which are their internal dependencies. Nothing else moved.
- `tessera/tests/feature-snapshots/{arrow-array,arrow-buffer,arrow-schema,zstd}.txt`: version strings only. Inert, shown by normalising `58.4.[12]` → `58.4.N` in the old and new files: the diff is empty for all four.
- `tessera/corpus/ingest-corpus.json`: the decoder version is sealed (ADR-0056 §6a), so this is a deliberate corpus event. In 7 parquet fixtures only `ingest_decoder.version`, `ingest_decoder.features` and `manifest_hash` changed (arrow-rs stamps its version into the footer). **No `content_hash` and no `id` moved.** Regenerated from the Gate A diff of CI run 45471236703.
- Version text: `info.trycmd`, `deny.toml` and `Cargo.toml` comments, and `tessera-cli/Cargo.toml`.

## Does 58.4.2 refuse anything tessera does?
No. Patched versions reject writing bloom filters when encryption is enabled. tessera enables no Parquet encryption feature and uses no encryption or decryption properties. Its `ArrowWriter` uses are test-fixture and bench writers only (`tessera-ingest/src/corpus.rs`, `tessera-cli/src/bench_compare.rs`), with default properties and no encryption. Ingest only reads Parquet.

## Proof
- `cargo deny check`: exit 0 (advisories ok).
- `cargo metadata --locked`: exit 0.
- `scripts/feature-snapshots.sh`: regenerated, delta inert as above.
- Pre-fix failure: CI run 45471236703 failed on the corpus gates (`ingest-gate-a*`, `workspace-test`) after the pin bump alone, before the corpus commit.
