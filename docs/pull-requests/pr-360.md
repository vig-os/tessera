# [PR 360](https://github.com/vig-os/tessera/pull/360) feat(io): nullable table columns — a validity mask, not a sentinel

> **Stacked on #359** — retargeted to `dev` so CI runs (the workflow only triggers for PRs into `dev`/`release/**`/`main`, so a PR based on a topic branch gets no checks at all). The commit list therefore shows #359's commit too; it disappears once #359 merges. **Merge #359 first.**

## Why

Missing values were not representable. A float column could abuse `NaN` — but `NaN` is a legitimate measured value — and an integer column has **no sentinel at all**, so "unknown" simply had no encoding. Scientific tables with gaps could not be stored honestly.

## Design

`ColumnData::Nullable { values: Box<ColumnData>, validity: Vec<bool> }` + a `Column::nullable` spec flag.

A **wrapper**, not a mask on every variant: nullability is orthogonal to dtype, so folding it in would square the enum and force every existing match arm to handle a mask it doesn't care about.

**Vortex-native.** Encoding goes through `PrimitiveArray::from_option_iter`, so the mask *is* Vortex's own validity — the compressor sees real nulls, a constant mask collapses to no buffer, and the mask round-trips through the file format for free. Decoding takes values and mask from a **single executed array** (`validity()?.execute_mask(..)`), so they cannot disagree.

## Two properties worth calling out

**1. Non-nullable output is byte-identical to before this PR.** `Column::nullable` is `skip_serializing_if`, so an unmarked column's JSON is unchanged. The committed conformance corpus keeps its goldens — `corpus_hashes_match_goldens` passes untouched, **no regeneration**.

**2. Values beneath a NULL are not preserved.** Encoding normalises every masked slot to the dtype default. Deliberate and load-bearing: it makes the bytes — and therefore `content_hash` — independent of whatever a producer left under a null. A writer must not be able to change a sealed product's identity by varying invisible data. Pinned by `bytes_are_independent_of_values_under_nulls`, which encodes the same column with three different fillers (`0`, `i32::MIN`, `999999`) and asserts identical bytes.

## The subtle bug this had to avoid

`decode` / `decode_projected` / `decode_column` pre-sized accumulators with `empty_column_with_capacity(&c.dtype, ..)` — dtype only, no nullability. A bare accumulator takes `extend_field`'s non-nullable branch, so **the validity mask would have been dropped silently**: the values still decode, nothing errors, and the nulls just quietly become zeros. All three now build from the `Column` via `empty_column_for`.

## Scope

Fixed-width numerics. `validate` is the single gate — spec/data nullability agreement, mask-vs-values length, no nesting, and a **typed rejection naming the dtype** for nullable `b1`/`str` rather than a panic downstream. Nullable variable-width columns need per-value length plus bit interleaving; separate design, follow-up.

## Semantics

| surface | behaviour |
|---|---|
| chunk statistics (`as_i64`) | NULLs **skipped** — folding them in as 0 would make min/max pruning exclude chunks that do contain matches |
| SQL | real Arrow validity bitmap → `IS NULL` matches; `AVG` skips nulls (returns 2.0, not the 1.0 you'd get averaging the on-disk placeholder) |
| ndjson | JSON `null` |

## Tests

Round-trip through all three read paths · all-null and all-valid constant masks · byte-independence from values under nulls · the non-nullable byte-stability gate · four `validate` rejections incl. out-of-scope dtypes · NULL-skipping statistics · SQL `IS NULL` + `AVG` · three `Column` JSON back-compat tests · and **`materialise_is_bit_identical_across_thread_counts` now carries a nullable column**, since validity is assembled per worker and is exactly the state that can interleave wrongly under parallelism.

**358 tests pass**; fmt + clippy `-D warnings` clean.
