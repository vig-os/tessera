# [PR 460](https://github.com/vig-os/tessera/pull/460) feat(ingest): generic table ingest — Parquet, Arrow IPC and CSV (ADR-0056 P1)

# Generic ingest, the table half: Parquet · Arrow IPC · CSV

Part of #386 (ADR-0056 P1). **This is PR A of two** — the table lane. The array lane (`.npy`/`.npz`,
`tessera ingest array`) lands in PR B, stacked on this branch, and `Closes #386` belongs there.

A scientist holding a Parquet table, an Arrow file or a CSV could previously only reach `ingest blob` —
a sealed black box with no codec, no projection, no ROI reads and no field-level integrity. That is the
gap #390's AX audit scored **write-your-own-data 2/5** while read UX scored 4.5/5. The normalising path
is where the value of the format is, and until now only vendors could reach it.

```text
tessera ingest table study.parquet study.tsra --name study-01 --timestamp 2024-03-01T12:00:00Z
tessera ingest table data.csv      out.tsra   --from csv --column id:u4 --column energy:f8?  …
```

## The determinism evidence

This is the part worth reviewing first, because it is the claim everything else rests on
(ADR-0057 §7): *feature selection may change which formats are readable; it must never change the bytes
produced for a readable one.*

| Property | How it is established |
| --- | --- |
| **Three independent Parquet writers → one `content_hash`** | New hermetic flake check `ingest-producer-equality`: pyarrow (2214 B), polars (1186 B), DuckDB (524 B) write the same logical table; all three seal the same payload. This is ADR-0056 §5's `ingest_parquet_producers` fixture, built for real. |
| The same table written five physical ways → one `id` + one `content_hash` | `tests/generic_table.rs` — dictionary on/off, snappy/zstd/uncompressed, statistics on/off, two-row row groups. |
| A CSV and the Parquet `duckdb COPY` makes from it → one `content_hash` | same file. ADR-0056 §8 advises that conversion; following it and not following it land in the same place. |
| Arrow IPC and Parquet of one table → one `content_hash` | same file. The container is not the product. |
| Reader batch size, **worker count**, RAM budget reach nothing | same file, asserted explicitly rather than assumed. |
| Four feature configurations agree with the committed goldens | Gate A, one derivation per configuration — including `tessera-cli/sql`, which ADR-0057 §5 proved flips `arrow-array/chrono-tz`: hazard **H1** arriving through a feature rather than a host. |
| A build without the CSV lane reproduces the same goldens | `ingest-gate-a-reduced`. This leg found a real bug — see below. |
| Re-running an ingest is byte-identical | `tests/generic_table.rs`. |

`manifest_hash` **does** differ between writers, and that is asserted too: the `ingested_from` edge pins
a merkle root over the source bytes, which genuinely differ. Asserting both directions is what stops a
bug that made every hash constant from looking perfect.

## What is in here

Nine commits, each self-contained. The first six are the feature; the last three are a Gate B
regeneration, an offset-safety proof, and the review fixes:

1. **`feat(core)`** — ADR-0056 §6's three sealed format fields: `Column.referencing` (the epoch slot —
   without it an Arrow timestamp is indistinguishable from a duration, a live ADR-0046 §2 violation),
   `Manifest.ingest_transform` (the recorded-transform receipt), `Column.sensitivity` + a fifth
   `Sensitivity::Unknown`. Plus the permissive builtin `table` / `array` schemas. All
   `skip_serializing_if`-guarded, and **corpus-neutral — asserted, not claimed**.
2. **`feat(ingest)`** — the lane: the canonicalisation boundary, the ADR-0056 §2 type map (three lanes,
   no lossy lane), the Parquet / Arrow-IPC / CSV readers, the sealed decoder identity, `--column-meta`,
   the spec variants and engine arms, and the §7 laundering rule. One commit because ADR-0057 §6's
   closed-and-total enum means a backend's name, handler and decoder cannot land separately.
3. **`feat(cli)`** — `tessera ingest table`, §7's two exit codes, and the trycmd walkthrough.
4. **`test(ingest)`** — the ingest conformance corpus (9 fixtures, generated sources, declared
   per-configuration counts), Gate A, and the three-writer check.
5. **`docs`** — ADR-0056 §12a and a new "Ingesting your own data" book chapter.
6. **`build(deps)`** — the Gate B snapshot regeneration, and the decoder-digest fix it exposed.

## Deviations from the ADRs, all recorded in §12a

The ADRs are locked, so every departure is written into the ADR rather than only into a commit message:

- **(a) CSV ships in P1.** §8 deferred it because *sampled inference* is anti-deterministic. This removes
  the inference, not the format: `--column NAME:DTYPE` is required, positional, and cross-checked
  against the header. Hazards **H3** (float rounding) and **H8** (locale) are closed *by construction* —
  Rust's `str::parse` is correctly rounded and locale-independent, unlike the `strtod` §5 was written
  about. Pinned by tests over the subnormal and halfway-rounding spellings, plus the German spelling
  being *rejected* rather than reinterpreted.
- **(b) `--as` is dropped** — once the verb names the primitive it is redundant surface.
- **(c) The §7 laundering rule lands now**, contradicting the ADR's phase table, for the reason §7 itself
  gives: retrofitting it would leave the first such seals permanently ambiguous. `raw` is exempt for now,
  and §12a says why so it is not mistaken for an oversight.
- **(d) Two new hazards, H10 and H11** — nullability decided by the **data** not the schema (this is what
  makes the three-writer check passable at all: the three disagree about declarations), and column
  order / dtype width preserved exactly.
- **(e) A nullable `str`/`b1` column is unrepresentable today** and is rejected at the door with a
  next command, instead of failing deep inside the codec. Encoder fix: #457.
- **(f) The arrow sub-crates, not the `arrow` meta-crate** — which reaches this tree only via datafusion
  and would newly pull the `chrono-tz` surface into every build. Net: **10** new crates, one arrow tree.
- **(g) How the §6a feature digest is derived — and the residual it cannot close**, stated plainly.

## A bug the anti-vacuity guard found

ADR-0057 §5's declared-fixture-count table asks for a count per *named configuration*. Declaring one for
`parquet-no-csv` forced that configuration to be **run**, and running it showed `content_hash` matching
while `manifest_hash` moved.

The sealed `ingest_decoder` digest was hashing *this crate's resolved feature set* — so whether the CSV
lane was compiled in changed the seal of a **Parquet** ingest. A lane that is off did not touch the bytes;
the effect was that two builds of one version sealed different `manifest_hash`es for an identical input,
making the format's version identity a function of how the reader's binary was compiled. Our own
`CARGO_PKG_VERSION` came out too, for a different reason: it would make every release a corpus
regeneration, re-introducing the churn ADR-0052 §1 / #336 removed.

The digest is now over the decode-path crate pins alone. Two regression tests pin the absence of both
removed components, and Gate A runs the reduced configuration so the class cannot come back.

## An adversarial review found one real defect

Worth surfacing rather than burying, because the class is instructive. Three lanes (dictionary, run-end,
fixed-size-list) reduce to one mechanism and share a `gather` helper — which is what ADR-0056 §2's
equivalence claims rest on. But each lane derived its index map from **its own** level of nullity, and only
the run-end lane also consulted the *values* array's validity. A `Dictionary<Int32, Utf8>` whose values
contained a null decoded that row to a **present zero**: non-nullable, no transform record, a product that
seals wrong data and verifies.

It also inverted the §2 justification it existed to serve: a plain nullable `str` column is *rejected*
(#457), so the dictionary-encoded form silently sealed wrong data where the plain form refused.

Fixed by folding the values array's validity into the index map **inside** `gather`, so the three lanes are
equivalent *by construction*. Regression test written first (it fails on the parent commit with
`I32([7, 0, 9, 0])`). The lesson is in §12a(h): **a shared helper makes lanes equivalent only for the
decisions actually taken inside it.**

The same review found that `ingest_parquet_nulls` could not test the hazard it claimed — H5 is producer
garbage *under* a null, and neither Parquet nor CSV can express that. H5 came off `LIVE_HAZARDS` with the
reason stated, the fixture was relabelled **H10** and given a declared-nullable-but-null-free column so the
claim is real, and H5's coverage is now the two unit tests that construct a values buffer plus a separate
mask. Plus six smaller ones, all fixed: `csv` caret-pinned while feeding the sealed digest; the CSV lane
trimming `str` fields; `unsafe set_var` in a shared-process test; `--exclude` of a nonexistent column
silently ignored in the arrow lane; `fixed_size_list<T, 0>` expanding to nothing; an error not naming its
column.

It confirmed clean: offset/slice handling on every arm, no reachable panic, and the fold's placeholder
never escaping into a sealed column.

## Correction to `f2171c1`'s commit message

That commit says the aarch64 release build sealed this shape differently from the x86-64 release build,
so "two shipped binaries sealed the same input two ways". **That is wrong**, and the correction matters
because it overstates the severity.

#468's divergence is driven by **`debug_assertions` alone** — measured by toggling the cargo knobs
independently: `overflow-checks` and the optimisation level change nothing. So every release build agrees
with every other release build, on any architecture. What I had actually compared were two *different
nix checks* with two different profiles: `ingest-gate-a` runs the generator with a bare `cargo run` (dev
profile, `debug_assertions` on) while `workspace-test` is `craneLib.cargoNextest` (release, off). Neither
leg was an architecture comparison.

The commit message is left as-is rather than force-pushed, because the array-lane branch is stacked on
this one and rewriting this history would break it. The accurate account is in ADR-0057 §5 on #468's
branch, and this PR is squash-merged, so the wrong sentence never reaches `dev`.

The separate aarch64 `ingest_parquet_floats` divergence is **#472** — same profile, different
architecture, so a genuinely different defect and still open.
