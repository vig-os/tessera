# [PR 728](https://github.com/vig-os/tessera/pull/728) feat(core): add the ADR-0064 partition marker to TableSpec

Refs #709 (part 1 of N)

Part 1 of ADR-0064 PR A (`docs/adr/0064-logical-tables-over-numbered-leaves.md`, §1, §2, §6). `tessera-core` only in
concern; no reader or writer changes.

## What changes

- `Partition { index: u64, last: bool }` and `TableSpec.partition: Option<Partition>`, the sealed marker every leaf
  of a partitioned table carries (§2). It is skipped when `None`, so every single-block spec, corpus golden and
  legacy product serializes byte for byte as before. No corpus file moves.
- `leaf_segment(index)` / `leaf_name(table, index)`: the index-padded `<table>/{index:04}` naming of §1 (`10000`
  past `9999`, no overflow).
- Every `TableSpec` struct literal in the workspace gains `partition: None` (76 lines, mechanical: the new public
  field requires it). No writer sets a marker yet; that is ADR-0064 PR D (#712).
- SPEC §5b and ADR-0063's amendment note now call ADR-0064 Accepted (2026-11-02).

## Tests

- `marker_serializes_both_fields_and_single_block_spec_is_unchanged`: a marker serializes as
  `{"index": 3, "last": false}` and round-trips; a single-block spec emits no `partition` key.
- `manifest_hash_binds_names_and_marker_content_hash_does_not` (§6): the same digests with the marker dropped, or
  under other leaf names, seal a different `manifest_hash` and the same `content_hash`; the same partition seals
  the same manifest.
- `leaf_names_pad_per_index_and_never_overflow`.

Shown failing once: with the field renamed (`#[serde(rename = "part")]`), the marker test fails
(`left: Null`) and the identity test fails (`assertion left != right failed` on `manifest_hash`).

Local: `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings` and
`cargo test -p tessera-core` exit 0.

## Not in this PR

The typed `LogicalTableError`, the resolver (`table_group`), `PARTITION_CHILD_CLASSES` and the seal-time check
follow in the next part(s) of #709.
