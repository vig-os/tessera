# [PR 842](https://github.com/vig-os/tessera/pull/842) docs(book): add the push_table migration note for streamed-table consumers

ADR-0064 step H: the consumer migration note for streamed tables.

## What

- **New book page** `docs/book/src/migrating-to-push-table.md`, "Migrating a streamed table to `push_table`", under a
  new "Upgrading" part in `SUMMARY.md`. It covers:
  - the before/after switch to `StreamWriter::push_table`, from the consumer's real call site (MorePET/visionx-rs
    PR #41, `stream_memory.rs:247-267` at `c4aff94`, `encode_streaming` inside a `push` job) and from alpha.4's
    `table_job_streaming`. The "after" is the RSS proof's own patch
    (`tessera/bench/ksb/677-rss-proof/stream_memory.patch:122-133`);
  - `table_job_streaming` refusing tables above `BLOCK_ROWS`;
  - the `<table>/NNNN` leaves, `pairs` as the one logical name for `logical_table`, `read`, `sql` and the Python
    `table`/`column`/`logical_column`, and legacy `_NNNN` products still reading;
  - the `TableSpec.partition` struct-literal break, with visionx-rs's literal (`metadata.rs:199-203`), and the typed
    `Error::LogicalTable`;
  - the heap bound and the #715 G r4 measurements, with the ksb job names and exit codes (from ADR-0026's record);
  - depending on the `v0.1.0-alpha.5` git tag, and the #758 limit: a dependent resolves vortex from crates.io. The
    interim fix is to copy tessera's `[patch.crates-io]` block, which `cargo tree -i vortex-array` confirms
    (without the block: `vortex-array v0.75.0`; with it: `…gerchowl/vortex?rev=608d8a1…`).
- **`performance.md`**: the write-engine section points to the page.

The visionx-rs issue and the #677 comment aren't part of this PR; they follow once it has merged.
