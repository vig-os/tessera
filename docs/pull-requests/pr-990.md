# [PR 990](https://github.com/vig-os/tessera/pull/990) fix(io): lineage names map to ref files injectively

Closes #975

## The bug

A repository named a lineage's ref file by replacing `:`, `/` and `\` with `_`. So `a:b` and `a_b` shared
`refs/a_b`. A commit on one replaced the other's tip; since #946 it was refused with `RefMoved` against the other's
tip.

## Decision: encode, don't restrict

A lineage is a product `id` (ADR-0036 §4, model A), and every id tessera writes is `blake3:<64 hex>`: it contains
`:`. A lineage alphabet that refuses `:` would refuse every real lineage. So the name is **percent-encoded** instead.

- Each UTF-8 byte outside `a-z`, `0-9`, `-` and `_` is written `%xx`, in lower-case hex. Examples: `blake3:3f…` →
  `blake3%3a3f…`, `a:b` → `a%3ab`, `a_b` → `a_b`.
- `%` is itself encoded, so the mapping is injective and reversible.
- Upper-case letters and `.` are encoded too. That keeps it injective on case-insensitive file systems (macOS is a
  release target), and no name can be `.`, `..` or hidden.
- **No ref file name holds `:`.** The output alphabet is `a-z`, `0-9`, `-`, `_` and `%`, and `%xx` is the only escape,
  so `:` is always `%3a`. No lineage (`pin:x` included) maps to a name holding `:` or starting with `pin:`. The
  Proposed ADR-0067 (#947, PR #988) reserves `refs/pin:<name>` on that basis. The test
  `no_lineage_maps_to_a_file_name_holding_a_colon` pins it, and the ADR-0036 note says so.
- An empty name, or one whose encoding exceeds 249 bytes, is refused with the typed `Error::InvalidLineage`, before
  the writer lock is taken. A product id needs 73 bytes.

## Existing repositories: refused, never remapped

- A repository now holds a `layout` marker, which `init` writes. An empty repository without one gets it on its first
  write.
- A repository with refs and no marker was named the old way, and **every entry point refuses it**
  (`Error::LegacyRefLayout`): `open`, `init` and every write. It is never read with the new naming.
- `tessera migrate-refs REPO [--name FILE=LINEAGE]` (`Repository::migrate_refs`) converts it once, under the writer
  lock. Each ref is attributed to:
  1. `--name`, which must map to the file under the old naming;
  2. else the file name, when it holds no `_` (the old naming left such names unchanged);
  3. else its tip's product id, when that maps to the file (what `import` names a lineage).

  A ref that none of these settles, or a corrupt one, stops the run with `Error::UnattributedLegacyRef`, and nothing
  changes.
- Crash safety: the renamed refs and caches are built in `refs.migrating/` and `log.migrating/` and synced. Then the
  marker is written, then the directories are swapped in. A crash before the marker leaves the old layout. A crash
  after it leaves a repository every verb refuses until a re-run finishes the swap. A leftover staging directory
  blocks readers and writers in both cases.
- The residual trade-offs are written down in the ADR amendment: rule 3 relies on the lineage-is-its-id
  convention, and rule 2 inherits case folding on case-insensitive file systems.

## Tests

- `distinct_lineages_keep_independent_tips` was written first. Lineages `a:b a_b a/b a\b Ab ab a%3ab a.b` each get two
  commits, and their tips and logs stay independent. On origin/dev it fails with
  `RefMoved { lineage: "a_b", expected: None, found: Some("blake3:f801…") }` (test exit 101).
- Old layout: `a_repository_laid_out_the_old_way_is_refused_then_migrated`, and in the CLI
  `a_pre_975_repository_is_refused_until_migrate_refs` (a real `import`, an id-named ref,
  `log`/`commit`/`import`/`init` refused, then migrate, then commit).
- Attribution: `an_unattributable_legacy_ref_stops_the_migration_until_named` and
  `a_corrupt_legacy_ref_stops_the_migration`.
- Crash and recovery: `an_interrupted_migration_is_finished_by_the_next_run` (fails at every directory sync),
  `a_staging_directory_left_before_the_marker_blocks_every_write`, `a_rerun_with_the_same_names_finishes_a_swap` and
  `an_unmarked_empty_repository_is_marked_on_its_first_write`.
- Bounds: `lineage_file_names_are_percent_encoded_and_bounded`.
