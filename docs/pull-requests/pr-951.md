# [PR 951](https://github.com/vig-os/tessera/pull/951) fix(py): nullable table columns read as masked arrays

Closes #804
Unblocks #828: the table-v2 corpus can hold nullable columns.

## What changed

- **Root cause, in the native layer.** The Python reads handed over `ColumnData::to_le_bytes`. For a nullable
  column that is the staging form `values ‖ ceil(rows/8)` mask bytes, so `np.frombuffer` either raised
  (`i4`/`f8`) or returned extra elements built from mask bits (an 11-row `u2` read as 12). Every NULL read as 0.
  The new `ColumnData::values_and_validity` (tessera-io) takes a column apart into its values and its mask.
  The native reads now return them separately:
  - `read_table` returns `(name, le_bytes, numpy_code, validity)`.
  - `read_table_column` and `read_logical_table_column` return `(le_bytes, numpy_code, validity)`.
  - `validity` is `None` for a column that is not nullable, else one byte per row.
- **Python surface (owner decision):**
  - `column`, `logical_column` and `table_dict` return `np.ma.MaskedArray` for a nullable column, with
    `mask=True` at each NULL. The type follows the schema, so a nullable column with no NULLs is still masked.
  - A column that is not nullable stays a plain `np.ndarray`. `api_drift.py` pins this.
  - `table_arrow` has a real validity bitmap (`null_count` is right).
  - `table` has native polars nulls.
  - A present NaN stays a value, not a NULL.
- **Tests:**
  - `tests/nullable_fixture.rs` builds a committed fixture: a partitioned table `obs` of 5 + 6 rows. Its
    nullable `i4`, `f8` (with a present NaN), `u2` (no NULLs) and `f4` (all NULL in leaf 0) columns sit beside
    a plain `u4`.
  - The same test builds the Rust reader's decode of the fixture (`nullable_obs.expected.json`). Both files
    must equal the committed bytes.
  - `tests/nullable_columns.py` holds `column`, `logical_column`, `table_dict`, `table_arrow`, polars and the
    native tuples to those values and masks, bit for bit.
  - `api_drift.py` pins the return shapes and the docstrings that state them. It now takes the fixture as its
    argument.
  - Both scripts are wired into `tessera-py-import` and `tessera-wheel-import`.
- **Docs:** the book's bindings chapter (its snippet is included from the tested script), the Python
  docstrings, the crate README and CHANGELOG Unreleased (Changed: the return type; Fixed: the defect).

## Other consumers of `to_le_bytes` on a nullable column

| Consumer | Affected? |
|---|---|
| CLI `read` / export (`nav.rs` `col_to_values`) | No. Renders from `ColumnData`: NULL is JSON `null`, CSV `nan`. The CSV NULL-vs-NaN ambiguity is the separate open #850. |
| `tessera sql` (`sql.rs` `nullable_to_array`) | No. Builds an Arrow validity bitmap. |
| Streaming staging fragments (`accumulate.rs`) | No. `from_column_bytes` inverts the trailer, given the row count. |
| Chunk-index digest (`row_group_digest`) | No. Hashes the staging form by design. |
| CLI `.npy` export (`nav.rs` `write_npy`) | No. Arrays only, not table columns. |
| WASM binding | No. Reads no table payloads. |

`to_le_bytes` now documents that its nullable form is not a numpy buffer and points to `values_and_validity`.

## Out of scope

The Python `Builder` writing nullable columns didn't fall out trivially. It needs a new `add_table` column shape,
and it is filed as #950.
