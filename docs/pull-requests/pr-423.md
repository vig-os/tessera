<h2>v0.3.3</h2>
<h3>Changed</h3>
<ul>
<li><strong>The release pipeline rebuilds the action bundle instead of relying on a hand-written commit</strong> (<a href="https://redirect.github.com/vig-os/commit-action/issues/157">#157</a>). <code>prepare-release-extension.yml</code> — the devkit-seeded, consumer-owned no-op whose header names exactly this use case — now resolves the devkit toolchain, runs <code>just sync &amp;&amp; just bundle</code> on the freshly cut <code>release/X.Y.Z</code>, and commits <code>dist/</code> when it differs. It runs after the branch is fast-forwarded onto the changelog freeze and before <code>open-pr</code>, so the refreshed bundle is in the release PR diff from its first CI run and <code>Dist Check</code> validates it; <code>rollback</code> already lists <code>extension</code> in its <code>needs</code>, so a failed rebuild deletes the branch and takes the commit with it. <code>release-extension.yml</code>'s finalize-time <code>verify-dist</code> is untouched and becomes a genuine backstop rather than the only gate, and <code>dist-check.yml</code> triggers are unchanged so <code>dev</code> stays ungated (<a href="https://redirect.github.com/vig-os/commit-action/issues/71">#71</a>). This removes the recurring manual rebuild that <a href="https://redirect.github.com/vig-os/commit-action/issues/130">#130</a> fixed once by hand and that had accrued again: six lock-file-maintenance PRs (<a href="https://redirect.github.com/vig-os/commit-action/pull/139">#139</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/143">#143</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/146">#146</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/148">#148</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/152">#152</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/156">#156</a>) moved <code>@octokit/core</code>, <code>@octokit/request</code>, <code>@octokit/endpoint</code>, <code>@octokit/request-error</code>, <code>@octokit/graphql</code>, <code>content-type</code> and <code>undici</code> — all <strong>runtime</strong> transitives that <code>ncc</code> inlines — while the committed bundle stood still. Drift is read from <code>git status</code> rather than a walk of <code>dist/</code>, so the gitignored declaration byproducts under <code>dist/src/</code> stay untracked (the <a href="https://redirect.github.com/vig-os/devkit/issues/1159">vig-os/devkit#1159</a> bug behind <a href="https://redirect.github.com/vig-os/commit-action/issues/134">#134</a>), and the commit is made through <code>vig-os/commit-action</code> at its last released tag rather than the possibly-stale local bundle.</li>

<h2><a href="https://github.com/vig-os/commit-action/releases/tag/v0.3.3">v0.3.3</a> - 2026-09-07</h2>
<h3>Changed</h3>
<ul>
<li><strong>The release pipeline rebuilds the action bundle instead of relying on a hand-written commit</strong> (<a href="https://redirect.github.com/vig-os/commit-action/issues/157">#157</a>). <code>prepare-release-extension.yml</code> — the devkit-seeded, consumer-owned no-op whose header names exactly this use case — now resolves the devkit toolchain, runs <code>just sync &amp;&amp; just bundle</code> on the freshly cut <code>release/X.Y.Z</code>, and commits <code>dist/</code> when it differs. It runs after the branch is fast-forwarded onto the changelog freeze and before <code>open-pr</code>, so the refreshed bundle is in the release PR diff from its first CI run and <code>Dist Check</code> validates it; <code>rollback</code> already lists <code>extension</code> in its <code>needs</code>, so a failed rebuild deletes the branch and takes the commit with it. <code>release-extension.yml</code>'s finalize-time <code>verify-dist</code> is untouched and becomes a genuine backstop rather than the only gate, and <code>dist-check.yml</code> triggers are unchanged so <code>dev</code> stays ungated (<a href="https://redirect.github.com/vig-os/commit-action/issues/71">#71</a>). This removes the recurring manual rebuild that <a href="https://redirect.github.com/vig-os/commit-action/issues/130">#130</a> fixed once by hand and that had accrued again: six lock-file-maintenance PRs (<a href="https://redirect.github.com/vig-os/commit-action/pull/139">#139</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/143">#143</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/146">#146</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/148">#148</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/152">#152</a>, <a href="https://redirect.github.com/vig-os/commit-action/pull/156">#156</a>) moved <code>@octokit/core</code>, <code>@octokit/request</code>, <code>@octokit/endpoint</code>, <code>@octokit/request-error</code>, <code>@octokit/graphql</code>, <code>content-type</code> and <code>undici</code> — all <strong>runtime</strong> transitives that <code>ncc</code> inlines — while the committed bundle stood still. Drift is read from <code>git status</code> rather than a walk of <code>dist/</code>, so the gitignored declaration byproducts under <code>dist/src/</code> stay untracked (the <a href="https://redirect.github.com/vig-os/devkit/issues/1159">vig-os/devkit#1159</a> bug behind <a href="https://redirect.github.com/vig-os/commit-action/issues/134">#134</a>), and the commit is made through <code>vig-os/commit-action</code> at its last released tag rather than the possibly-stale local bundle.</li>
</ul>
