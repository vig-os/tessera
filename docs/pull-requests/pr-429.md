# [PR 429](https://github.com/vig-os/tessera/pull/429) ci: adopt actions/checkout v7 and fix cargo-dist plan under it

## Summary

Supersedes Dependabot PR #427 (do NOT close automatically — the coordinator will).

That PR bumped every workflow's `actions/checkout` from v4 SHAs to v7.0.1, but the Release workflow's `plan` job failed with:

```
× /home/runner/work/tessera/tessera/.github/workflows/release.yml has out of date contents and needs to be regenerated:
-      - uses: actions/checkout@v7.0.1
+      - uses: actions/checkout@v6
help: run `dist init` to update the file
      (`allow-dirty` in Cargo.toml to ignore out of date contents)
```

## Root cause

`.github/workflows/release.yml` is generated by cargo-dist (pinned to 0.32.0 in `dist-workspace.toml`), and every `dist plan` run regenerates it and diffs against the checked-in file. cargo-dist 0.32.0 — through 0.33.0 and even main today — still emits `actions/checkout@v6` by default (see `default_action_versions` in `cargo-dist/src/backend/ci/github.rs`). Bumping the file to `@v7.0.1` therefore drifts from what `dist plan` re-emits, and the check aborts with exit 255.

The `plan` step itself is fine under actions/checkout v7 — no `fetch-depth` / `fetch-tags` issue.

## Fix

cargo-dist ships exactly the hook we need: [`[dist.github-action-commits]`](https://opensource.axo.dev/cargo-dist/book/reference/config.html#github-action-commits) (added in 0.29.0), which overrides the version string `dist` injects per action. Setting `"actions/checkout" = "v7.0.1"` makes `dist plan`'s regenerated file match the checked-in `@v7.0.1`, and `plan` passes.

- `dist-workspace.toml` — add the `[dist.github-action-commits]` block with an inline comment pointing at the reference.
- `.github/workflows/release.yml` — `actions/checkout@v6` → `@v7.0.1` in all 5 spots (kept as a bare tag, matching what dist emits under the override).
- `.github/workflows/{ci,release-nix,release-plz,scorecard,sync-issues}.yml` — bump `actions/checkout` from its old v4 SHA to v7.0.1's SHA (`3d3c42e5aac5ba805825da76410c181273ba90b1`) and fix the trailing comment to `# v7.0.1`. Dependabot's PR updated the SHA but left the `# v4` comment stale on four of these; this restores the SHA-pinned `# <version>` convention the rest of the repo uses.

## Note on release-plz.yml

release-plz.yml (broken since 2026-07-03) is NOT the same cause. Its failing run errors with `working directory has uncommitted changes … [".envrc"]` — an unrelated `.envrc`-both-committed-and-in-`.gitignore` issue. That fix belongs in a separate change; not touched here.
