# [PR 1038](https://github.com/vig-os/tessera/pull/1038) feat(cli): collection commit/log/diff and pin commands (ADR-0067 step 7)

Closes #1002

Expose `collection commit|log|diff` and `pin set|rm|ls` through the existing repository APIs.
Collection commits atomically supply product and sub-collection members under the sealed collection's lineage id.
Caller-supplied `--expected` exposes CAS. Logs are oldest first; ancestry preserves the specified predecessor order.
Walkthroughs cover forks, delta commits, merges, drops, pins and garbage collection.

Failure classification preserves the origin of the error:
- 4: moved ref or pin; reread before rebuilding or reconsidering the operation.
- 5: write-time kind refusal, unstored new pin target, missing product block or collection member, and other rules.
- 6: read-time ref kind disagreement, absent/torn ref target, corrupt ref, aborted store walk or unsupported layout.
- Existing codes 0 (success), 1 (other error), 2 (usage) and 3 (backend unavailable) retain their meanings.

The exhaustive classifier lives in `tessera-core`, where `Error` is defined, rather than in a cross-crate wildcard.
Adding any error variant requires an explicit classification at compile time. The CLI maps its closed class set
onto process exit codes. An unclassified probe variant produced compiler error E0004 and exit 101; it was restored.

Stored ref kind disagreements remain `RefKindMismatch` (6). Validating a new pin kind uses `ObjectKindMismatch` (5).
`RefTargetUnreadable` preserves the read context even during a writer's CAS check; `UnstoredPinTarget` and
`MissingProductBlock` preserve write-refusal context. There is no extra preflight read or I/O-message guessing.
The existing fork-token validator message is classified narrowly, with real-validator tests for empty tokens.

Pin diagnostics name logical refs with pin-specific CAS guidance. Pin rows use JSON-quoted names. The book
explains the unlocked lineage-log race and output format; the missing-member transcript shows its full path.
Only this PR's changelog entry changes; older entries are restored. Avoidable long prose and format lines are wrapped.
