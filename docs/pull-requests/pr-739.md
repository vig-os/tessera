# [PR 739](https://github.com/vig-os/tessera/pull/739) feat(io): check partitions at every door and pin the legacy flat form

ADR-0064 PR B, **part 2 of 2**, on top of part 1 (#735, merged as 66543a0). Part 1 made every reader resolve a table
name through `tessera-core`'s one resolver. This part checks partitions at the remaining doors that finalise a set of
block names, proves `.cidx` pruning over leaves, pins the legacy flat form with a committed fixture, and fixes #733
items 1 and 2. 323 diff lines added and 45 removed, plus one 28 KiB binary fixture.

Closes #710
Closes #733

## What changes

- **`select_blocks_overlapping` / `block_stats` over leaves.** `LogicalTableView` is built on `table_group` (part 1),
  so its blocks are the resolved leaves, and `block_stats` finds each leaf's sidecar (`pairs/0001.cidx`) through
  `cidx_name`. No pruning code changes. This part adds the test proving that pruning reads only the sidecars, never a
  leaf payload.
- **One check at every door.** `unpack` and `pack_dir` call `tessera_core::block::check_partitions`, the check
  `ProductBuilder::seal` runs, right after their `check_leaf_rule` calls, and refuse before writing anything.
  `WriteSession::seal` already reached it through `ProductBuilder::seal`; the test now pins that too.
- **Legacy fixture.** `tests/fixtures/legacy_flat_events.tsra` was written by the pre-switch multi-block writer: three
  `events_NNNN` blocks via the `with_block_rows` seam. Its `content_hash` is pinned:
  `blake3:c1115417dcf7aba23ee3e9d50c6d193011b9d0201ffad7a528ff03ab572dd39a`.
  - A second test re-runs the writer and checks that it reproduces that `content_hash`. After PR D (writers switch to
    `events/NNNN`) it still must, since a block's name is not in its payload (ADR-0064 §6).
  - The fixture is included in the nix source filter (`flake.nix`, `/tests/fixtures/`) and excluded from `typos`.
- **#733 item 1.** A forged partition index that makes the canonical leaf name longer than 255 bytes is
  `LogicalTableError::NonCanonicalLeaf`, not a bare `Error::InvalidBlockName`.
- **#733 item 2.** The read path and the seal now apply one rule. `table_group` refuses a marked legacy-named block
  under a node (`a/pairs_0001`) with the error the seal gives for its parent node. Before, it resolved a `LegacyFlat`
  group around it. A marker with no parent node is still `StrayMarker`.
  - ADR-0064 §3 rule 4 gets a dated clarification, including the exemption for a whole group that is one leaf read by
    its full name.
  - #733 item 3 (`DuplicateIndex` unreachable while the seal accepts duplicate block names) is filed as #734.
- **Review notes from part 1:**
  - `LogicalTableView::prefix` becomes `name` (documented); `prefix()` stays as a `#[deprecated]` alias.
  - `group_specs` documents why its `NotFound` branch can't be reached for a group from the same manifest.
  - The CHANGELOG records that a legacy block whose spec doesn't parse is now `SchemaMismatch` (it was `Error::Serde`).
- ADR-0064 §6 erratum: the migrated pyramid test asserts `NotATable { kind: "array" }`, not `Single`.
- CHANGELOG (Unreleased): `unpack`/`pack_dir` refuse invalid partitions; the `prefix` deprecation; the spec-error
  change; and the two #733 fixes.

## Entry points that return the typed variants (`Error::LogicalTable { name, reason }`)

- Readers: `Reader::table_group`, `Reader::logical_table` (and through it `LogicalTableView`). CLI `read`/`sql` and
  Python `read_logical_table_column` call `logical_table`; their own surfaces are C1/C2.
- Doors that finalise names: `WriteSession::seal` (through `ProductBuilder::seal`), `unpack`, `pack_dir`.
- `Reader::block_group` is deprecated and returns no errors.
