# [PR 516](https://github.com/vig-os/tessera/pull/516) ci(nix): fold the reduced ingest-gate configurations into one derivation

Three reduced feature configurations now share `ingest-gate-a-reduced` instead of two derivations. Same
commands, same coverage, one fewer check on the flake: **23 → 22** on `x86_64-linux`, measured with
`nix eval` over the attrset before and after rather than counted by eye.

## Why — and what this deliberately does *not* fix

`nix flake check` schedules derivations concurrently under a `max-jobs` cap, so an extra check cannot push
concurrency past that cap. What it changes is **which** checks can be co-scheduled, and a new one can create
a heavier overlap than the previous mix allowed. Splitting the `npy`-without-`npz` configuration into its own
derivation coincided with:

| | x86_64 peak / free | aarch64 peak / free | |
| --- | --- | --- | --- |
| before the split (#461 `5d28854`) | 13534M / 2454M | 11536M / 4410M | green |
| after it (#461 `84b1ed2`, merged) | 14286M / 1702M | **15095M / 852M** | green |
| a run that was EVICTED (#500) | 15577M / 412M | 15633M / 313M | exit 143 |

**852M free on aarch64 sits inside the noise band of the arm that died at 313M.** It passed twice, but
passing and having margin are different claims, and #495's recorded 2.4 GB of headroom is stale in the
wrong direction.

Honest about strength: the derivation count is **verified** (14 → 15 cargo derivations between those two
commits); the causal step is **inference from one run per side**, and x86 wall-clock variance on a single
branch is ~23 minutes, so single readings deserve suspicion.

So this is **relief, not a bound.** The next derivation anyone adds can recreate the overlap, and it will
keep being someone's accident rather than anyone's decision. The bound is lowering `--max-jobs`, after which
adding derivations costs wall-clock instead of peak memory — which is the property worth having, since these
configurations exist for good reasons and nobody should have to trade CI memory against catching a compile
break. That work is #514's, not this PR's.

## The trade accepted

The three configurations now run **sequentially**, so a failure in an earlier one hides the later ones until
it is fixed. Cheap: each is seconds of `cargo test` against an already-built dependency graph, and they are
independent enough that one failing rarely predicts another.

## Coverage is unchanged, and the reasons travel with it

Each configuration keeps the comment saying **what it caught**, because a gate whose reason is lost is a gate
someone later deletes as noise:

- `--features parquet` — the leg that catches a `manifest_hash` depending on which lanes were compiled in.
- `--features npy` — found `generic_column_meta` and `warn_unclassified_identifying_columns` gated on
  `any(parquet, arrow, csv)` while the array arm calls both, plus three targets needing `required-features`.
- `--features parquet,npy` — reaches the corpus without `npz` (the corpus module is gated on `parquet`, so
  `npy` alone never compiles it) and found `ingest_npz_member` declared `requires: ["npy"]` while its builder
  calls `zip`.

## Verification

Built the check **under nix**, not just run in a devShell — all three configurations pass in the sandbox
(`nix build .#checks.x86_64-linux.ingest-gate-a-reduced`, rc=0). Plus `nix eval` asserting
`ingest-gate-a-reduced` is present and `ingest-gate-a-npy-only` is gone, prek and
`validate-commit-range` clean, commit signed.
