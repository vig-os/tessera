# [PR 484](https://github.com/vig-os/tessera/pull/484) docs: ingest cookbook, generated product-schema reference, and a tested Python write example

Closes the "write your own data: **2/5**" half of the #390 AX audit. Every example is executed by a gate,
so none of it can rot.

## What's new

| | |
|---|---|
| **`ingest-cookbook.md`** | a which-recipe-do-I-want table, two worked recipes (`ingest blob`, a declarative `--spec`), the Python write path, and what to do next. Its transcript is `{{#include}}`d from a new `cookbook.trycmd` CI runs against the real binary |
| **`schemas.md`** | all **14** built-in products with required/recommended/optional fields, sensitivity tiers and block roles — **generated** from `SchemaRegistry::builtin()` |
| **`write_example.py`** | the write path as runnable documentation, anchored and `{{#include}}`d, executed by **both** `tessera-py-import` and `tessera-wheel-import` |

The schema reference can't drift: it lives in a `guardrails:derived` region, so the `derived-docs` gate
fails any commit where the table and the registry disagree. A schema cannot gain a required field without
this page gaining it in the same commit.

## Four real bugs the "docs as tests" rule caught

None of these would have been found by writing a page carefully.

1. **`bindings.md`'s Python snippet did not work at all.** It documented `tessera.Reader("study.tsra")`
   plus `read_array` / `read_array_subset` / `read_table` / `read_table_column` — **none of which exist**.
   The real surface is `tessera.open()` and `array` / `array_roi` / `table` / `table_dict` / `column`. That
   section now includes the tested example instead, so it cannot drift again. This is the audit's
   complaint in its purest form: the docs advertised an API nobody had run.
2. **My own first cookbook draft asserted output the tool does not produce** — four separate guesses,
   replaced by four facts once I recorded real transcripts: `ingest blob` prints
   `ingested <id> (blob) -> …`; collection members are written under their **content id**, not their human
   name; `tessera verify` does **not** accept a `collection.json` (that is `tessera collection verify`);
   and `extract` takes `<FILE> <BLOCK> <OUT>`, not `--out`.
3. **My own Python example had a bug the check found**: `table_dict` returns numpy arrays, so `== [...]`
   raises *"truth value of an array … is ambiguous"* rather than comparing.
4. **`slice`'s grouped-help line still said "as CSV"** after #476 added npy/png/json. Generating the
   command index from the binary surfaced it in seconds.

## Also

- **`cli.md` no longer renders as nothing outside an mdBook build** (#389's fourth bullet). The command
  index is now a `derived-docs` region carrying the binary's real grouped help, so the raw file **stands
  alone and** cannot drift, while the detailed transcripts stay `{{#include}}`d rather than duplicated —
  one copy, not two.
- **`arrays.md` gains the "Output formats" section #476 never wrote**: the format table, the
  binary-to-a-TTY refusal, the png-is-a-preview caveat, and the terminal-only row cap.
- **A gate interaction worth recording:** pymarkdown's MD001 fixer demoted the generated
  `### <product>` headings, which then made `derived-docs` fail — two gates fighting over one file, which
  would have looped in CI. Fixed at the source by nesting the region under a `##` so the generated levels
  are legal exactly as emitted.

## Deliberately not documented

The generic `ingest table` / `ingest array` verbs (#386) are **not on `dev`** yet, so they are not
documented. The cookbook says so in a marked section and points at the issue — a cookbook listing flags a
reader cannot run is worse than one that admits the gap. Ready to fill in once #460/#461 land.

## Follow-up filed

**#482** — writing the schema reference surfaced that **no built-in schema sets `requires_generation`**, so
ADR-0058 §3's "computed products must carry a recipe" rule is a mechanism with no policy attached: `sim`,
`recon` and friends can all seal with no recipe. Setting it is a validation-policy change needing a
per-product decision, so it is its own issue — but the generated table now shows the real state in a
`requires a recipe` column, which is how it became visible.

## Testing

`cargo nextest run` → **443 passed**; `mdbook-build`, `tessera-py-import` and `derived-docs` all pass; the
full `prek --all-files` suite passes with zero failures. The rendered HTML was inspected to confirm the
includes resolve to the right content rather than merely building.
