# [PR 958](https://github.com/vig-os/tessera/pull/958) docs(design): table-v2 note amendment after the A3/A4/A5 miss

Docs only. Records the owner's decision of 2026-11-22 on #828
([comment](https://github.com/vig-os/tessera/issues/828#issuecomment-7085524452)): `tessera-table-v2` missed the
design note's A3, A4 and A5 floors, and `tessera-table-v1` stays the default.

- `docs/spikes/915-tessera-table-v2.md`: a dated §10 amendment (and a status line). It covers the failed floors
  with the load-independent numbers: encode at 0.50× / 0.52× of v1's CPU per event, +1,145 / +908 instructions per
  event, take-500 9–18× slower, decode 2–4× slower. It states that the cost lies in the profile itself (forced
  per-column Pco and Zstd-9; the 12-point sweep reaches at most 0.60×), not in a parameter, and records the
  decision. It then poses the open question: is v2 worth having as an opt-in archival profile, and how would it
  land additively? That covers naming, a reader meeting an unknown profile today, which encodings released readers
  decode, the footer encoding-ID trap, and the missing opt-in door. Four options are listed with their costs, one
  marked (Recommended). The owner answers; the note does not decide.
- `docs/spikes/828-m4b-a3.md`: the round-2 measurement report, unchanged (numbers and ksb job names). The job
  files it cites live on the parked branch `feature/828-tessera-table-v2-codec-profile` (commit `cf616994`).
- `docs/adr/0066-seal-encoding.md`: step 7's status reads "deferred: owner decision 2026-11-22, see #828", and rule
  13 points to it. #917's scope comment already records the alpha without #828.

The v2 implementation stays parked in draft PR #949.
