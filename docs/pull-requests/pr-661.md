# [PR 661](https://github.com/vig-os/tessera/pull/661) docs(adr): ADR-0062 streaming table provider (Proposed)

## What

ADR-0062 (**Proposed**) for epic #654: a streaming, bounded-memory query provider over sealed table
blocks, replacing the whole-table `MemTable` behind `tessera sql`. Docs only: the ADR plus its row in
`docs/adr/README.md`.

## Decisions (one line each)

1. **Home:** an engine-neutral, synchronous `tessera_io::scan`, plus a new `tessera-query` crate that
   holds only the DataFusion adapter. `tessera-core`, `tessera-wasm` and the abi3 wheel stay
   DataFusion-free. Rejected: a feature on `tessera-io`, putting everything in `tessera-query`, and
   `vortex-datafusion` (multi-thread tokio, an unpatched umbrella crate, no seal/`.cidx`/zip).
2. **DataFusion coupling:** DataFusion appears only in `tessera-query`, which re-exports it. One
   major at a time, and its arrow major must match Vortex's. A DataFusion major is a breaking
   `tessera-query` release.
3. **Bounded memory, per query:** at most `max_partitions` (default 8, not DataFusion's core-count
   default) scan partitions, each running explicit 65 536-row window scans with a per-block segment
   cache; the formula lists every term. Operators above the scan are bounded only by DataFusion's
   pool. Proven by a CI high-water test and a ksb run that measures anonymous memory (swap off, pinned
   CPUs and partitions, a negative control that must be OOM-killed).
4. **Pushdown and pruning:**
   - Projection is always pushed down.
   - Filters prune in two tiers: first `.cidx`, before any block byte is read, with exact NULL rules;
     then zone maps.
   - Pushdown covers a closed filter class. Every pushed filter is `Inexact`, and floats and casts are
     never pushed.
   - A pushdown-on/off differential test gates this.
5. **Positional zip:** only with an alignment proof: a sealed `aligned_to` (a writer's claim, written
   only by `derive_aligned`, recording the source blocks' digest), or a strictly increasing, NULL-free
   key checked while streaming, across unit boundaries too. A mismatch is refused before the first row.
   There is no hash-join fallback.
6. **Multi-product scans:**
   - Units are (product, block, row-group run).
   - Members are pinned by `manifest_hash`.
   - Schemas must be identical, or the caller names the common columns explicitly.
   - Object-store reads go through our own `VortexReadAt` on one I/O thread per store, behind a
     `RangeSource` seam so a consumer's DataFusion `ObjectStoreRegistry` (object_store 0.13, beside our
     0.14) can feed it.
7. **Integrity:** `VerifyBlocks` is the default. A block is verified before any of its rows is
   emitted, and only once per query, and the `.cidx` is verified in every mode. Locally the rows are
   read in a second pass, so the guarantee covers corruption at rest, not a concurrent writer.
   `SealOnly` is a labelled opt-out.
8. **Phasing:** #666 single-product streaming and pruning → #667 positional zip → #668 multi-product,
   local then object store. Each has its acceptance criteria. Deferrals are filed as #669 (float
   pushdown), #670 (per-segment digests) and #671 (zip over a Collection).

## Evidence

The API claims cite DataFusion 54.0.0, arrow 58.3.0, the Vortex 0.75 fork at `608d8a1`, object_store
0.14 and zip 9.0.4 from `tessera/Cargo.lock`, by item path and line. A scratch probe outside the repo
established seven claims. The results that shaped the design:

- Vortex scales scan concurrency by the core count.
- Default splits are about 1 MiB of uncompressed column.
- Window scans without a segment cache re-read 2.6–8× the bytes.
- With the layout-reader cache plus a 4 MiB `MokaSegmentCache`, window scans read exactly what one
  scan reads.
- A zone-pruned filter read 328 KB where the same projection without it read 1.31 MB.

## Open questions for the owner

(a) Must a declared `aligned_to` be signed by a trusted key before a zip trusts it? Related: #656, #566.
(b) Should local `VerifyBlocks`, which doesn't protect against a concurrent writer, stay the default?

Filed separately, each with a recommendation: #672 (object-store integrity default), #673
(`tessera-query` version line at 1.0), #674 (workspace MSRV), #675 (indexed column in the table `.cidx`).
