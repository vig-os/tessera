# [PR 732](https://github.com/vig-os/tessera/pull/732) feat(core): resolve logical table names and check partitions at seal

Closes #709

Part 2 of 2 of ADR-0064 PR A (`docs/adr/0064-logical-tables-over-numbered-leaves.md`, §2, §3, §4). Part 1 (#728)
added the marker and the leaf naming. This part adds the shared resolver, its typed errors and the seal-time check,
which completes #709's scope. `tessera-core` only; the reader call sites are PR B (#710).

## Why one PR, not A2 + A3

The read-time resolver and the seal-time check don't split cleanly under the ~400-line cap:

- The resolver alone (`table_group`, `validate_node`, `LogicalTableError`, `PARTITION_CHILD_CLASSES`,
  `is_legacy_flat_member`, `marker`) is about 390 production lines and about 430 test lines. It is over the cap
  without the seal check.
- The seal check is a 25-line loop over `table_group` (`check_partitions`) plus a 4-line hook in
  `ProductBuilder::seal`. Its tests are the resolver's tests: each table-driven case asserts the same variant at
  read and at seal, because §2.4 requires the seal and the readers to agree. Splitting would duplicate those cases or
  leave the seal check untested in its own PR.

## What changes

- `table_group(blocks, name)` maps a table name to `Single`, `Partitioned { leaves }` or `LegacyFlat { blocks }`,
  reading only the manifest, or refuses it with `Error::LogicalTable { name, reason }`. `LogicalTableError` is
  `#[non_exhaustive]` and has the 13 variants of #709.
- Node validation (§2.1, §2.5): canonical `{index:04}` table leaves, unique indices contiguous from 0, `k ≥ 1`,
  exactly one `last` at the highest index, strictly increasing manifest order, one schema, and no child outside
  `PARTITION_CHILD_CLASSES` (only a leaf's `.cidx` sidecar). Validation is O(n).
- A marker on a block that isn't a `<table>/NNNN` table leaf is refused:
  - on a top-level or legacy flat block: `StrayMarker`;
  - on a non-digit or wrongly padded segment: `NonCanonicalLeaf`;
  - on a non-table block, a marked `.cidx` included: `ForeignChild`.
- A malformed `partition` key is `Error::Invalid`; it is never read as "unmarked".
- The legacy `_NNNN` rule moves verbatim into `is_legacy_flat_member`. A name that both a node and a legacy group
  answer to is `Ambiguous`.
- `ProductBuilder::seal` runs `check_partitions` after ADR-0063's leaf rule.
- `leaf_name` now returns a `BlockName` checked against the ADR-0063 grammar (`Error::InvalidBlockName`), not an
  unchecked `String`. `leaf_name("", 0)` was `"/0000"`. A table over 234 bytes is refused, because a `u64` index
  can then push the leaf past 255 bytes (§1.3).
- From the #728 review:
  - `docs/adr/0026` and `FEATURE-MATRIX.md` now call ADR-0064 Accepted.
  - The identity test's comment says its digests are synthetic, and that the writer-side payload-digest check
    is PR D (#712).
  - `CHANGELOG.md` records that the new public `TableSpec.partition` field breaks external `TableSpec { .. }`
    struct literals (pre-1.0). Downstream visionx-rs needs `partition: None`.

## Tests (`block::partition::tests`)

Every validity rule has a negative test that asserts its variant at read and at seal:

- `ForeignChild`: an unmarked `pairs/0003`, a `pairs/view` array, a deeper `pairs/sub/x`, a marked array leaf and
  a marked `.cidx`.
- `NonCanonicalLeaf`: `pairs/00001`, `pairs/1` and `pairs/abcd`.
- `DuplicateIndex`.
- `Gap`: one in the middle, and one that doesn't start at 0.
- `NoTerminal`.
- `AfterTerminal`: two leaves marked `last`, and a leaf after the terminal one.
- `OutOfOrder`, `SingleLeaf`, `Ambiguous` and `SchemaMismatch`.
- `StrayMarker`: a top-level block and a legacy block.
- `leaf_name` refuses `""`, `"a/"`, `"a b"` and a 235-byte table, and accepts a 234-byte table at `u64::MAX`.
- A malformed marker is refused.

Positive cases:

- A partition with its `.cidx` sidecars resolves.
- Index 10000 follows 9999.
- A leaf named in full and a small table resolve as `Single`.
- `NotATable` and `NotFound`.
- The legacy `events_NNNN` cases of `container.rs` resolve as before, and an unmarked `events/notes` takes no part.

Each test was shown to fail with its rule removed. For the new tests, these mutants each exit 101:

- the kind check made `false`;
- `leaf_name` with a leading `/` stripped;
- the after-terminal check made `false`;
- the canonical-name check replaced.

Local checks, each exit 0:

- `cargo fmt --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test -p tessera-core -p tessera-io` (lib and integration tests)
- `cargo test -p tessera-core --doc`
