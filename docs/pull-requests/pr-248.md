# [PR 248](https://github.com/vig-os/tessera/pull/248) feat(core): embed the product schema in every sealed manifest (obligatory, self-describing)

Reported from real-data use: `tsra tree ct-lung.tsra` showed `schema=recon✓`, but the `.tsra` only stored the product **name** — validity was checked against the schema **compiled into the reading binary**, not anything in the file. Open it in 5 years with a drifted/absent registry and its contract is gone. That breaks FAIR-Reusable.

## Change
`ProductBuilder::seal()` now embeds the resolved `ProductSchema` JSON into `manifest.schema` for every **known** product (a caller-supplied `with_schema` or an inherited one still wins; open-world/unknown products stay schema-free — the permissive escape hatch). The embedded schema is **inside the seal** → covered by `manifest_hash`, tamper-evident, and travels with the data.

- `ProductSchema::{to_value,from_value}` + `validate_manifest(m)` — validate against the **embedded** schema when present (self-contained), else the built-in registry (legacy/open-world).
- `tsra schema <file>` reads the embedded contract and reports registry **drift**; `tsra schema <file> --json` **dumps** it.
- tree/inspect status badge validates via the embedded schema.

## Blast radius (small)
Only `manifest_hash` changes — `id` (= id_inputs) and `content_hash` (= block-digest merkle) are **stable**. So the conformance corpus + trycmd walkthroughs regenerated (`gen_corpus` + `TRYCMD=overwrite`), but id/content_hash goldens are untouched; the trycmd diff is literally `built-in schema` → `embedded schema`.

Unit-tested: a known product embeds a schema == the registry and is sealed; an open-world product stays schema-free; validation routes through the embedded copy. Full `nix flake check` green.

First of the FAIR/provenance batch (schema embed done; source-file hashes + producer stamp + DICOM porting follow).
